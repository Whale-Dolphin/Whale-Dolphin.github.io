精评

1. System One 模型也能单步作画：Jeveration 512 图 78ms、快 122 倍

2611.24738

一句话：System One 模型靠快速并行预测做决策，Jeveration 证明同一范式也能一次前向就生成高质量图像，512×512 只要 78ms，比现有统一模型快至 122 倍。

贡献/机制：建立在冻结的视觉–语言模型之上，复用其视觉语义知识做整体图像生成；关键难点是全局一致性——同一个提示对应许多合法图像，并行预测必须收敛到一幅自洽的图，做法是让所有位置共享一个随机状态来协调并行预测，使每次采样得到不同但自洽的图像；由于直接图像监督下模型倾向于忽略该状态，先学习离散图像码上的分布来引导单步生成；除文生图外，同一架构还统一了图生图与稠密预测，一个 checkpoint 支撑三项任务、每项都一次前向完成。作者：Yuhe Liu、Qi Li、Shihua Zhang、Xinchao Wang。

数值结果：512×512 图像单次前向 78ms，比现有统一模型快至 122 倍，同时保持有竞争力的图像质量与稠密预测性能。

批判性分析：这篇的切口很准：扩散模型的多步去噪是生成速度的天花板，System One 的“一次前向给答案”正好是反方向——共享随机状态协调并行预测，是对“并行采样如何保持全局一致”这个真问题的回答，122 倍提速的数字也够硬。但要留神：摘要只说了“有竞争力的质量”，没有给出与主流扩散模型同台对比的具体分数，78ms 背后的硬件条件也没交代；而且“先学离散码分布再引导生成”这一步，等于把一部分建模负担推回了码本，单步生成的质量天花板究竟在哪，得看正文的消融与评测。

摘要译文：Jev 这类 System One 模型通过快速并行预测给出决策。本文介绍 Jeveration，证明同样的决策范式也能在一次前向中生成高质量图像。Jeveration 建立在冻结的视觉–语言模型之上，复用其视觉语义知识做整体图像生成。关键挑战是保持全局一致性：一个提示对应许多合法图像，但并行预测必须收敛到一个自洽的整体。因此我们让所有位置共享一个随机状态来协调并行预测，使每次采样得到不同但自洽的图像。由于在直接图像监督下模型倾向于忽略该状态，我们先学习离散图像码上的分布来引导单步生成。除了文生图，我们还在同一架构内统一了图生图与稠密预测，使一个 checkpoint 支撑全部三项任务、每项都在一次前向中完成。实验表明，Jeveration 生成 512×512 图像只需 78ms，比现有统一模型快至 122 倍，同时保持有竞争力的图像质量与稠密预测性能。

2. 智能体进化卡在哪：不是想不出好办法，是测不出哪个更好

2611.23068

一句话：智能体进化是个“提议–筛选”循环，七种进化方法、六个模型、超 1000 万次 LLM 调用的证据表明，瓶颈不在提议，而在评估噪声让筛选几乎等于随机挑。

贡献/机制：提出“分辨率假说”（Resolution Hypothesis）：智能体进化停滞，不是因为方法提不出更好的产物（提示词、技能、记忆），而是因为带噪声的评估无法可靠识别它们；在候选层面，有用的产物确实存在，但筛选在区分好坏上并不比随机好，误差随轮次累积；在方法层面，常见几百分点的差距小于同一方法两次独立运行之间的差异，发表的方法排名常常靠运气。作者：Yuanhao Zeng、Shaocheng Lan、Ao Lu、Kuang Yan 等。

数值结果：横跨七种进化方法与六个模型、超 1000 万次 LLM 调用；候选层面筛选约等于随机；方法层面典型差距只有几个百分点，小于同一方法的运行间差异。

批判性分析：这篇的价值在于把“自改进智能体”这个热门方向的注意力从“设计更多提议机制”拽回到“让真实改进可检测、可累积”——1000 万次调用的规模让“筛选≈随机”这个结论很难被当作偶然，方法排名靠运气的提醒，对整个子领域的论文阅读方式都有用。但要留神：结论本质上是否定的（指出瓶颈而非给出解法），“如何提高评估分辨率”这一半只给了方向没给可复用的方法；而且实验集中在提示词/技能/记忆这类文本产物上，结论能否推广到权重层面的自改进，还得另看证据。

摘要译文：智能体进化遵循一个简单循环：提议者写出候选产物（提示词、技能、记忆），筛选接受其中得分更高的。这一循环已显出前景，但实践者面临一个难题：方法在不同论文间互有胜负，进化在某些任务上常常无法起步。我们把这个难题追溯到“分辨率假说”：智能体进化停滞，不是因为方法提不出更好的产物，而是因为带噪声的评估无法可靠识别它们。在七种进化方法与六个模型（超 1000 万次 LLM 调用）上，我们在评估分数被使用的两个层面都找到了支持该假说的证据。在候选层面（选择产物），有用的候选产物确实存在，但筛选在区分它们与有害产物上并不比随机好，因此误差随轮次累积。在方法层面（给方法排序），典型几百分点的差距小于同一方法两次独立运行之间的差异，因此已发表的排名常常建立在运气之上。这些发现共同表明，智能体进化常常受制于能否可靠识别改进。这要求我们转变开发与评估自改进智能体的方式：从设计 ever more 候选改进系统，转向让真实改进可检测、可累积。

3. 全模态模型听得懂“要不要开口”吗：O-IN-Bench 最高分 59.6，意图与内容是两回事

2611.24706

一句话：全模态大模型能直接语音通话，但“听出用户在求助”与“答到点子上”是两种能力，O-IN-Bench 测下来最强模型总分只有 59.6，意图判断 74.4%、内容判断仅 42.6%。

贡献/机制：提出 O-IN-Bench：模型看一段带原生语音的完整视频，输出一段文字回复，或在无需回应时输出 [SILENCE]；含 1000 个中英样本、五个类别、16 个子类别；对比样本把同一请求配上不同场景条件，检验回复是否随场景变化；每样本一套评分标准，把语言、意图与内容分开打分，并由 O-IN-Engine 对照视频逐项核验。作者：Zijie Xin、Tianyi Wang、Daoze Zhang、Jie Yang 等。

数值结果：30 种全模态模型配置中，最高总分 59.6（Gemini3.7-Flash）；该模型意图判断通过率 74.4%，内容判断仅 42.6%；当语音是同伴间对话而非对助手的请求时，强模型也常忍不住接话；需同时满足多人的回复，最佳得分仅 25.9。

批判性分析：这篇的拆分很对语音助手的胃口：真实对话里“该不该开口”与“开口说什么”本来就是两道关，74.4% 对 42.6% 的落差说明模型多半是“听懂了大概、答不到点上”，而“同伴对话也接话”与“多人需求 25.9 分”这两个失败模式，恰好是语音助手落地时最容易翻车的场景。但要留神：评分标准依赖 rubric + 视频核验的半自动流程，rubric 本身的严格程度会直接左右分数，59.6 这个绝对值不宜跨基准比较；而且 1000 样本、五类别的规模，对“意图理解”这个大命题来说只是个起点。

摘要译文：全模态大语言模型（omni-modal LLMs）能直接通过语音与视频通话回应口头请求。这类请求依赖用户与助手共享的场景，因此同一句话可能需要不同的帮助，也可能根本不需要回应。多数音视频基准把问题以单独文本输入给出，交互式基准则多半把回复作为整体打分。因此，模型是否识别出用户在求助、识别出之后回复是否满足用户需求，仍不清楚。我们提出 O-IN-Bench，评估全模态大模型理解口语意图的能力。模型观看一段带原生语音的完整视频，输出一段文字回复，或在无需回应时输出 [SILENCE]。O-IN-Bench 包含 1000 个中英文样本，覆盖五个类别与 16 个子类别。对比样本把同一请求与不同场景条件组合，检验回复是否随场景变化。每样本一套评分标准把语言、意图与内容分开评判，O-IN-Engine 对照视频逐项核验。在 30 种全模态模型配置中，最佳总分为 59.6，由 Gemini3.7-Flash 取得。Gemini3.7-Flash 的意图判断通过率为 74.4%，内容判断仅为 42.6%。当语音是同伴之间的对话而非对助手的请求时，即使强模型也常常继续回应。当回复必须同时满足多人时，最佳得分仅为 25.9。这些结果表明，识别请求与满足其要求是两种不同的能力，O-IN-Bench 对二者分别测量。

4. Omni-LLM 的 token 瘦身：ReMo 砍掉 54% 输入，准确率反超满 token

2607.21179

一句话：Omni-LLM 的输入 token 绝大多数是高度冗余的视觉 token，ReMo 用音频与文本把视觉信息“分流”出去，免训练砍掉 54% 的输入 token，准确率反而略超满 token 模型。

贡献/机制：训练无关框架 ReMo：视觉 token 只在别处没有它的信息时才保留——先在共享空间里对齐音频与视频（闭式标定），删掉已被音频或其他视觉 token 解释掉的视觉 token；再把轻量检测器找到的物体级视觉 token 换成紧凑文本代理（物体的简短描述加位置），用更少的 token 传达相同内容。在 Qwen2.5-Omni 两个规模上验证。作者：Suho Yoo、Youngjoon Jang、Hyebin Cho、Joon Son Chung。

数值结果：去掉 54% 的输入 token，准确率与满 token 模型相当，在五个音视频基准上的平均准确率达到满 token 模型的 101.2% 与 101.4%（两个模型规模）。

批判性分析：这篇的思路很干净：Omni-LLM 的成本不平衡是结构性的——视觉 token 占大头又高度冗余，“只保留别处没有的信息”比均匀压缩更像正确的压缩原则；免训练、101% 的准确率，落地门槛也低。但要留神：101.2% 这个“反超”幅度很小，本质上是“无损”，不宜读成“压缩反而更好”；而且文本代理依赖轻量检测器找物体，对没有明确物体的场景（抽象画面、快速剪辑）能省多少 token，摘要没有交代。另外注意：这篇 arXiv 首发于 2026-07-23，是经 11-17 日 HF 榜单重新入选的老论文，并非本周新作。

摘要译文：本文的目标是降低 Omni-modal 大语言模型（Omni-LLMs）在推理时的输入 token 成本。Omni-LLMs 联合推理音频、视频与文本，但三条流的成本高度不平衡：视觉 token 占输入的绝大多数，且高度冗余。本文提出 ReMo，一个免训练框架，通过把视觉 token 的信息跨模态重新分配来压缩视觉 token：一个视觉 token 只有在其信息别处不存在时才保留。ReMo 通过两种方式实现这一点：（i）通过闭式标定在共享空间中对齐音频与视频，删除已被音频或其他视觉 token 解释的视觉 token；（ii）把轻量物体检测器识别出的物体级视觉 token 换成紧凑文本代理，即物体的简短描述及其位置，以更少的 token 传达相同内容。在两个模型规模的 Qwen2.5-Omni 上，ReMo 去掉 54% 的输入 token，准确率与满 token 模型相当，在五个音视频基准上的平均准确率达到满 token 模型的 101.2% 与 101.4%。

5. 多声源音频拼图为什么总拼错：几何错位诊断，AIC 最高 2.25 倍

2611.24410

一句话：多声源音频转图像时，各声源的音频 token 在 CLIP 文本 token 空间里位置错位、语义无锚，扩散模型既注意不到它们、也分不清各自的空间区域，CLAP 嵌入加多 token 扩展能把组合保真度抬回来。

摘要译文：异步强化学习提高训练吞吐量，但来自旧策略的数据与训练和推理之间的数值失配会使学习不稳定。为稳定离策略学习，分数中心化（SC）去掉奖励基线对期望更新的影响。我们的梯度诊断表明，SC 的梯度比重要性采样（IS）更温和，但当学习者远离生成数据的行为策略时，SC 仍可能失败。为限制这种策略失配，我们引入正则化分数中心化（RSC），加入反向 Kullback-Leibler（KL）惩罚，鼓励学习者的下一 token 分布靠近行为策略的下一 token 分布。RSC 可与截断重要性采样（TIS）联用，后者对 token 重要性权重设上限。我们的理论分析支持这一做法，表明 KL 正则化改善收敛保证。我们在数学推理与智能体任务（包括在线购物、工具使用、游戏与全异步软件工程）上评估稠密与混合专家模型。带 TIS 的 RSC 在所有智能体基准上大幅提升样本效率，以相同采样量取得更高训练奖励。在最终评估中，它在全部六个智能体任务上取得最优表现，在 AppWorld 上提升 14.3%，在 BabyAI 上达到最强基线得分的 9.9 倍。

数值结果：10,159 个环境、17 个软件领域；RepoHorizen-35B-A3B 在 NL2Repo-Bench 上提升 22.6 个百分点，在五个长程编码与智能体基准上平均提升 8.5 分；去掉环境进化后分别为 17.5 与 6.4 分，说明进化循环本身贡献了约 5 个点与 2 分。

批判性分析：这篇的思路对“智能体训练缺环境”这个痛点抓得准：真实仓库自带复杂度与可验证性，比人工合成任务更接近生产场景；“有效性×耦合×范围”的乘法目标也比单一通过率更能防止环境退化成 trivial 任务。但要留神：10,159 个环境的“可验证”质量参差不齐的风险不小，代理信号与真实训练价值之间的相关性，摘要没有给出直接证据；而且 22.6 个点的提升是在自家 NL2Repo-Bench 上的数字，跨到外部基准的泛化还得看独立复现。

摘要译文：训练长程任务的编码智能体需要带可验证反馈的环境。现有流水线常遵循线性流程、以验证收尾，确立了可用性，却对如何提升训练价值几乎没有指导。递归自改进（RSI）常常需要模型 rollout 或模型训练后再做下游评估，在长程任务上成本与反馈延迟都被放大。我们如何用及时可靠的代理信号提升训练价值、并规模化合成环境？我们提出 RepoFactory，一个把真实仓库自动转成可验证环境的流水线，智能体在其中按语言规约从头构建完整项目。其环境进化循环通过代理反馈优化有效性、结构耦合与实现范围相乘的目标。RepoFactory 产出 10,159 个环境，覆盖 17 个软件领域。在这些环境上训练 Qwen3.5-35B-A3B，得到 RepoHorizen-35B-A3B，相比基线在 NL2Repo-Bench 上提升 22.6 个百分点，在覆盖真实生产场景中长程编码与智能体任务的五个基准上平均提升 8.5 分；而没有环境进化时分别为 17.5 与 6.4 分。这些结果凸显了 RepoFactory 环境的训练价值，以及环境进化循环带来的额外增益。

简报

11. Gaspard：语音和手势一起生成，不再先说话后配动作

2611.24862

语音与手势是高度协同的多模态信号，现有方法多半是级联：先生成语音、再用语音驱动手势，语音生成本身与手势无关。Gaspard 是统一语音–手势生成模型，基于连续自回归生成与下一步流匹配预测，在大规模多模态数据集 Seamless Interaction 上训练；针对语音与手势异质的时间特性，采用模态专属预测头与解耦的分类器无关引导（CFG），在推理时重新平衡语音与手势的影响，在提升表现力的同时缓解连续自回归手势生成中的动态坍缩。客观与感知评估表明，Gaspard 对单模态基线是强劲的手势生成模型，且相比匹配的级联系统产生高度同步的语音与手势。作者：Téo Guichoux、Théodor Lemerle、Catherine Pelachaud、Nicolas Obin。来源 arXiv，未上 HF 日榜。

12. SLAM-ASR 靠的是 induction head：语音识别借用了文本的复制机制

2611.24721

一个小型映射就能把编码器状态接到冻结语言模型的嵌入空间、做出有竞争力的语音识别，靠的是什么？这篇证明 SLAM-ASR 模型依赖冻结语言模型的 induction head：文本里负责复制重复 token 序列的同一批头，对把语音嵌入映射到转录 token 也很重要；还发现成对的头表现为一种受约束的差分注意力，抵消注意力噪声、把注意力锐化到前一个已生成词上；最后展示了如何利用 induction head 在噪声音频下提升转录质量。作者：Artem Fedorchenko、Tanel Alumäe。来源 arXiv，未上 HF 日榜。

13. ALIVE：流式视频模型学会主动追问与协调任务

2611.21366

流式视频 LLM 能持续观察世界，却常常孤立地处理用户请求。ALIVE 是交互式流式视频模型，支持主动监测、流式任务协调与寻求反馈的交互；构建 ALIVE-SFT-288K 与 ALIVE-RL-3K 做两阶段训练：对比监督微调教模型何时以及如何回应，带行为对齐信用分配（BACA）的强化学习结合轨迹级与局部优势，在多轮交互中精修决策、回应与沉默；还引入 FSI-Bench 评估反馈寻求与后续任务完成。ALIVE 在四个公开基准与 FSI-Bench 上取得被比较模型中最高的总体得分。作者：Jinzhao Li、Yuan Xu、Jinxuan Wu、Yukun Wang 等。upvotes 32。

14. CurvDelta：低曲率空间里改模型，学新能力少忘旧本事

2611.24654

大模型适配的核心矛盾是能力保持：改出目标能力的同时别把通用能力搞垮。CurvDelta 把保持约束直接做到模型更新的参数化里：分析保持约束在预适配模型附近的局部几何，构造一个低曲率空间，使参数更新几乎不改变保持损失；用 Kronecker 分解近似曲率（K-FAC）与分解投影让构造在大模型上可行，并引入同几何下的低秩变体 CurvLoRA；适用于能力学习与选择性遗忘两类保持约束适配任务。在数学推理、代码生成上取得有竞争力的下游表现并更好地保持通用能力，在 TOFU 与 MUSE 遗忘基准上，目标遗忘与知识保持的平衡优于基线，保持表现接近从头重训的参照。作者：Zeguan Xiao、Zhuocheng Liang、Yun Chen、Yong Wang 等。upvotes 22。

15. WorldRuler：世界模型按自定义规则走，存档读档规则不断

2611.24869

规则决定玩家动作如何改变交互世界，不同规则在相似场景与动作空间里造出不同的游戏体验。WorldRuler 把规则定义、依赖与物体状态组织进可执行的 3D 规则图，把规则执行、视频生成与感知反馈连成闭环：规则图支持规则与世界状态的联合保存与恢复，动态物体绑定把规则指定的实体落到视觉实例上，并用存储的状态约束其首次出现时的生成；还引入物体属性状态替换与反事实重建训练，实现准确的属性控制与兼容的外观/运动变化，同时限制对无关内容的干扰。用 GTA-V 与 Habitat 搭建自动化数据采集与标注管线，构建规则驱动交互数据集 RuleVerse，含规则在受影响物体出现之前就已生效的案例。实验表明 WorldRuler 在存档/读档间保持规则–状态一致性，并准确实现指定物体与属性上的规则结果。作者：Mingliang Zhai、Chuanhao Li、Jiaming Tan、Zhen Li 等。upvotes 18。

16. BLIP-Live：流式视频助手何时开口，PAUC-F 管住时机与精度

2611.21553

流式视频助手要主动才自然有用：证据一够就回应，又不能过早、重复或错误地开口。BLIP-Live 围绕“主动性即有效的因果回应决策”统一数据、指标、harness 与训练：构建含人类标注的主动回应内容与时机的 BLIP-Live-780K 数据集，提出 PAUC-F 指标，把回应及时性指标与触发精度结合起来，奖励及时有用的回应而不奖励过度触发；还研究了从离线视觉语言模型中引出主动流式能力的模型无关推理 harness 与进一步提升主动响应能力的训练流程。BLIP-Live-Qwen 模型在四个主动流式基准上取得 SOTA，相对基线最高提升 44%，并超过多个闭源 API 模型。作者：Kanchana Ranasinghe、Honglu Zhou、Dominick Reilly、Le Xue 等。upvotes 9。

17. QDA：量化配方交给智能体设计，GLM-5.3-Flash 恢复 98.3%

2611.23388

事后量化是低成本服务大模型的标准做法，但最优配方随模型与精度而变，专家每次都要重做。QDA 让 LLM 智能体为每个模型与精度设计配方：评估快——用候选输出与原模型在智能体没见过的推理轨迹上的 KL 散度在几分钟内打分，再用长生成检查重复循环等失败；构建快——提供相互兼容、适配新架构的公开 PTQ 方法库。在四个推理模型上，QDA 在 W4A16、W4A8、W3A16 上比最强公开配方平均高 0.9、1.4 与 2.2 个百分点，每次搜索 64 GPU-h；在 320B 参数 MoE 模型 GLM-5.3-Flash 的 NVFP4 W4A4 上恢复 FP8 模型 98.3% 的准确率，而最优厂商 checkpoint 为 96.9%；所有 checkpoint 都能在现有服务 kernel 上运行、无推理开销。作者：Xingyang Li、Tianlang Zhao、Song Han、Ligeng Zhu。upvotes 8。

18. RoughCut-Bench：视频粗剪基准，语音驱动的清理也有份

2611.24098

视频粗剪是媒体生产流程的核心环节，把原始素材整理成初始剪辑。RoughCut-Bench 覆盖两类实际设定：（1）视觉驱动：101 个视频案例、831 条原始视频、1,476 条高光标注，测高光检测与选择、源视频排序、遵循用户要求；（2）语音驱动：84 个基于 ASR 转录的案例，测填充词去除、表达去重与低价值内容修剪。评估拿切分方案与标注对比，视觉设定还用人类对齐的智能体评估器评价成片质量；并给出引导 LVLM 产出结构化切分方案的智能体工作流。实验表明当前 LVLM 在产出专家对齐的切分方案上仍然有限。基准、代码与提示词已发布。作者：Ruisi Zhao、You Li、Sihan Chen、Aosong Cheng、Chixiang Ma 等。upvotes 9。
