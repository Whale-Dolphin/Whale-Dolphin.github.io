精评

1. 智能体总在证据不足时抢答：RLVB 用可验证信念奖励“该查就查、够了再答”，9 个设置全胜基线

2611.32884

一句话：RLVB 指出长任务智能体的“懒惰”根源是结局奖励分不出“蒙对的”和“有证据的”，于是用模拟器能算出的精确后验来奖励“证据不足时继续查、证据够了再提交”，在 3 个视觉解谜基准、9 个设置上全部超过基线，平均提升 17.1%。

贡献/机制：指出结局奖励只看最终答案，蒙对的和有证据支撑的答案拿一样的奖励，学不会“何时提交”；而训练时模拟器可以在每一步算出答案的精确后验、判断证据是否充分；提出可验证信念强化学习（RLVB）：后验仍允许多个答案时奖励继续行动，证据充分时奖励提交，奖励不需要裁判、评论家或奖励模型，也不读智能体每步行动前写下的信念行；同时提出 Pro Worlds 基准——智能体透过小窗口观察大世界的视觉解谜任务。作者：Richmond Sin Jing Xuan、Peilin Feng、Wenbin Wang、Soujanya Poria。

数值结果：在 3 个视觉语言模型、3 个基准（其中 2 个训练时未见）上，RLVB 在全部 9 个设置上都超过基线模型，平均提升 17.1%；而结局奖励下的 GRPO 和 PPO 平均反而低于基线；RLVB 还比“PPO + LLM 裁判过程奖励”平均高 9.3%，且 GPU 小时少用 1.6 倍。训练后的智能体在有充分证据时才作答的比例，在 3 个基准上分别为 51%、12%、74%，基线只有 8%、0.4%、36%；证据不足且信念行仍列多个答案时就提交的比例仅 0.1%–2.2%，基线为 3%–68%。

批判性分析：这篇抓的是智能体训练里一个很实在的漏洞：结局奖励教不会“谨慎”，因为它奖励的是结果不是过程；用模拟器后验当奖励信号是个干净的解法——不需要裁判模型、不读智能体的自我陈述，奖励本身就是可验证的。9 个设置全胜、且 GRPO/PPO 反而退步的对比很有说服力。但要留神：方法的核心依赖“模拟器能算精确后验”，这在 Pro Worlds 这类可控解谜环境里成立，到了开放世界、网页操作、真实机器人任务里，后验往往算不出来或算不准，迁移路径还不清楚；另外“证据充分”的阈值怎么定、会不会让智能体变得过度保守（一直查不提交），摘要里没有展开。值得看全文里后验阈值的设计与失败案例。

摘要译文：在长任务中工作的 AI 智能体常常在证据不足时就 committed 一个答案，这种行为被称为懒惰。在我们的评估中，它们即使在自己陈述的信念仍列出多个可能答案时也频繁提交。 episode 末尾的结局奖励只给最终答案打分，因此教不会智能体何时提交，因为蒙对的答案和有证据支撑的答案得到同样的奖励。然而在训练时，模拟器可以在每一步算出答案的精确后验，并判断证据是否已经足够。我们提出可验证信念强化学习（RLVB），它在后验仍允许多个答案时奖励智能体采取进一步行动，在证据充分时奖励提交。该奖励不需要裁判、评论家或奖励模型，也从不读取智能体每次行动前写下的信念行。我们还引入 Pro Worlds，一个视觉解谜基准，智能体通过小窗口观察一个大世界。我们在三个基准上评估了三个视觉语言模型，其中两个基准训练时从未见过。RLVB 在全部九个设置上都改进了基线模型，平均提升 17.1%。在结局奖励下，GRPO 和 PPO 平均低于基线模型。RLVB 还比使用 LLM 裁判过程奖励的 PPO 平均高出 9.3%，同时 GPU 小时少用 1.6 倍。训练后的智能体在三个基准上分别在 51%、12% 和 74% 的 episode 中以充分证据作答，而基线为 8%、0.4% 和 36%。因此，它的准确率提升来自更多地在高证据水平下作答。信念行展示了智能体如何达到这一证据：它按自己的信念行动。它仅在 0.1% 至 2.2% 的证据不足回合中提交，此时其信念行仍列出多个答案，而基线为 3% 至 68%。

2. Qwen3-Omni 的 Talker 到底用什么标签训出来的：Mimi bf16 复现了，最后一帧还有个坑

2611.32286

一句话：Qwen3-Omni 的 Talker 预测 16 个 codebook 的 12.5 Hz 音频 codec 标签，但做标签的编码器没开源；这篇用白盒回归加校准过的似然测试锁定了它就是 kyutai Mimi 的前 16 个 codebook、bf16 权重，并揪出 transformers 版 Mimi 编码最后一帧不一致的坑。

贡献/机制：指出 Qwen3-Omni 通过 Talker 说话，Talker 预测 16 个 codebook 的 12.5 Hz 音频 codec，但生成训练标签的编码器未发布，新声音无法用匹配的标签训练；通过白盒回归发现 Talker、多 token 预测器与 Code2Wav 解码器的 codebook embedding 与 kyutai Mimi 的前 16 个 codebook 逐层匹配；指出仅靠解码器的测试看似可信但校准失败——在已知标签上训练的解码器分不清各实现；而用 13 个 code 语言模型校准过的 teacher-forced Talker 似然能区分实现：Talker 更偏好 kyutai moshi 包 bf16 权重生成的标签；同时排除响度归一化与 20% 以上数据的带限处理；另外发现 transformers 的 MimiModel 编码最后一帧与 kyutai 编码器不同，除非输入长度是 1920 样本的倍数。作者：Yuxuan Chen。

数值结果：用复现标签 LoRA 微调后，44%–55% 的生成句子以噪声爆音结尾；同一帧让基于 Mimi 的 CSM-1B 损失 119 nats；对输入做 padding 后两者都消失。摘要未给出 Talker 本身的语音质量对比分数，这是一篇“复现配方”论文。

批判性分析：这篇对 AudioLLM 社区很实用：Qwen3-Omni 是开源全模态模型里被跟进最多的之一，Talker 标签不明一直卡着新声音的训练；白盒回归 + 校准似然的双重证据链很扎实，尤其是“解码器测试分不清、似然测试分得清”这个反直觉结论，提醒人别轻信单一验证手段。最后一帧的坑更是实打实的工程价值——44%–55% 的句子尾部噪声爆音，padding 就能修。但要留神：结论建立在“Talker 偏好 moshi bf16 标签”的似然证据上，仍是间接推断而非官方确认；且只验证了标签来源，没验证用这套标签训出的 Talker 在语音自然度、可懂度上能否复现原版。作者放出了编码配方、标签检查器与 Talker 微调工具包，值得直接拿来用。

摘要译文：Qwen3-Omni 通过一个 Talker 说话，该 Talker 预测 12.5 Hz 音频 codec 的 16 个 codebook，但制作其训练标签的编码器并未发布，因此新声音无法用匹配的标签进行训练。我们从已发布模型的行为中识别出这一编码器。白盒回归表明，Talker 的 codebook embedding、其多 token 预测器与 Code2Wav 解码器与 kyutai 的 Mimi 的前 16 个 codebook 逐层匹配。基于解码器的测试看起来可信，但校准失败：在已知标签上训练的解码器无法区分它们。用 13 个在已知标签上训练的 code 语言模型校准的 teacher-forced Talker 似然则能区分实现：Talker 更偏好来自 kyutai 的 moshi 包 bf16 权重的标签，而非我们尝试的其他每个变体。响度归一化与对 20% 或更多数据的带限处理被排除。另有一点，transformers 的 MimiModel 编码最后一帧的方式与 kyutai 的编码器不同，除非输入长度是 1920 样本的倍数。在其标签上 LoRA 微调后，44%–55% 的生成句子以噪声爆音结尾，同一帧让基于 Mimi 的 CSM-1B 损失 119 nats；对输入做 padding 后两者都消失。我们发布了编码配方、标签检查器与 Talker 微调工具包。

3. 交错多模态推理不用攒演示数据了：ThinkMorph-SSL 把图像修复本身变成推理监督，12 个基准平均涨 11.33 个点

2611.32183

一句话：ThinkMorph-SSL 提出两阶段配方：先把图像上色、去噪等视觉预任务转成“边想边画”的交错推理轨迹做无指令预训练，再用自动构造的演示做指令微调，完整配方比基线平均高 11.33 个准确率点。

贡献/机制：指出交错多模态推理让模型像人一样边生成中间图像边推理，但训练这种能力通常依赖任务专属演示，难以收集；提出 ThinkMorph-SSL，两阶段训练配方：第一阶段“预任务推理”把图像上色、去噪等视觉预任务转成无需指令的交错轨迹——模型描述被损坏或变换的图像、生成修复后或规范化的图像、再解读结果；第二阶段用自动构造的演示做问题驱动的指令微调。在同样的指令微调预算下，带预任务推理的模型优于只做指令微调的模型。作者：Jiawei Gu、Linjie Li、Yiming Liu、Yunzhuo Hao、Huichen Wang、Guanzheng Chen、Zhichao Peng、Luxin Xu、Xinyu Zhang、Li Luo。

数值结果：完整配方在 12 个基准上比基线平均提升 11.33 个准确率点；摘要未拆分各基准分数，也未点名基线模型与参数规模。

批判性分析：这篇的思路很漂亮：图像本身就是监督信号——上色、去噪这些预任务天然就是“先想、再画、再看”的推理过程，不用人工攒演示就能规模化；“同等指令微调预算下预任务阶段仍有增益”的对照也做得干净，说明增益来自预任务本身而非更多数据。但要留神：摘要只给了 12 个基准的平均涨幅，没拆分哪些任务涨、哪些没涨，也没说基线是谁、多大规模；预任务推理的轨迹质量（模型自己生成的中间图像是否可靠）与“交错推理”在真实复杂任务上的上限，都要读全文。交错推理是多模态推理的下一个方向，这篇的配方值得复现时参考。

摘要译文：人们用图片和文字一起推理。交错多模态推理让模型以类似方式解决问题：生成中间图像并用它们引导进一步推理。训练模型具备这种能力通常依赖任务专属演示，难以收集。我们引入 ThinkMorph-SSL，一个两阶段训练配方，利用图像本身作为监督来源。第一阶段“预任务推理”把图像上色、去噪等视觉预任务转成无需指令的交错轨迹：模型描述一张被损坏或变换的图像，生成修复后或规范化的图像，并解读结果。第二阶段使用自动构造的演示进行问题驱动的指令微调。在相同的指令微调预算下，经过预任务推理训练的模型优于仅经过指令微调的模型。完整配方在 12 个基准上比基线平均提升 11.33 个准确率点。这些结果表明，从图像中导出的监督可以构建交错推理所需的视觉能力，并改善从任务专属演示中的学习。

4. 医院里的空间推理，35 个多模态大模型集体不及格：Clinical3D-Bench 最高 53.6%，医生 79%

一句话：Clinical3D-Bench 用 373 个医院病房布局的第一人称漫游视频考多模态大模型的空间智能，35 个模型里最好的专有模型只有 53.6%，医生是 79%；微调能追上，但模型基本不会用给它的 3D 地图，作者提出的 GeoJeV 改为让模型自己算 3D，拿到最高分。
