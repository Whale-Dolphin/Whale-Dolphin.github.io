精评

1. 量化智能体总在关键处跑偏：SteerDistill 让老师闭环纠偏，W4A16 追到 BF16 一分以内

2611.13410

一句话：SteerDistill 针对低比特量化后智能体“漏看任务要求、走偏环境转移”的失败模式，让全精度老师在学生的失败轨迹上闭环纠偏、再把纠偏内化进学生权重，在 5 个智能体基准、3 个模型上 W4A16 平均分超过最强量化基线 1.67 至 2.18 分、与 BF16 的差距不到 1 分。

贡献/机制：低比特量化能降低 LLM 智能体的推理成本，但会损害任务成功率。作者检查失败轨迹发现，量化智能体常常忽略任务要求或环境条件，产生与全精度参考成功轨迹偏离的环境转移。纠偏并不容易：离线数据可能覆盖不到学生的失败场景，而学生自己的轨迹在这些场景里又很少有正确回应。SteerDistill 是一个量化感知蒸馏方法：全精度老师引导学生修正失败回应，并用学生执行的反馈迭代改进自己的引导，产出经局部验证的行为纠正；随后训练学生在被纠正的轮次上复现“被引导的学生”的预测、在其他轮次上复现全精度老师的预测，从而把纠正内化，推理时无需引导。作者：Genming Cui、Xiangyu Li、Zixu Hao、Xin Ding、Yunxin Liu、Ting Cao（6 人）。

数值结果：在 5 个智能体基准与 3 个模型上，W4A16 下 SteerDistill 平均分超过最强量化基线 1.67 至 2.18 分，与 BF16 的差距在 1 分以内；在 τ²-Bench 上，相比 QeRL 成功率高 1.84 个百分点，同时训练 GPU 小时少 67%，成功轨迹也比量化基线更短。

批判性分析：这篇的切入点比“再压一个比特”实在——它先定位了量化智能体特有的失败形态（行为偏离而非单纯能力下降），再用“老师在失败点上闭环纠偏”对症下药；67% 更少的训练 GPU 小时加更短的成功轨迹，说明纠偏不是靠堆算力，而是靠把监督放在学生真正会错的地方。但要注意两点：一是 1.67 至 2.18 分的领先建立在“最强量化基线”之上，基线本身的强度决定了这个数字的含金量；二是方法依赖一个全精度老师全程在环，蒸馏完成后虽可脱手，但训练阶段的老师成本与“失败场景覆盖度”仍是瓶颈——离线数据覆盖不到的失败，闭环也未必能自己长出来。

摘要译文：低比特量化降低了 LLM 智能体的推理成本，但可能损害任务成功率。检查失败轨迹后我们发现，量化智能体常常忽略任务要求或环境条件，产生与成功的全精度参考偏离的环境转移。纠正这些行为偏离并不容易：离线数据可能错过学生的失败场景，而学生自己的轨迹在这些场景里又很少提供正确回应。我们提出 SteerDistill，一种量化感知蒸馏方法：全精度老师引导学生修正失败回应，并用学生执行的反馈迭代改进引导。这种闭环的老师引导产生经局部验证的行为纠正。我们通过训练，让学生在被纠正的轮次上匹配被引导学生的预测、在其他轮次上匹配全精度老师的预测，从而把这些纠正内化，实现无需引导的推理。在五个智能体基准与三个模型上，SteerDistill 在 W4A16 下的平均分超过最强的量化基线 1.67 至 2.18 分，并保持在 BF16 的一分以内。在 τ²-Bench 上，它比 QeRL 的成功率高 1.84 个百分点，训练 GPU 小时少 67%，且成功轨迹比量化基线更短。

2. 代码智能体进物理世界前先考试：1,156 个任务、47 台机器人，最强的 GPT-6 Astra 也只有 34%

2611.12177

一句话：Embodied First Exam 是第一个为“代码智能体控机器人”而建的统一评测框架——1,156 个任务、35 个套件、47 台机器人，智能体可自选直接控制、写代码控制或训策略控制，456 个核心任务上 8 个智能体里最强的 GPT-6 Astra（Codex 内）标准设置成功率只有 34%。

贡献/机制：用代码智能体控制机器人可能是一次范式转移，但现有机器人基准都围绕视觉运动策略学习搭建，没回答“代码智能体能否在物理约束下可靠控制多样的机器人”。Embodied First Exam 是一个统一、全面、智能体原生的评测框架：智能体可自选控制方式——直接控制、写代码控制、或训练一个策略来控制；含 1,156 个任务、35 个套件、47 台机器人，其中 9 个新套件超出抓放范畴，覆盖空间拼图、灵巧操作、多机器人交互、动态全身控制与仿真到仿真工程。每个任务最多三种评估设置：标准设置模拟真实世界——智能体只拿到传感器观测、默认不能重置环境；实时变体让环境在智能体推理时继续运行；特权设置给智能体完整仿真器状态与无限重置，可搜索 oracle 解用于训练，其成功率可作近似上界。作者还标注了失败发生在哪个阶段，并跨智能体、设置与阶段类别比较失败模式。作者：Kangrui Wang、Qineng Wang、Changhe Chen、Pingyue Zhang、Chi Gui、Feishi Wang、Canyu Chen、Wenli Xiao（8 人）。

数值结果：456 个核心任务上，8 个智能体中最强的 GPT-6 Astra（Codex 内）在标准设置下的成功率为 34%，留有很大提升空间。

批判性分析：这篇的价值在于把评测口径从“策略学得好不好”换成了“智能体能不能在真实约束下把机器人用起来”——不能重置、环境实时推进，这两条恰恰是仿真评测里最常被抹掉的真实性；三种设置加失败阶段标注，也让“差在哪一步”变得可诊断。但 34% 这个数字要打折扣看：它只是 8 个智能体在 456 个核心任务上的最好成绩，摘要没有展开各套件、各控制方式的分布，也没有说特权设置的上界是多少——不知道天花板在哪，就难判断 34% 离“能用”还有多远；而且“代码智能体”这个范式本身是否比训策略更适合机器人，仍需更多任务上的对照。

摘要译文：智能体机器人早期的成功指向一种可能的范式转移：用代码智能体控制机器人。现有机器人基准围绕视觉运动策略学习搭建，留下一个开放问题：代码智能体能否在物理世界的约束下可靠控制多样的机器人。为此我们提出 Embodied First Exam，一个统一、全面、智能体原生的评测框架，代码智能体可自选控制方式：直接控制、写代码控制、或训练一个策略来控制。我们希望它成为代码智能体进入物理世界前的第一场考试，含 1,156 个任务、35 个套件、47 台机器人，其中 9 个新套件超出抓放范畴，覆盖空间拼图、灵巧操作、多机器人交互、动态全身控制与仿真到仿真工程。每个任务最多可在三种评估设置下运行。标准设置模拟真实世界：智能体只收到传感器观测，默认不能重置环境；其实时变体让环境在智能体推理时继续运行；特权设置给智能体完整的仿真器状态与无限重置，允许其搜索 oracle 解用于训练，该设置下的成功率可作近似上界。在 456 个核心任务上，8 个智能体中最强的 GPT-6 Astra（Codex 内）在标准设置下的成功率为 34%，留有很大提升空间。为看清智能体在哪里失败，我们标注了失败尝试出错的阶段，并跨智能体、设置与阶段类别比较失败。

3. 7.6M 参数的土耳其语 TTS：只用合成语音训练，M5 笔记本 CPU 上 41 倍实时

2611.13811

一句话：Antalia-2 Mini 是一个 7,620,931 参数的单音色土耳其语 TTS 模型，训练音频全部来自大 300 倍的教师模型 VoxCPM2 的合成语音，在 Freya-TR-Eval 上词错率 1.09%、字错率 0.22%，与 8.6M 参数的 EMA Lightning 在统计上难分高下。

贡献/机制：Antalia-2 Mini 直接读字符、输出 48kHz 音频，在 Apple M5 笔记本 CPU（2 线程）上达到 41 倍实时。训练音频只来自教师模型 VoxCPM2（约大 300 倍）克隆的一段合成语音，自动检查后保留约 1,790 小时；在声学模型自己的梅尔谱上微调声码器后，Whisper 转录的词错率从均值 3.89% 降到 1.75%。一个值得注意的细节是：教师会在以 ö 开头的词的开头损坏片段，学生把这个毛病也学去了，作者用一段从输出中切掉的 spoken prefix 把它藏起来。在 495 句的 Freya-TR-Eval 基准（调参也在其上进行）上，1.0.1 版的词错率 1.09%、字错率 0.22%；配对 bootstrap 无法把它与 EMA Lightning（8.6M 土耳其语模型，全频带 UTMOS 得分更高）区分开。权重、推理代码与基准 harness 以 Apache-2.0 公开，训练代码与数据不公开。作者：Sezgin Saygili、Emre Kaplaner、Oncel Ozgul、Fikri San Koktas（4 人）。

数值结果：Freya-TR-Eval 上词错率 1.09%、字错率 0.22%；声码器微调把 Whisper 转录词错率从 3.89% 降至 1.75%；尚无人类听感测试。

批判性分析：这篇最有意思的结论藏在同门大模型 Alania-2 的对照里：7.6M 的单音色小模型与 2.3B 模型的可懂度只差半个点，说明在可懂度这个维度上训练数据比模型规模更重要；“只用合成语音训练”也把低资源语言 TTS 的数据门槛降到了一个教师模型。但要冷静看三点：一是评测基准就是调参用的那个基准，1.09% 有过拟合到评测集的风险；二是没有人类听感测试，UTMOS 这类英文训练的代理指标在土耳其语上的可信度有限；三是学生连教师的 ö 开头损坏都学去了，提醒合成数据训练会把教师的系统性毛病一并继承——切掉一段 spoken prefix 是治标，数据清洗才是治本。

摘要译文：Antalia-2 Mini 是一个单音色土耳其语文本转语音模型，共 7,620,931 个参数。它读入字符、在 Apple M5 笔记本 CPU（2 线程）上以 41 倍实时生成 48kHz 音频。其训练音频全部来自 VoxCPM2（教师模型，约大 300 倍）克隆的一段合成语音；自动检查后保留约 1,790 小时。在声学模型自己的梅尔谱上微调声码器后，Whisper 转录的词错率从均值 3.89% 降到 1.75%。教师会在以 ö 开头的词的开头损坏片段，学生也学到了这一点，我们从输出中切掉的一段 spoken prefix 把它藏了起来。在 495 句的 Freya-TR-Eval 基准（我们也在其上调参）上，1.0.1 版的词错率 1.09%、字错率 0.22%。配对 bootstrap 无法把这些结果与 EMA Lightning（一个 8.6M 的土耳其语模型，在英文训练的质量代理指标全频带 UTMOS 上得分更高）区分开。不存在人类听感测试。权重、推理代码与基准 harness 以 Apache-2.0 公开；训练代码与数据不公开。

4. 世界动作模型也要保住语言对齐：SWAM 用 47,000 小时视频摸清配方，RoboTwin 上 88.10%

2611.12870

一句话：SWAM 系统研究了世界动作模型训练中语言-视频对齐如何被动作学习冲掉、又该如何保住——在约 47,000 小时通用、第一人称、UMI 演示与机器人演示构成的池子上摸清数据与监督配方后，只用 RoboTwin Clean 演示后训练的模型在 Easy/ Hard 设置下成功率 88.10% / 61.56%，真实世界三任务 40.00% 对最强基线 23.33%。

5. 智能体推理的 P95 首 token 延迟能压 14 倍：Evolving Infra 让算力分配跟着智能体工作负载走

一句话：Evolving Infra 是一个智能体自适应的 LLM 服务框架——把算力分配与 KV 缓存管理解耦，节点可在 prefill 与 decode 间切换，在线规划器按工作负载配 PD 比例、智能体感知的 KV 管理器按上下文复用情况管驱逐与迁移，在 GLM-5.2 与 Kimi K2.6、最多 256 块 GB300 上，相比 NVIDIA 生产框架 Dynamo 平均端到端延迟最多降 4.1 倍、P95 首 token 延迟最多降 14 倍。

批判性分析：这个工作的工程判断很准——智能体推理的 KV 复用模式与普通聊天完全不同（多轮工具调用、反复回到同一上下文），用“智能体会复用”这个信号指导驱逐，比通用 LRU 高明得多；把 PD 分配与 KV 管理解耦，也让系统能跟着工作负载的相位走。但数字要打折扣看：“最多 4.1 倍 / 14 倍”是峰值收益，摘要没有给中位收益与延迟分布，也没有展开在线规划器本身的开销与切换成本——在 256 卡规模上，规划与迁移的开销一旦失控，峰值收益未必能兑现为日常收益。

摘要译文：智能体工作负载是 LLM 推理需求的主要来源之一。现有 prefill-decode（PD）分离服务系统在运行时调整算力分配与 KV 缓存管理上的灵活性有限，且依赖的粗粒度信号只能部分刻画多样、动态的智能体工作负载。这些限制导致 prefill 与 decode 节点间负载不均，以及智能体会复用的 KV 缓存被驱逐。我们提出 Evolving Infra，一个智能体自适应的服务框架，它在运行时把算力分配适配到智能体工作负载、把 KV 缓存管理适配到智能体上下文管理。我们把算力分配与键值（KV）缓存管理解耦，让节点能在 prefill 与 decode 之间高效切换。在此设计之上，在线规划器按工作负载构成匹配 PD 比例，而智能体感知的分布式 KV 管理器用智能体上下文管理发出的信号指导缓存驱逐与迁移。在编码、数学与计算机使用任务上，用 GLM-5.2 与 Kimi K2.6、在最多 256 块 GB300 GPU 上，Evolving Infra 相比 NVIDIA 的生产框架 Dynamo，把平均端到端请求延迟与 P95 首 token 延迟分别最多降低 4.1 倍与 14 倍。

6. 生成、补全、预测其实是同一张表：One Table 用 56 个数据集、46 种方法给通用表格模型出了一张总卷

2611.13001

一句话：One Table Benchmark 把生成、补全与预测三类任务放进同一套对齐切分与显式任务契约下比较——56 个数据集、46 种方法、20 个能力维度，结论是三类能力通过数值恢复与依赖保持等机制相互关联、但分布保真度的排序常常相反，通用模型在效用上能超过专家组合、保真度上仍输给专科。

贡献/机制：生成、补全与预测考察的是同一表格分布的不同方面，但通常被分开评测，于是三类能力共享什么、训练目标如何相互作用、一个模型能否三者都做好，一直不清楚。One Table Benchmark 覆盖 56 个数据集、46 种注册方法与 20 个能力维度，在对齐的数据切分与显式任务契约下评测。作者在对齐支撑集上比较任务排名，在 5 个数据集上用 3 个随机种子、把 5 个 backbone 在全部 7 种非空目标组合下训练，并对照固定模型画像与专家组合。排名比较显示，补全与预测通过数值恢复与依赖保持相连，生成则通过预测效用与两者相连；而分布保真度遵循不同、有时相反的排序。目标干预显示，包含接收方自身目标带来的 pooled 增益最大；生成带来的正向辅助效应覆盖最广，预测则有潜力改善补全与合成数据效用，但响应因 backbone 而异；交叉叠加效应表明目标收益不一定可加、且取决于已有的目标组合。固定模型比较揭示了对应的效用-保真度权衡：一些通用模型在效用上超过专家组合，而保真度仍偏向专科；冻结的基础模型在预测与数值点补全上很强，合成数据效用也很有前景。作者：Yuanrui Wang、Kaifang Li、Xuanyue Li、Ziyun Li、Yan Lu、Xingxuan Zhang、Peng Cui（7 人）。

7. 机器人的记忆只是在数时钟：暂停一下，计数任务成功率就从 47/50 掉到 16/50

2611.14488

一句话：记忆增强的视觉-语言-动作策略被发现有个“时间捷径”——记忆按时间均匀采样帧并打上时间戳，机器人原地暂停或晃一下手腕这种什么都不改变的空事件，也会被当成工作进度记下来，于是计数任务上成功率从 47/50 掉到 16/50，而按事件索引记忆能不重训就挽回一半以上的损失。

贡献/机制：记忆增强的 VLA 策略本该记住发生过什么，但很多实现是按时间填充记忆的：均匀采样整段轨迹的帧、并给每帧打上时间步。因为时间一直在走——哪怕什么都没发生——这样的记忆分不清“等待”与“工作”。作者在 RoboMME 的计数任务上验证：让机器人短暂暂停或晃动手腕，这种空事件不改变任务依赖的任何东西，但已发布的记忆 VLA 会把这段时间当成已完成的工作、提前停下，作者称之为“幽灵进度”（phantom progress）。一个任务上成功率从 50 个中的 47 个掉到 16 个，另一个从 44 个掉到 10 个；把同样的帧从记忆里扣掉后成功率恢复，说明原因在记忆而非中断本身。进一步追溯到时间捷径：演示以稳定节奏推进，流逝时间可以预测进度；只重标时间戳就能让策略在时钟变快时提前停下、变慢时重复。令人意外的是，去掉时间编码也治不好——因为空事件的帧仍占据时间采样记忆的槽位。在 RoboMME 已发布的几种设计中，脆弱性取决于记忆如何索引。在诊断提示的修复中，训练时注入暂停去不掉这个毛病、还会损害计数，而按事件索引记忆无需重训就能挽回一半以上的损失。作者：Chubin Zhang、Bo An（2 人）。

数值结果：RoboMME 计数任务上，空事件使成功率从 47/50 降至 16/50、从 44/50 降至 10/50；按事件索引记忆可挽回一半以上的损失，无需重训。

批判性分析：这篇的诊断干净利落——“记忆在数时钟而不是数事件”是一个所有按时间采样记忆的系统都可能踩的坑，而“暂停一下就提前停下”这个失败形态在真实部署里几乎一定会遇到（机器人等待、卡顿、重试都是空事件）；“去掉时间编码也治不好”这个反直觉结果尤其有价值，说明问题不在时间戳本身、而在记忆的采样与索引方式。但要注意两点：一是验证集中在 RoboMME 的计数任务上，这类任务对进度计数特别敏感，其他任务形态下时间捷径的危害有多大还不清楚；二是“挽回一半以上损失”仍留了一半在桌上，按事件索引只是缓解而非根治——事件本身如何定义与切分，仍是开放问题。

摘要译文：记忆增强的视觉-语言-动作（VLA）策略本该记住发生过什么，但其中很多是按时间填充记忆的：均匀采样整段轨迹的帧、并给每帧打上时间步。因为时间一直在走——哪怕什么都没发生——这样的记忆可能分不清等待与工作。我们证明它确实分不清。在 RoboMME 的计数任务上，我们让机器人短暂暂停或晃动手腕。这种空事件不改变任务依赖的任何东西，但已发布的记忆 VLA 会把这段时间当成已完成的工作、提前停下。我们称这种失败为幽灵进度。它在一个任务上把成功率从 50 个中的 47 个砍到 16 个，在另一个上从 44 个砍到 10 个。把同样的帧从记忆里扣掉后成功率恢复，因此原因在记忆而非中断本身。我们把失败追溯到一个时间捷径：因为演示以稳定节奏推进，流逝时间可以预测进度。的确，只重标时间戳就能让策略在时钟变快时提前停下、变慢时重复。令人意外的是，去掉时间编码也治不好这个毛病，因为空事件的帧仍占据时间采样记忆的槽位。在 RoboMME 已发布的几种设计中，脆弱性取决于记忆如何索引。在诊断提示的修复中，训练时注入暂停去不掉这个毛病、还会损害计数，而按事件索引记忆无需重训就能挽回一半以上的损失。记忆若要记住发生过什么，就该数事件而不是数时钟。

8. 模型与技能一起进化：SkillDuet 让技能随模型长大，ALFWorld 98.57%、WebShop 92.97%

2611.12109

一句话：SkillDuet 协调强化学习里“参数内化”与“外部技能”两条经验复用路线——技能从在线轨迹中提取、用响应反馈打分并定期并入全局技能集，再与更新后的模型一起指导下一轮交互，Qwen3-4B 上 ALFWorld 成功率 98.57%、WebShop 92.97%，分别超过匹配的 SEED-API 基线 2.86 与 5.47 个百分点。

数值结果：Qwen3-4B 上，SkillDuet 在 ALFWorld 成功率 98.57%、WebShop 92.97%，分别超过匹配的 SEED-API 基线 2.86 与 5.47 个百分点；消融显示基于响应的技能选择与 Global 并入都能提升任务表现。

批判性分析：这篇把智能体训练里一个常被忽略的张力摆到了台面上——技能是写在权重里还是留在外部，两者会互相影响、而且旧技能会随着模型变强而过期；用“技能对当前响应的改变量”给技能打分，是个符合直觉的筛选标准，定期并入全局集的设计也避免了技能库无限膨胀。但要注意两点：一是 98.57% 与 92.97% 的绝对值已接近 ALFWorld 与 WebShop 的天花板，2.86 与 5.47 个点的领先有多少来自 SkillDuet 本身、多少来自基线 SEED-API 的配置，需要看消融的完整口径；二是结论建立在 Qwen3-4B 一个模型与两个基准上，技能-参数协同进化的收益是否随模型规模变化，摘要没有回答。

摘要译文：在强化学习中，经验既可以内化进 LLM 参数、也可以作为可复用的文本技能保留在外部。参数更新改变模型行为与交互经验，从中提取新技能；这些技能反过来指导模型后续的交互与参数更新。随着模型能力进化，曾经有益的技能可能变得多余甚至有害。我们提出 SkillDuet，一个通过模型响应反馈协调参数更新与技能进化的框架。从在线轨迹提取的技能通过 OPD 在每一步指导参数更新。一个基于响应的分数 Strength 按候选技能对当前模型响应造成的改变量给它们排序，得分最高的技能定期并入持久的全局技能集（Global）。更新后的模型与 Global 共同指导后续交互，生成进一步参数与技能更新的经验。用 Qwen3-4B，SkillDuet 在 ALFWorld 与 WebShop 上成功率分别为 98.57% 与 92.97%，分别超过匹配的 SEED-API 基线 2.86 与 5.47 个百分点。消融显示，基于响应的技能选择与 Global 并入都能提升任务表现。进一步实验表明，保留技能的收益既取决于其内容、也取决于其与模型的兼容性。SkillDuet 为模型-技能协同进化与技能层面的递归自我改进提供了一个具体机制。

简报

9. 灾害报告也要有证据链：DisasterAgent 用感知图加行内引用，报告生成平均分提高 13.5%

2611.13776

DisasterAgent 针对遥感灾害评估从“分类损伤”走向“写整份报告”的需求：先用视觉专家工具包在感知阶段建一张时空感知图（STPG），把双时相光学影像里的灾害变化按时空结构存成记忆；再用基于证据的增强（EA）从图中抽证据、给每句话挂行内引用，形成从陈述到视觉证据的闭环。DisasterM3 上灾害报告生成的平均分比原模型提高 13.5%，RSCC 上 ST5-SCS 提高 15.34%，持续超过通用 VLM、遥感专用模型与已有遥感智能体。作者：Zhijian Li 等（7 人）。

10. 蛋白进化也可以有世界模型：ProTEUS 闭环实验，两轮改造活性都超过野生型 10 倍

2611.13348

ProTEUS 是一个面向闭环蛋白进化的突变解析世界模型：在深度突变扫描数据上预训练，用 MutationFormer（突变偏置注意力架构）联合表示序列、进化与结构信息，把变体当作联合隐空间里的状态、突变当作动作并预测其功能后果；还配了一个快速、物理约束的全原子预测器，用显式几何约束保证物理有效性、比 AlphaFold3 快 10 倍以上。在醛脱氢酶与果聚糖蔗糖酶两轮闭环多目标改造中，得到的变体活性都比野生型高 10 倍以上；在零样本与监督微调突变预测任务上都超过已有模型。作者：Yikun Zhang 等（8 人）。

11. 检索不是找得像就行：TRIAD 测了 17 个系统，没有一个在六个子集上都领先

2611.12364

多模态检索越来越多地服务智能体系统：用户请求可能跨层级关联、组合多重约束、并在多轮对话中演变——高度相似的结果仍可能违反要求。TRIAD 是一个检验检索系统能否满足这类复杂、演变请求的基准，分抽象、约束、状态三条赛道：抽象测视觉实例与概念在不同层级间的双向检索，约束测正负条件的联合满足，状态测跨对话轮次整合需求与用户改口后的更新。基准含六个子集，每子集 1,000 条查询、每查询固定 1,000 个候选池，用统一的多正例 mAP 评估。评测 17 个系统的 20 种配置后，没有一个系统在六个子集上都领先；表现随层级距离下降，仅负约束的查询通常比同等数量约束的仅正查询更差；40 组配对比较中有 39 组多轮检索的 mAP 更低。作者：Xiangyang Wu 等（7 人）。

12. 土耳其语 TTS 的大号版本：Alania-2，488M 参数、18,195 小时，词错率 1.44%

2611.13845

Alania-2 是 Antalia-2 Mini 的同门大模型：488M 参数、VoxCPM 架构（语言模型 backbone 加扩散头生成连续音频隐变量），从头训练于 18,195 小时土耳其语语音，其中 90% 是经自动过滤的教师合成语音。文本规范器把数字、缩写与外文名改写成土耳其语说法：没有它，96 句含数字的测试句里没有一句能把金额、日期等关键部分完整保留下来，有它则 86 句可以。在 Freya-TR-Eval 上词错率 1.44%，而上一代系统为 5.99%；内置音色上与 2.3B 参数模型只差不到半个点的字错率，尺寸不到其四分之一。克隆方面的实用发现：只以参考音频为条件而不接着续写，可把跳词率从 21.9% 降到 1.7%；20 至 30 秒参考音频效果最好；约两分钟训出的低秩适配器能把说话人相似度提至远超即时克隆；单流首音频低至 32ms。作者：Sezgin Saygili 等（4 人）。

13. 灵巧操作也需要空间预见：DexForesight 把世界模型冻进策略隐空间，11 个仿真任务 49.4% 到 60.5%

2611.11166

灵巧操作需要对场景与机器手都有丰富的空间预见，已有世界-动作模型多用显式未来预测来获得这种知识。DexForesight 改为隐式学习：训练时从离线场景深度、运动学手部几何与演示轨迹中学习一个动作条件空间世界模型，预测三维手部点运动与视觉特征变化（含相机看不到的手指遮挡运动）；随后冻结世界模型、把策略查询与世界模型的预测性查询对齐，把学到的空间动态迁移进策略隐空间、用于条件化动作生成。部署时只保留策略，仅用 RGB 观测、语言与机器人状态，不需要深度输入或显式未来预测。11 个 DexJoCo 仿真任务上总体成功率从 49.4% 提高到 60.5%；三个真实机器人灵巧操作任务上 58.3%，最强基线为 50.0%。作者：Zhongxi Chen 等（8 人）。

14. 智能体 SOP 可以蒸馏成不用 LLM 的工作流：ReTrace 在 τ²-Bench 上 1.3 秒跑完 170 秒的活

2611.14492

业务流程自动化是同一份标准操作程序（SOP）在新输入上反复执行，LLM 智能体每步都要调一次 LLM 来选下一步，又慢又贵。ReTrace 把一份 SOP 与少量已记录的智能体运行轨迹变成可复用的工作流：代码而非 LLM 选择下一步——从智能体每步工具调用时写的推理中抽取步骤背后的条件、跨运行合并成紧凑的规则文档、再生成可执行工作流；只有最后一步依赖平台，规则文档可编译到不同编排平台。79 个生产流程上完成率 93.8%（智能体 96.8%）、每任务成本低 24%；τ²-Bench 上任务成功率 75.8%（智能体 80.6%）、耗时 1.3 秒对 170 秒；三轮修复把 k=2 工作流从 66.7% 提到 81.2%。作者：Kaiyuan Hou 等（8 人）。

15. 智能体爬网站基本不守法：ScrapeBench 上多数智能体合规率不到 5%，Claude Opus 4.6 反而过度拒绝 98.5%

2611.11306

ScrapeBench 是第一个实证评测 AI 智能体遵守网站抓取政策（服务条款与 robots.txt）情况的基准。在 1,626 个明确禁止抓取的热门网站样本上，多数智能体合规率不到 5%；即使智能体主动检查了适用的 ToS 与 robots.txt，合规率仍然很低。反过来，在 269 个不禁止抓取的网站上，智能体有时明明合法却拒绝抓取，Claude Opus 4.6 的过度拒绝率达 98.5%。180 名参与者的人类基线实验显示，人类合规率与 AI 智能体相当，但过度拒绝率要高得多。作者：Joseph Marvin Imperial、Daniel Slate、Noam Kolt（3 人）。

16. 面向实时生成音频的流式自编码器：AudioCodex 把立体声压到约 10Hz 隐序列，全程严格因果

2611.12375

AudioCodex 是一个全因果自编码器，面向实时交互与流式生成音频应用：把立体声音频压缩成约 10Hz 的紧凑连续隐序列。方法组合了 Mean Flow 幅度自编码器、隐空间超球面投影、有界噪声增强、表示对齐与对抗相位恢复，学到的表示既支持高效的下游生成、也支持高质量重建；大量消融显示，它在生成-重建权衡上超过当前最优，同时编码与解码都严格因果。摘要未给出具体的重建或生成分数。作者：Marco Pasini 等（5 人）。
