精评

1. 音频智能体别急着下判断：Think2Listen 先找证据再承诺，准确率 +5–17.7 个点

2611.21083

一句话：大音频语言模型能听见内容，却未必会用声音当证据做推理，Think2Listen 用“先证据、后承诺”的迭代交互主动找能区分假设的声学线索，在两个基准七个音频类别上把音频智能体的准确率提高了 5.08%–17.67%。

贡献/机制：针对“感知声学内容”与“把它作为推理证据”之间的鸿沟，Think2Listen 把迭代推理与有针对性的 LALM 交互耦合：主动寻找能区分竞争假设的声学线索，根据返回的观察修正候选判断；学习问什么、如何使用证据、何时停止，用观察引起的候选状态变化来指导训练信用分配。代码：https://github.com/JinWang79/Think2Listen。作者：Jin Wang、Liang Lin、Kaiwen Luo 等。

数值结果：在覆盖七个音频类别的两个基准上，多步音频推理的整体准确率比竞争的音频智能体高 5.08%–17.67%；跨语音、声音与音乐的音频理解与推理，整体准确率比相应基线高 2.29%–13.10%。

批判性分析：这个工作的切口很准——音频理解的瓶颈早就从“听见了什么”移到“凭什么这么判断”，把证据搜寻做成可学习的交互循环，比单纯堆工具调用更接近智能体该有的样子；5–17 个点的提升幅度也说明这条路不是小修小补。但要留神两点：一是提升区间的下限（2.29%）与上限（17.67%）差距很大，收益在哪些类别上集中、哪些上微弱，摘要没有展开；二是“何时停止”的判断本身若学偏了，多步交互可能变成无效追问，成本与收益的账得看正文。

摘要译文：最近，大音频语言模型（LALM）的进展拓宽了跨语音、声音与音乐的音频理解，基于工具的智能体通过调用预定义的音频工具进一步支持这些任务。然而，感知声学内容与把它作为推理证据使用之间仍有一道持续的鸿沟：认出能听到什么，并不能保证模型识别出哪些线索能解决一个不确定的决策。为弥合这一鸿沟，我们提出 Think2Listen，一个面向智能体音频理解的证据中心学习框架。在“先证据、后承诺”的指导下，Think2Listen 把迭代推理与有针对性的 LALM 交互结合起来，主动寻找能区分竞争假设的声学线索，并根据返回的观察修正候选判断。它学习问什么、如何使用证据、何时停止，用观察引起的候选状态变化来指导训练信用分配。在覆盖七个音频类别的两个基准上的大量评估表明，Think2Listen 实现：（一）增强的多步音频推理，在整体准确率上比竞争的音频智能体高 5.08%–17.67%；（二）跨语音、声音与音乐的音频理解与推理提升，整体准确率比相应基线高 2.29%–13.10%。源代码见 https://github.com/JinWang79/Think2Listen。

2. TTS 该知道哪里该重读：ProTTS 自己发现词重音，MOS 3.96 对 3.12、偏好率 83.5%

2611.19832

一句话：大多数 TTS 对重音不敏感、少数重音感知系统又依赖外部标注，ProTTS 让重音检测从 TTS 模型自身中涌现并反过来引导合成，听众偏好率 83.5%，重音检测零样本迁移 F1 达 0.933。

贡献/机制：在 FastSpeech2 的方差适配器中加入聚类头，直接从聚合的韵律特征中发现词重音；发现的重音驱动强调方差预测器，修改重读词的音高、能量与时长；TTS 重建损失与聚类损失联合训练，全程不需要重音标签；推理时接受自定义重音掩码，支持用户可控的强调。作者：Sai Harshitha Aluru、Chiranjeevi Yarra（2 人）。

数值结果：听众偏好 ProTTS 而非基线，MOS 为 3.96 对 3.12，偏好率 83.5%；重音检测在 ISLE（德语/意大利语二语）上取得 0.839/0.861 F1，超过无监督（0.70）与有监督（0.82）基线，并在 Tatoeba 上零样本迁移取得 0.933 F1。

批判性分析：这篇的优雅之处在于把“发现重音”和“用重音合成”放进同一个端到端循环——不需要标注是真省事，而 0.933 的零样本迁移 F1 说明学到的重音特征不是只在训练分布里有效；MOS 提升 0.84 也相当可观。但要留神：评估覆盖的语言仍有限（ISLE 是德语/意大利语二语者、Tatoeba 迁移也未说明语言广度），重音模式跨语言能走多远还得看；而且“用户自定义重音掩码”的可用性是宣称，摘要没有给可用性评估。

摘要译文：自然语音传达意义不仅靠词语，也靠少数词语上的重音。然而大多数 TTS 系统仍对重音不敏感，现有的重音感知 TTS 需要外部重音标注，而无监督重音检测器孤立运行、与合成脱节。这造成一个根本缺口：没有现有系统能自动发现重音应落在哪里、把它实现为自然的韵律、并提供用户对强调位置的控制——全部在一个模型内完成。为绕开这一点，我们提出 ProTTS，一个统一框架：重音检测从 TTS 模型自身中涌现，进而引导它合成更自然、可控的语音。我们在 FastSpeech2 的方差适配器中加入一个聚类头，直接从聚合的韵律特征中发现词重音；发现的重音随后驱动强调方差预测器，修改重读词的音高、能量与时长。框架端到端训练：TTS 重建损失与聚类损失共同塑造一个重音可辨的特征空间，全程不需要重音标签。推理时，同一架构也支持用户可控的强调，接受自定义重音掩码。我们在 ISLE（非母语）、LibriTTS、VCTK（母语训练）与三个评测基准（Tatoeba、TinyStress-15k、EmphAssess）上评估 ProTTS。听众更偏好 ProTTS 而非基线，MOS 为 3.96 对 3.12，偏好率 83.5%。在重音检测上，ProTTS 在 ISLE（德语/意大利语二语）上取得 0.839/0.861 F1，超过无监督（0.70）与有监督（0.82）基线，并在 Tatoeba 上零样本迁移取得 0.933 F1。

3. 零样本克隆别只保音色：三阶段后训练让 Qwen3-TTS 按文本调韵律，Emotion 18.5→81.2

2611.19787

一句话：零样本声音克隆保住了音色，却常把说话风格焊死在参考音频上，这篇把问题定义为“文本自适应韵律合成”，用 DPO 冷启动、GSPO 联合优化、OPSD 自蒸馏三阶段后训练，让 Qwen3-TTS 的 Emotion 从 18.5 提到 81.2。

贡献/机制：三阶段框架：DPO 把模型与文本适配的表现力语音对齐做冷启动；GSPO 联合优化韵律表现力、声学质量、可懂度与说话人相似度；上下文条件在策略自蒸馏（OPSD）把表现力行为从强参考条件迁移到弱参考条件，实现自我提升。作者：Jingbin Hu、Xinfa Zhu、Hao Wang 等。

数值结果：在 Qwen3-TTS 上，Emotion 从 18.5 提升到 81.2，Paralinguistics 从 38.4 提升到 73.9；大量消融验证了每个阶段的作用。

批判性分析：这个工作的立意比数字更重要——它点出了零样本克隆的一个真盲区：克隆保真度指标越高，模型越可能无视目标文本该有的情绪；Emotion 从 18.5 到 81.2 的跳变说明后训练确实能把“按文本调韵律”学出来。但要留神：摘要没有给出说话人相似度与可懂度在优化后的具体数值，表现力提升是否以牺牲保真度为代价，是这篇必须交代的账；而且 Emotion/Paralinguistics 的评分口径也没有展开，81.2 的绝对含金量得看正文。

摘要译文：零样本声音克隆通常强调保留参考说话人的音色与韵律特征。然而在真实使用中，语音应随目标文本调整表达方式，而不是固定在一种说话风格上。在本工作中，我们把这一问题形式化为面向零样本声音克隆的文本自适应韵律合成，并研究后训练如何赋予克隆模型这一能力。我们开发了一个三阶段框架。第一，直接偏好优化（DPO）通过把模型与文本适配的表现力语音对齐来冷启动。第二，组序列策略优化（GSPO）联合优化韵律表现力、声学质量、可懂度与说话人相似度。最后，上下文条件在策略自蒸馏（OPSD）通过把表现力行为从强参考条件迁移到弱参考条件来实现自我提升。在 Qwen3-TTS 上，我们的框架把 Emotion 从 18.5 提升到 81.2，把 Paralinguistics 从 38.4 提升到 73.9。大量消融验证了每个阶段的作用。

4. 说话不只是出声：DuoFlow 让语音与动作在同一时间坐标上联合生成、细粒度可控

2611.21530

一句话：现有语音-动作联合生成只靠文本语义隐式驱动，控制不了动作层级、身体部位与声音风格，DuoFlow 用双流潜在流 Transformer 在共享噪声水平与统一秒级时间坐标下联合去噪语音与动作，并给出 MotionSpeech 可控生成基准。

贡献/机制：先构建 MotionSpeech 结构化基准，包含文本、声音风格描述与两个层级上的动作条件；DuoFlow 是双流潜在流 Transformer：模态特定的残差连接器把结构化条件注入对应流，逐层双向跨模态注意力协调两路生成，单调音素路径结合归一化进度锚点与 CTC 监督强化语音时序建模。作者：Jun Dong、Ronghui Li、Zhongyuan Hu、Yunqi Zhao、Lijie Guo、Ruizhang Xu、Di Kang、Linchao Bao、Xiu Li（9 人）。

数值结果：摘要未给出量化指标，只称模型能合成高质量、同步且指令一致的语音-动作序列。

批判性分析：这篇的价值在问题定义——具身说话者的表现力确实一半在声音、一半在身体，而“动作层级、身体部位、声音风格”的显式控制接口正是现有联合生成缺的东西；双流 + 共享时间坐标的设计也合理。但证据偏薄：没有同步性、动作质量或语音质量的量化数字，MotionSpeech 基准的规模与评测口径也没有展开，所谓“高质量、同步”目前只是宣称，得看正文与样例。

摘要译文：具身说话者的表现力不仅取决于说了什么，还取决于声音听起来如何、身体如何运动。然而，现有的语音-动作联合生成模型大多由文本语义或中间语音表征隐式驱动，对动作层级、身体部位或声音风格几乎没有显式控制。为弥合这一缺口，我们构建 MotionSpeech，一个面向可控语音-动作联合生成的结构化基准，包含文本、声音风格描述与两个层级上的动作条件。基于这一基准，我们提出 DuoFlow，一个双流潜在流 Transformer，在共享噪声水平与统一的以秒为单位的时间坐标下联合去噪语音与动作。模态特定的残差连接器把结构化条件注入对应流，逐层双向跨模态注意力协调它们的生成，单调音素路径结合归一化进度锚点与 CTC 监督来强化语音时序建模。DuoFlow 提供了一个统一接口，用于细粒度的动作与声音风格控制，并展示了合成高质量、同步且指令一致的语音-动作序列的能力。

5. 有了文本，脸和声音就“听不见”了：CoVeR 用反事实视图治语言捷径，LS 准确率 61.7%

2611.20349

一句话：LLM 做多模态融合时，文本一进来就把非语言证据盖过去——给静音视频加文本能让视觉-语言准确率掉 46–53 个点，CoVeR 把各视图训练成单模态裁判、在意见不一致时暂缓融合监督，在五个基准上做到 SOTA。

9. 数据不够就别多训几遍：潜在反馈是算力与数据的放大器，最多省 48% 算力、47% 数据

2611.20404

一句话：高质量数据耗尽后多训几遍的收益递减，潜在反馈把每个 token 的顶层状态喂给下一个 token 的输入，在同等算力下比多 epoch 的 vanilla Transformer 更划算，最多节省 48% 的算力与 47% 的独特数据。

贡献/机制：在一组模型规模、独特数据量与 epoch 上，把潜在反馈与把同样算力花在更多 epoch 上的 vanilla Transformer 做对照，在每个规模与独特数据量下调优两个模型；给两个模型拟合一条缩放定律，其中潜在反馈相当于一个参数更多的 Transformer。作者：Benhao Huang、Chaitanya Dwivedi、Xuezhe Ma、Alexander Moreno、Hector Liu（5 人）。

数值结果：潜在反馈最多节省 48% 的算力与 47% 的独特数据；缩放定律在 60M 到 271M 参数的模型上拟合，对 778M 的留出规模预测损失误差在 0.3% 以内，两个模型间的差距误差在 0.05% 以内；两种节省都随每参数独特数据与重复次数增长。

批判性分析：这篇的实验设计很干净——不是只报一个点的胜负，而是拉了一条“规模 × 数据 × epoch”的网格，再用一条缩放定律把结论外推到 778M，0.3% 的预测误差也让外推显得可信；“数据耗尽时别多训、改结构”的结论对当下的数据瓶颈很应景。但要留神：验证的模型最大只有 778M，结论在 7B、70B 量级上是否还成立，摘要没有给出；而且潜在反馈的推理开销与工程实现成本也没有讨论，省下的训练算力会不会在推理端还回去，是落地前要问的。

摘要译文：当高质量数据耗尽时，常见做法是在其上训练多个 epoch，但每次重复的价值都低于上一次。潜在反馈把每个 token 的顶层状态喂给下一个 token 的输入，是另一种花费算力的方式，但它尚未与把同样算力花在更多 epoch 上的 vanilla Transformer 做过对比。我们在一组模型规模、独特数据量与 epoch 上运行这一对比，在每个规模与独特数据量下调优两个模型。潜在反馈让每个 FLOP 与每个 token 都更有价值，除非独特数据相对于模型规模稀缺——而今天的模型远未处于这一区间。我们发现潜在反馈起到放大器的作用：在独特数据固定时，它用更少算力达到 Transformer 的损失；在 epoch 固定时，它用更少独特数据达到该损失。而且两种节省都随每参数独特数据与重复次数增长，下游任务也一致。为超越我们的网格，我们给两个模型拟合一条缩放定律，其中潜在反馈相当于一个参数更多的 Transformer；它预测两种节省都随独特数据与重复次数持续增长。该定律在 60M 到 271M 参数的模型上拟合，对 778M 的留出规模预测损失误差在 0.3% 以内，两个模型间的差距误差在 0.05% 以内。潜在反馈最多节省 48% 的算力与 47% 的独特数据。当数据而非算力成为限制时，对给定规模的模型，潜在反馈是 FLOP 更好的用途。

数值结果：CrossRPO 在最高分辨率的 ViRA-Bench 上达到 63.3% 的对比集准确率，而 GRPO 为 59.3%；ViRA-9B 是同规模最准确的开源模型，ViRA-27B 在大多数基准上超过 Claude Haiku 5.5 与 GPT-6-Luna（均为最高思考水平）。

批判性分析：这个工作的聪明处在于把“读证据”从口号变成了可训练的目标——对比集的设计让猜测在整组层面上无利可图，63.3% 对 59.3% 的差距虽然不大，但方向是对的；只用约 3,500 条数据就训出效果，也说明这条路数据效率很高。但要留神：对比集准确率的绝对值仍只有 63.3%，超高分辨率视觉问答远未解决；而且 ViRA-Bench-Real 的真实改动集规模没有展开，编辑痕迹排除得是否彻底，也得看正文。

摘要译文：视觉智能体通过放大相关区域来回答超高分辨率照片的问题。然而现有智能体常常凭常识作答，而不是阅读证据。对最终答案做强化学习无法纠正这一点，因为猜对与读对得到同样的奖励。我们提出 Cross-Input Relative Policy Optimization（CrossRPO），在对比集上训练智能体。一个对比集用同一问题问同一图像的多个版本，这些版本只在一个含证据的小区域上不同、答案也不同，因此只有阅读证据才能解出整个对比集。CrossRPO 奖励解出整个对比集，并且我们证明它不会强化凭常识答对的对比集。我们通过编辑 21 到 120 兆像素图像中的一个小物体来构建训练用对比集（ViRA-Train）与评测用对比集（ViRA-Bench），并用真实改动拍摄更多对比集（ViRA-Bench-Real）以排除编辑痕迹。我们用 CrossRPO 在每种约 3,500 条 ViRA-Train 数据上训练两个视觉推理智能体 ViRA-9B 与 ViRA-27B。CrossRPO 在最高分辨率的 ViRA-Bench 上达到 63.3% 的对比集准确率，而 GRPO 为 59.3%。ViRA-9B 是同规模最准确的开源模型，ViRA-27B 在大多数基准上超过 Claude Haiku 5.5 与 GPT-6-Luna（均为最高思考水平）。

11. 编码智能体进了组织还是交不了差：SWE-CoWork，F2P 63% 但完整交付不到 8%

2611.20218

SWE-CoWork 是把编码智能体放进模拟工程组织的基准：101 个开发任务、101 个真实仓库、11 种语言、12 个应用领域，每个任务配 26 位职责、知识与协作行为各异的同事；智能体要从同事与工作记录里拼出需求、调和冲突证据，再通过私有可执行测试交付。11 个模型里最强的两家满足约 63% 的 fail-to-pass 测试，但完整交付不到 8% 的任务；事前给全需求能把 F2P 提高约 16 个点，完整成功率却纹丝不动；轨迹分析显示，Claude-Opus-5.5 把 93% 的首问问对了负责人，却只拿到 64% 的同事持有需求，31% 自报完成的需求通不过测试。作者：Xinping Lei 等。upvotes 44。

12. 长视频别只训短片段：MovieRoll 三件套把 15 秒训练推到 60 秒，缓存省 78%

2611.21339

MovieRoll 是流式长视频生成的 base-to-distilled 框架：窗口教师强制（WinTF）做多步基座、分层 KV 缓存压缩（HieraKV）在浅层保留全部历史、深层只留 sink 与近期历史，缓存内存减少至多 78% 且质量反而提升；累积长时调优加分布匹配蒸馏（CuLT-DMD）让每步更新汇聚跨时间位置的监督。在 HeliosBench 上，MovieRoll-Base 在只训 15 秒视频的情况下 30 秒仍具竞争力，蒸馏版在单事件与多事件评测中 60 秒内总分最高。作者：Yunyang Ge 等。upvotes 10。

13. 语音 tokenizer 也该把内容和音色拆开：Facto 因子化自监督 token，TTS 与声纹转换都受益

2611.18898

Facto 是因子化语音 tokenizer，把时变信息（内容与韵律）与静态成分（说话人身份与录音条件）拆开：先在线性因子化方法上扩展到未见说话人，再对因子化空间聚类、训一个轻量解码器从 token 重建音频。去掉静态成分后再聚类，token 对小噪声扰动更稳定；作者还从理论上分析了因子化的收敛与缩放性质，并量化了它随训练说话人数量的改善。在下游任务上，更高的 token 稳定性转化为更好的 TTS 表现，以及有竞争力的声音转换与口语建模结果。代码：https://github.com/ubisoft/ubisoft-laforge-facto/，演示页：https://ubisoft-laforge.github.io/speech/facto/。作者：Benjamin Van Niekerk 等（6 人）。

14. 流式多人 ASR 又要准又要快：可验证奖励 RL 把 SA-WER 从 20.51% 压到 12.70%， onset p50 快 65%

2611.19136

面向可穿戴场景的流式多人 ASR：说话人角色固定、标签必须先于轮次出现，SFT 对稀疏标签优化不足，而抢先提交标签又会拖慢后续文本。这篇用可验证奖励 RL 后训练流式 LLM-ASR：固定角色的说话人归属 WER（SA-WER）评分器加轮次级起始延迟奖励。在八方向多人队列上，SA-WER RL 把 SA-WER 从 SFT 的 20.51% 降到 13.14%；加上延迟目标后，onset p50 从 0.918 秒降到 0.320 秒（-65%）、p90 从 1.389 秒降到 0.780 秒（-44%），同时 SA-WER 做到 12.70%。作者：Jing Pan 等（5 人）。

15. 阿拉伯方言 ASR 的生产级答案：Sada-ASR，120 小时测试 WER 11.69%，赢过微软等 11 家

2611.19512

Sada-ASR 是 EchoNova 生产阿拉伯语音智能体的识别器：在 120 小时、覆盖现代标准阿拉伯语与八种方言的测试集上，对 11 家系统（微软、ElevenLabs、谷歌、OpenAI、Speechmatics、IFM、Cohere、英伟达、Audar 等）取得最低词错率与字错率：词错率 11.69%，对最强的微软 MAI-Transcribe-2 的 13.51%；按方言平均 15.52% 对 16.96%；在阿曼方言上领先 4.30 个点、埃及 3.78、沙特 2.19，叙利亚打平，只在黎巴嫩输了（24.96% 对 23.05%）。六个公开测试集上平均词错率 17.17%，低于已发表的 Falcon-ASR（20.92%）、Jais-ASR（22.85%）与 Audar-ASR-V1-Turbo（23.17%）。作者：Mahmoud Khaled 等（5 人）。

16. 音频 LLM 偷练了谁的录音：AudioTrace 做文件级成员推断，AUROC 0.60

2611.21088

公开音频被拿去训音频大语言模型，隐私与版权审计却缺少有效方法；现有成员推断攻击默认攻击者知道完整训练样本及其文本监督，而实际中录音配对的文本往往是私有的。AudioTrace 提出音频文件级成员推断：不假设知道训练任务与标注，只判断一段录音是否被用于训练。作者构建 AudioTraceBench（含 1,285 段有明确微调成员标签的录音），并提出 AudioTrace：用目标模型生成音频条件代理问题，从回答中提取成员证据、在录音级聚合。三个音频 LLM 上的评估显示，现有文本与视频成员推断方法移植到音频后接近随机猜测，而 AudioTrace 的 AUROC 达到 0.60，并在微调暴露增加或适配容量增大时进一步上升。作者：Guangzhi Sun 等（5 人）。

17. 多人多语重叠语音分离：MOUSSE，13.18 dB SI-SDRi，比最强基线高 1.58 dB

2611.19706

MOUSSE 面向多语种重叠语音分离：先构建 MuSSeD 英韩基准，含 2–4 人混合、不同重叠比；再提出流匹配框架，结合边界感知训练与逐帧预测不确定性（置换不变高斯负对数似然），预测的尺度还用于采样时自适应分类器无关引导。MOUSSE 达到 13.18 dB SI-SDRi 与 0.175 ESTOIi，超过判别式与流匹配分离基线，比最强模型高 1.58 dB SI-SDRi。作者：Su Yeon Shim 等（4 人）。
