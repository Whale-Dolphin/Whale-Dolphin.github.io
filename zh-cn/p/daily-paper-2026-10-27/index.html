精评

1. 全双工语音模型为什么长聊必崩：滑窗丢掉第一个 KV 锚点，模型再被自己的复读带偏

2610.32349

一句话：全双工模型边听边说、每帧都要生成 token，几分钟就耗尽上下文，而现有基准只测单轮或几轮，测不出长程失效；这篇提出 FD-LHB 基准，在长回放对话与与 LLM 伙伴的实时对话两种设定下测了五个近期全双工模型——无一例外，最终要么退化要么耗尽上下文；保全历史的模型在上下文用完之前就先退化，滑窗模型则陷入复读、沉默与胡言乱语，并定位到两个机制：胡言与沉默源于滑窗丢弃首个 KV 条目的"初始化锚点驱逐"，复读则被模型自己近期的输出强化；据此给出的两个免训练修复（锚点钉住 IAP + 双工复读惩罚 DRP）在长达一小时的回放里显著减少崩溃且保持实时。

贡献/机制：贡献分三层：基准层，FD-LHB 第一次把评测时长拉到"数十分钟"量级，并用回放与实时双设定排除单一协议偏差；诊断层，把滑窗模型的崩溃拆成两个可分别验证的机制——锚点驱逐解释胡言/沉默，自输出强化解释复读，而不是笼统归因于"长上下文不行"；修复层，IAP 只保留一个 KV 条目、DRP 只改解码惩罚，两者都不重训练，修复有效本身即是对诊断的因果验证。作者：Yeonju Kim、Bella Godiva、Se Jin Park、Yong Man Ro。摘要未提供代码链接。

数值结果：受测五个全双工模型全部最终退化或耗尽上下文；IAP+DRP 在长达一小时的回放中显著减少对话崩溃并保持实时运行。摘要未给各模型的崩溃时点、退化率等逐模型数字，量级细节需查正文。

批判性分析：对做实时语音对话的人，这篇把"长聊稳定性"从体感问题变成了有基准、有机制、有免训练补丁的工程问题：上下文预算要按帧率而非轮次算，滑窗策略必须显式保护锚点。保留意见：修复只在回放协议与作者的实时设定下验证，“显著减少"没有给出量化幅度，DRP 这类复读惩罚在需要 legit 重复的场景（确认、复述、列表）会不会误伤，摘要未测；五个模型的名单与各自失效模式的对照表也在正文里，引用时不要把"全部崩溃"外推到未受测的架构（如带外部记忆的全双工系统）。

摘要译文：全双工语音模型同时聆听和说话，因此有望实现自然、开放式的对话。但它们能维持数十分钟连贯的对话吗？由于它们即使在聆听时也每帧生成一个词元，几分钟内就会耗尽上下文窗口。然而现有基准只评估单轮或少数几轮对话，太短，暴露不了长程问题。我们提出全双工长程基准（FD-LHB），在长回放对话以及与一个 LLM 伙伴的实时对话中测试五个近期的全双工模型。每个受测模型最终要么退化，要么耗尽上下文。保留完整历史的模型往往在上下文耗尽之前就退化，而滑窗模型仍会陷入重复、沉默和胡言乱语。对于滑窗模型，我们找出两个促成机制。胡言乱语和沉默与初始化锚点驱逐有关，即滑窗丢弃了第一个 KV 条目。重复还会被模型自己近期的输出强化。受这一诊断启发，我们应用两个简单的修复：初始化锚点钉住（IAP）保留那个首条目，双工重复惩罚（DRP）抑制回声同时防止长时间沉默。两者共同支持了这一诊断，并且无需重训练，就在长达一小时的回放中显著减少了对话崩溃，同时保持实时运行。

2. Spark-Audio 1.0：0.65B 音频编码器 + 30B-A3B MoE，国产芯片上用 1300 万小时音频训出的语音基础模型

2610.31292

一句话：Spark-Audio 1.0 是在国产算力基础设施上训练的语音基础模型：0.65B 稠密音频编码器（BEST-RQ 表征增强预训练 + 多任务监督精调）耦合 30B-A3B MoE 语言模型，经分阶段预训练与 SFT + 在线蒸馏的后训练，共用 1300 万小时音频加大规模文本训练；支持 99 种语言、202 种方言的识别、翻译、音频理解与语音对话；作者称其音频训练数据显著少于 Qwen3.5-Omni-Flash，却在多数音文任务上与之相当，并在多语种识别、语音对话与真实应用场景上超过对方，接近更大的闭源模型。

贡献/机制：这篇的本体是技术报告而非单点方法：架构账（小编码器 + 稀疏大模型）、数据账（1300 万小时音频的量级与构成口径）、训练账（编码器两段式、音文模型分阶段预训练、后训练用在线蒸馏而非单纯 SFT）与国产硬件账（华为昇腾 910B 与海光 BW1000 上完成训练，证明国产路径可行）四笔账一次交齐。对国内语音团队，它的参照价值在于"同等任务面需要多少数据与算力"的量级锚点。作者：Chenyue Zhang、Cong Liu、Dingshu Tian、Dong Sun、Genshun Wan、Guanming Meng、Guolong Zhong、Hang Chen、Hankun Yang、Haoming Wang 等 66 位作者。摘要未提供代码链接。

数值结果：模型规模 0.65B 编码器 + 30B-A3B MoE；训练音频总量 1300 万小时；覆盖 99 种语言、202 种方言。与 Qwen3.5-Omni-Flash 的对比为定性口径（多数任务相当、多语识别/语音对话/真实场景占优），摘要未给逐基准分数，引用具体数字需查正文表格。

批判性分析：读法上按技术报告读：最有信息量的不是"超过 Qwen"这类定性结论，而是数据量级与硬件路径——1300 万小时这个数给国内同行提供了可对照的 scale 锚点，国产双硬件栈跑通则把"能不能训"的问题关掉了。需要打折的地方也明确：评测含大量自建真实场景测试集，口径自定、外部不可复现；作者自己承认指令遵循与复杂音频推理仍有差距，这恰是 Omni 类模型当前的主战场；与闭源模型的"接近"没有给差距数字。结论引用建议只引规模、数据量与硬件事实，不引未给数字的优劣判断。

摘要译文：本文介绍 Spark-Audio 1.0，一个在国产算力基础设施上训练的语音基础模型。该模型接受文本和语音输入并生成文本输出。它支持多语种（99 种语言）和多方言（202 种方言）语音识别、语音翻译、音频感知与理解，以及基于文本和语音的对话，标志着从仅仅"听得清"到真正"理解"语音的转变。在架构上，Spark-Audio 1.0 将一个 0.65B 参数的稠密音频编码器与一个 30B-A3B 混合专家（MoE）大语言模型耦合。音频编码器先用表征增强的 BEST-RQ 预训练，然后通过多任务监督训练精调。音频-语言模型经过分阶段预训练，随后是结合监督微调与在线蒸馏的后训练。该模型总共在 1300 万小时的音频数据以及大规模文本数据上训练。我们在主流音频和文本基准以及取自真实应用场景的内部测试集上评估了 Spark-Audio 1.0。尽管使用的音频训练数据显著少于 Qwen3.5-Omni-Flash，Spark-Audio 1.0 在大多数音频和文本任务上取得了相当的性能，在多语种语音识别、语音对话和真实应用场景中超过了它，并接近更大的闭源模型的性能。尽管如此，在指令遵循和复杂音频推理方面仍有改进空间。最后，Spark-Audio 1.0 在包括华为昇腾 910B 和海光 BW1000 芯片在内的国产硬件上的成功训练，证明了构建语音基础模型的一条国产技术路径的可行性。

3. 纯文本 LLM 纠错器在"修"ASR：它先把 13–32% 本来正确的转写改坏，给它听音频才降到 1–3%

2610.30385

一句话：LLM 给 ASR 输出纠错只看总 WER，掩盖了修了多少、又改坏了多少；这篇把每一次 WER 变化精确分解为修复词元、损伤词元与插入三部分，在三个语料上对比有无音频、纠正自家草稿与独立识别器输出四种组合：用 Gemini 2.5 Flash 时，纯文本纠正自家草稿会改坏 13–32% 本来正确的转写，给它加上音频后只坏 1–3%；损伤在两种设定下都下降，修复则对自家草稿下降、对独立识别器上升；在医疗听写上，被保留的插入抵消了净 WER 收益。

贡献/机制：方法本体是分解口径：总 WER 是净值，修复与损伤同向变动时会被互相抵消，“纠错有效"的结论可能建立在大量改坏正确句子的代价上。分解之后，“音频到底给纠错器加了什么"这个问题才可测：答案是音频主要压制损伤（别乱改），而不是提升修复。作者同时诚实标注混淆项：两个实验臂的提示词不同，因此对比给出的是音频效应的界而非干净隔离。很少编辑的开源权重模型 Voxtral 不呈现这一模式，说明损伤与纠错器的"手欠"程度相关。作者：Vasiliy Kudryavtsev、Kirill Borodin、Nikita Vasiliev、Mikhail Gorodnichev、Grach Mkrtchian（与昨日精评 Verifier’s Floor 为同一团队）。摘要未提供代码链接。

数值结果：纯文本纠正自家草稿的损伤率 13–32%（按已正确转写计），带音频降至 1–3%；医疗听写上保留插入抵消净 WER 收益。摘要未给三个语料的逐项修复率与净 WER。

批判性分析：这篇对所有在 ASR 后面挂 LLM 纠错的管线都是直接警告：上线前必须单独测损伤率，总 WER 不降甚至微升都可能是赚的，净 WER 涨了也可能伴随不可接受的正确句子被改坏——在医疗这类场景，改坏一句正确听写的风险权重远高于修好一句错的。与昨天的 Verifier’s Floor 合看，这组作者在系统性地拆语音管线里"默认可信"的后处理环节。保留意见：提示词混淆作者已自陈，1–3% 这个数应读作"带音频的整套方案"的损伤率而非音频的纯效应；证据主要来自 Gemini 2.5 Flash 一个闭源模型，纠错器激进程度不同结论幅度会变，Voxtral 的反例正说明这一点。

摘要译文：ASR 输出的 LLM 纠错器以总 WER 评判，这掩盖了它们修复了什么、又破坏了什么。我们把每一次 WER 变化精确地分解为被修复的词元、被破坏的词元和插入，并用它来追问源音频给纠错器带来了什么。我们在三个语料上，对比了带音频与不带音频的纠正，对象既包括模型自己的草稿，也包括一个独立识别器的输出。使用 Gemini 2.5 Flash 时，对其自身草稿的纯文本纠正会破坏 13–32% 本已正确的转写；带上音频后，这一比例为 1–3%。损伤在两种设定下都会下降。修复对自身草稿下降、对识别器输出则上升。在医疗听写中，被保留的插入抵消了净 WER 的收益。很少做编辑的开源权重模型 Voxtral 没有表现出这种模式。两个实验臂之间的提示词不同，因此这些对比限定了音频的效应范围，并没有将其干净地隔离出来。

4. 说话人激活后门：只要 2 分钟目标人的声音，他的嗓子就是触发器，转写层看不见、Agent 层中招 87.5%

2610.27210

一句话：已有的音频后门需要攻击者在推理时塞入触发信号，这篇研究的威胁模型更阴：攻击者只在微调阶段下毒、推理时完全不接触受害者输入，触发器就是目标说话人本人的自然嗓音；两阶段微调（先让说话人身份更可及、再把目标说话人绑定到载荷）在 Whisper-medium 与 Parakeet 上达到 90.2% 与 97.0% 的后门成功率，误报率仅 1.7% 与 0%，最少只需 2 分钟目标人真实音频；更进一步，内容相关的语义改写可把恶意指令插入 96.9% 的目标人转写，这些转写喂给前沿 LLM Agent 后，GPT-4o 与 Claude（Opus、Sonnet、Haiku）执行有害动作的比例最高达 87.5%。

贡献/机制：关键设计是把触发器从"外加信号"换成"身份本身”：推理侧没有任何异常输入可供检测，转写文本层也看不出异常（载荷以语义改写形式混入正常转写）。两阶段配方里第一阶段"放大身份可及性"是选择性与干净性能同时成立的前提，单阶段基线在相同预算下明显更差，内容相关攻击尤其依赖它。攻击面还跨过了模态边界：语音模型只是入口，真正的载荷在下游文本 Agent 处引爆。作者：Nataša Krčo、Euodia Dodd、Peter Romov、Yves-Alexandre de Montjoye。摘要未提供代码链接。

数值结果：后门成功率 Whisper-medium 90.2%、Parakeet 97.0%，误报率 1.7% 与 0%；最少 2 分钟目标人音频；恶意指令插入率 96.9%（目标人转写）；下游 Agent 执行有害动作比例最高 87.5%；对未见录音、多目标说话人与常见声学退化均可泛化。

批判性分析：这篇对语音 Agent 供应链的含义很直接：微调数据的投毒面不止是"错标签”，说话人身份本身可以成为寻址通道；防御侧靠输入检测与转写审查都抓不住，因为异常既不在输入里、也不以异常文本形式出现，能防的位置只剩微调数据溯源与"高权限工具调用前对指令来源做独立核验”。保留意见：威胁模型假设攻击者能参与微调（数据投毒或直接提供微调服务），这在外包微调与第三方数据集场景成立、在全自研管线里门槛更高；87.5% 是"最高达"的口径，不同 Agent 与动作类型的分布未在摘要展开。尽管如此，仅 2 分钟音频的触发成本低得值得所有语音入口团队认真对待。

摘要译文：语音模型越来越多地被用作 AI 系统的接口，从转写工具到语音 Agent。现有的音频后门要求攻击者在推理时引入触发器。我们研究一种不同的威胁模型，其中攻击者在微调期间攻陷模型，但无法访问受害者在推理时的输入。我们引入说话人激活后门（SAB）设定，其中目标说话人的自然嗓音充当触发器。我们开发了一种两阶段微调方法，先使说话人身份更易被利用，然后将目标说话人与攻击者选择的载荷绑定。与相同训练预算下的一阶段基线相比，两阶段方法显著提高了选择性和干净性能，并且对内容相关的攻击尤其重要。SAB 在 Whisper-medium 和 Parakeet 上分别达到了 90.2% 和 97.0% 的后门成功率，误报率分别为 1.7% 和 0%，最少只需目标说话人两分钟的真实音频。我们进一步展示了内容相关的语义改写和下游工具使用攻击，其中恶意指令被插入到 96.9% 的目标说话人转写中。当这些转写被传递给前沿 LLM Agent 时，GPT-4o 和 Claude（Opus、Sonnet 和 Haiku）中注入的指令驱使 Agent 执行有害动作的比例最高达 87.5%。该攻击可泛化到未见过的录音、多个目标说话人以及常见的声学退化。这些结果确立了说话人身份作为一种实用的后门触发器，它不需要攻击者在推理时进行任何访问，并且在转写层不可见。

5. SURE-Tagger：把语音标成结构化标签再选数，1 小时微调让 Qwen3-ASR 错误相对降 14.3%，字幕引导选数反而变差

2610.32198

一句话：语音同时携带内容、说话人、时序互动、副语言线索与声学环境，现有语音字幕模型对这些维度的覆盖不一致、省略含糊，没法跨数据集系统分析；SURE-Tagger 用"专家观察 + 语言模型推理"构建带显式属性值、补充描述与"证据不足时弃权"的半结构化语音表征，并在 Tag-Bench（真实录音 + Agent 合成的受控语音场景）上 29 个维度中真实语音 25 项、合成语音 24 项取得最高分；更实用的结果在选数侧：用这些表征从独立候选池里挑数据，1 小时微调预算下把 Qwen3-ASR-1.7B 的整体错误率相对未适配模型降低 14.3%，而字幕引导与随机选数在同一设定下反而让错误上升。

贡献/机制：这篇把"表征"同时当评测工具与选数工具用：结构化标签让"某个条件下 ASR 为什么错"可以被组合查询（跨数据集按条件切子集），同一套标签又直接驱动定向选数，形成标注→诊断→改进的闭环。弃权机制是小而关键的设计：证据不足时明确不标，避免把猜测写进表征污染下游。选数对照的设计也干净——同预算、同候选池，只换引导信号，字幕引导变差说明"描述流畅"不等于"对选数有用"。作者：Jing Peng、Huifei Wang、Weihan Chen、Shuo Gao、Bicheng Zhang、Junhao Du、Hanqi Li、Chaolei Liu、Wen Wen、Tao Liu、Xu Li、Yu Xi、Shuai Wang、Kai Yu。摘要未提供代码链接。

数值结果：Tag-Bench 29 个维度中最高分：真实语音 25 项、合成语音 24 项；选数微调（1 小时预算）使 Qwen3-ASR-1.7B 整体 ASR 错误率相对降低 14.3%，字幕引导与随机选数则使错误上升（摘要未给上升幅度）。

批判性分析：对做 ASR 数据工程的人，这篇最值钱的是选数对照：同样 1 小时预算，选数信号的质量决定了微调是赚是亏，而且"更丰富的自然语言描述"这个直觉选项实测为负——结构化、可查询、带弃权的表征胜在可审计，不是胜在信息量。保留意见：14.3% 只在一个模型（Qwen3-ASR-1.7B）与一个候选池上验证，标签体系本身由专家模型加 LLM 推理构建，其构建成本与标签噪声没有在摘要里给账；Tag-Bench 的合成部分由 Agent 生成，分布与真实长尾条件的差距会影响"24/29"这个数的含金量。引用时建议引选数对照的方向性结论，不把 14.3% 外推到其他模型规模。

摘要译文：语音传达语言内容、说话人特征、时间互动、副语言线索和声学环境。尽管近期的语音字幕模型用自然语言描述这些维度，但属性覆盖不一致和含糊的省略阻碍了跨录音的系统分析。我们引入 SURE-Tagger，一个构建半结构化语音表征的框架，带有显式属性值、补充描述，以及在证据不足时的弃权机制。通过经由语言模型推理整合专家观察，SURE-Tagger 使语音条件能够被一致地识别，并在数据集之间联合查询。我们进一步引入 Tag-Bench，它将真实录音与受控的、由智能体合成的语音场景以及经过验证的属性标注相结合。在 Tag-Bench 上，SURE-Tagger 在 29 个评估维度中，真实语音有 25 个、合成语音有 24 个取得了最高分，超过了基于字幕的基线在结构和描述属性上的表现。除了标注之外，我们用这些表征构建跨数据集的评估子集，并揭示了特定条件下的 ASR 错误。使用一个独立的候选池，SURE-Tagger 引导的选择在一小时微调预算下，将 Qwen3-ASR-1.7B 的整体 ASR 错误率相对于未适配模型降低了 14.3%，而字幕引导和随机选择在相同设定下增加了错误。这些结果展示了结构化语音表征如何连接丰富的标注、组合式评估和有针对性的模型改进。

6. DRAMA-Eval：多轮、多说话人的语音生成没人统一测过，这个基准把三类系统拉到同一张考卷上

2610.31796

一句话：语音生成正在从单句零样本 TTS 转向上下文感知、多轮、多说话人合成（有声书、广播剧正是这类需求），但评测没跟上：指令可控生成、多轮对话模型、音视频生成的音频分支三类系统一直各测各的；DRAMA-Eval 用结构化脚本上下文搭了统一框架，从客观、局部、全局三层评估声学保真、句级执行与长程连贯，并发布 12 小时中英双语、人工校正的真实脚本测试集（附参考音频、评测代码与基准结果）；评测领先开源与商业模型后，暴露出的关键短板是长程说话人一致性与需要深层上下文理解的隐含指令遵循。

贡献/机制：统一性是这篇的核心贡献：三类此前不可比的系统被放进同一脚本上下文与同一 LLM-as-a-Judge 可行的评测协议里，“多轮里换人了没有、隐含指令听懂了没有"这类问题第一次有了跨范式的对照。测试集的构建口径也扎实：真实世界脚本、人工校正、双语、带真值音频，12 小时的量级足够支撑分项统计。短板定位与精评 1 的全双工长程崩溃互为印证：生成侧与对话侧在"长程一致性"上同时不及格，这不是某个模型的毛病而是当前范式的共同上限。作者：Jingbin Hu、Zihang Yang、Xiaoge Peng、Haoyu Zhang、Ziyu Zhang、Qirui Zhan、Huakang Chen、Zhao Guo、Wenjie Tian、Kangxiang Xia、Wenkang Hou、Ruonan You、Zihan Liu、Chenyi Liao、Hongyu Lyu、Zihao Bai、Jinrui Liang、Shengming Lin、Yunxiang Chen、Houdun Liu、Su Feng、Bengu Wu、Liumeng Xue、Lei Xie。代码与数据：见论文发布页（摘要称已发布测试集、评测代码与基准结果）。

数值结果：测试集 12 小时、中英双语；评测覆盖领先开源与商业模型。摘要未给各模型的分项分数与排名，长程说话人一致性与隐含指令遵循的短板为定性结论，量化差距需查基准结果表。

批判性分析：对做音频剧、多人对话合成的人，这篇提供了第一张能横向比系统的考卷，选型与迭代都应该先过它。保留意见集中在评测方法本身：复杂场景评测依赖 LLM-as-a-Judge，裁判对"连贯"“指令遵循"这类主观维度的稳定性与人类判断的一致性，摘要没有给出对照数字；12 小时脚本以真实剧本为主，题材与语言分布（中英之外的语种、方言、自发对话）覆盖有限。另需注意：短板结论是跨模型的定性归纳，具体到单个系统选型仍要看分项表，不能只引结论句。

摘要译文：语音生成的近期进展正在转向上下文感知、多轮和多说话人的合成。尽管这些能力对于有声书和广播剧制作等应用需求很高，但评估并未跟上这些进展。除了传统的零样本文本转语音（TTS）之外，该领域的现代系统主要分为三类：指令可控的生成模型、多轮对话模型，以及音视频生成模型的音频分支。然而，现有的基准孤立地评估这些范式，未能对上下文建模、指令遵循和多说话人生成提供统一的评估。与此同时，音频理解模型的近期进展使得使用 LLM-as-a-Judge 方法评估此类复杂场景成为可能。为了弥合这一差距，我们引入 DRAMA-Eval，一个用于评估此类系统的综合基准。DRAMA-Eval 利用结构化的脚本上下文，提供了一个涵盖生成质量的目标、局部和全局方面的整体评估框架，能够评估声学保真度、句级执行和长程连贯性。我们在一个人工验证的数据集上对领先的开源和商业模型进行了基准测试。结果揭示了在长程说话人一致性和隐含指令遵循方面需要深层上下文理解的关键弱点。为了促进可重复的研究，我们发布了一个 12 小时的双语（中文-英文）测试集，包含人工校正的真实世界脚本，并附有真值音频、评估代码和基准结果。

简报

1. MQAScore：文生音乐对齐别再只看一个全局相似度，让音频大模型逐个概念回答"有没有”

2610.31083

文本-音乐对齐通常用文本与音频嵌入的全局相似度评测，所有属性被压成一个分数、缺了哪样看不出来。MQAScore 改为沿流派、乐器、情绪/主题、人声、用途五个片段级维度逐个核查原子音乐概念，用大音频语言模型对二元问题回答"是"的概率打分；作者还构建了由存在/缺席标注与 LLM 引导概念替换得到的验证标签，并提出灵敏度-不变性比（SIR）衡量评测器对"改变含义的替换"选择性响应的程度。实验显示概念级打分同时改进了问答式与相似度式评测器。对做音乐生成评测的人，这提供了比 CLAP 类全局分数更可解释的细粒度补充。

2. 音色藏在哪：1–8 kHz 幅度与声道谱包络主导感知，8 kHz 以上机器仍可辨，浅层 SSL 泄漏最集中

2610.29150

音色相似度是声音转换、说话人克隆 TTS 与零样本语音生成的关键评测目标，生成声音不像目标人往往源于音色与内容分离不干净。这篇以说话人身份为可测代理，系统探测了频带、相位/幅度结构、WORLD 源-滤波器分解、有声/无声区域、SSL 层、EnCodec/HuBERT 词元，并做了 45 名听者的感知测试，覆盖普通话、英语、日语的说话与歌唱数据。结论：说话人信息是分布式存放的——1–8 kHz 幅度与声道谱包络结构主导人类感知，8 kHz 以上频带人类不敏感但机器仍可区分，浅层 SSL 层暴露紧凑的说话人信息，词元层面的泄漏取决于 tokenizer 与层选择。对生成系统该在哪条件化音色、codec 与 token 管线该在哪审计残留泄漏，这篇给了具体的下手位置。

3. SLM-SS：把语音分离改写成 token 生成，Libri2Mix 上 WER 6.92% 逼近 codec 重构上限

2610.27785

现有语音分离系统多以信号级目标优化，波形指标好看但对可懂度敏感的下游任务并不最优。SLM-SS 先用神经 codec 把干净语音离散为多码本词元序列，用序列化输出训练（SOT）排列多说话人目标，再由编码器-解码器自回归语音语言模型预测零阶序列定说话人顺序与粗内容，非自回归模块精修高阶残差码本；其按说话人的 NAR 策略进一步简化高阶建模。在 Libri2Mix 上，按说话人 NAR 版本取得 6.92% WER，接近仅 codec 重构的水平；WavTokenizer 变体免去 NAR 精修，在受测分离系统中主观质量分最高，其 UTMOS 与 DNSMOS 优势在未微调的未见噪声与中文混合上依然保持。对生成式分离路线，这是一个"指标与听感同时成立"的样本。

4. Uni-Stream：一个流式模型同时做 ASR 与 TTS 逼近专用模型，但语音与文本在潜空间里仍各住各的

2610.32187

统一流式语音语言模型要在一个模型里同时支持识别与合成、还要保住各自的任务性能，并不容易。Uni-Stream 建立在紧凑的预训练语音模型之上，以流式格式处理交错的文本与语音，经两阶段训练达到与任务专用模型相当的表现；作者还开发了流式训练的数据标注管线，并将公开释放生成的转写与词级时间戳。更有意思的是表征分析：即使在统一架构里联合训练，语音与文本仍驻留在明显不同的潜在特征空间，而同一模态内的表征在深层变得更依赖任务。对做统一语音模型的人，这个"统一的是架构、不是表征空间"的发现值得在设计表征对齐时先验一下。

5. 长音频时间定位：FiLM 把查询语义注入连续时间网络，骨干冻结、只训轻量模块就有稳定增益

2610.31252

长篇录音里目标事件往往只占一小段，查询还常带多个语义约束，时间定位（TAG）的搜索空间因此很大。这篇提出查询条件化的 liquid 时间定位框架：先用 FiLM 把查询语义注入，再用闭式连续时间（CfC）网络建模长程时间依赖；系统生成多个查询相关的候选，最后由冻结的大音频语言模型选出最兼容的一个做轻量局部边界精修。预训练骨干全程冻结，只优化轻量定位模块。在 LAT-Bench 的英语 TAG 子集上，该框架在 MOSS-Audio 与 Qwen3-Omni 两个骨干上均取得一致改进，消融确认 FiLM 与 CfC 互补。对长音频方向，这是一条"不重训大模型、靠结构与选择"的低成本路线；摘要未给具体数值，增益幅度需查正文。

6. On-Policy Self-Training：只给几个高层主题词，模型自造题、自造特权推理再自蒸馏，无人工数据也能涨（upvotes 12）

2610.32770

在线策略自蒸馏能不用更强的外部教师做后训练，但已有方法仍依赖真值问答对或人工题集。这篇把监督推到极限：只给粗粒度的高层主题描述，模型自行合成一整套课程——查询与特权推理轨迹都自产，不接触任何人工提示或答案，然后在这些完全合成的特权信息上做自蒸馏。结果是模型在多个领域上自我提升，同时在未自训练的领域保持能力；框架在文本与多模态（VQA）上都成立。对做后训练的人，这把"自举"的边界又往外推了一步：值得追的是它对合成课程质量的依赖与何时饱和，摘要未给逐基准数字，需查正文。

7. 视频世界模型综述：用读、写、共享、交互四种操作，把视频基础模型与世界模型装进同一面镜子（upvotes 213）

本期 HF 热度最高的论文（upvotes 213）是一篇综述：它把观测到的视频看作潜在时间世界的部分、有损、时序有序的投影，用四种互补操作组织整个文献——读（从视频推断世界属性）、写（按指定或学到的世界条件合成视频）、共享（以共同建模机制整合理解与生成）、交互（在动作与演化观测下预测并更新世界状态）。这一视角把"序列层面的时间连贯"与"底层世界状态的一致"明确分开，并指出领域重心正从片段级识别与感知保真转向持久状态、可控演化、物理与因果有效性，以及以交互和下游决策为落点的评测。配套资源：https://github.com/vid-gen/awesome-video-world-model 。按地图读，不按结论读。
