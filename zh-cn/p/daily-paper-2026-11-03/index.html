精评

1. 长音频别硬塞整段：先检索再推理——AudioHelix 用层次双图把跨段声学与文本证据连起来

2610.41390

一句话：大音频语言模型处理长录音时，整段输入既贵又抓不住分散在远处片段里的查询相关证据；AudioHelix 用层次双图 RAG 把文本证据与声学证据跨时间连起来做多跳推理，在三项基准上一致优于整段处理与现有 RAG 方法。

贡献/机制：与纯文本 RAG 或无图 RAG 的区别在“双图”：同一框架里同时组织文本线索与声学线索，并跨越时间上相距很远的片段建立关联，服务的是需要多步取证的长音频推理，而非单片段问答。作者：Eunsang Lee、Taein Ju、Jiyoung Lee。代码已开源（见原文）。

数值结果：摘要只给定性结论——在 TraceAV-Bench、MMAU-Pro 与 AudioMarathon 三项基准上一致优于整段处理与现有 RAG 方法；具体提升幅度、检索延迟与上下文节省量未在摘要中给出，需查正文。

批判性分析：方向踩在用户关心的长音频痛点上：小时级录音的问答不能靠“窗口越大越好”，取证结构本身就是能力的一部分。但摘要没给数字，无法判断这是小幅稳赢还是质变；图构建的成本（离线索引耗时、在线检索延迟）也没交代——如果建图比省下的推理还贵，落地账就算不过来。另外三项基准是否覆盖真实长音频场景（会议、播客、长访谈）要看正文的任务构成。宜读作方法框架，等正文数字与开源复现。

摘要译文：大音频语言模型（LALM）在长音频推理上举步维艰，因为处理整段录音往往难以捕捉分布在远处片段中的查询相关内容，同时带来可观的计算成本。我们提出 AudioHelix，一个面向 LALM 检索增强生成（RAG）系统的层次双图框架。与现有的纯文本或无图 RAG 方法不同，AudioHelix 把跨时间远距离片段的相关文本证据与声学证据连接起来，以支持多跳推理。在 TraceAV-Bench、MMAU-Pro 与 AudioMarathon 上的大量实验表明，AudioHelix 一致优于整段音频处理与现有 RAG 方法。

2. ASR 的评测假设过期了：Speech-LLM 不再只“转录”，而是生成有语音依据的文本——GSR 与 GSR-Bench

2610.41292

一句话：语音语言模型已把 ASR 从转录扩展为通用语音到文本生成，但现有基准仍假设每句话只有一个标准转录，读不懂格式化、结构化的合理输出；GSR 把识别重定义为生成有语音依据的文本，并给出四级能力层次与首个综合基准 GSR-Bench。

贡献/机制：核心是“ grounded reformulation space”：刻画输入语音所支撑的全部合法文本实现，并据此划分四级能力——字面转录、规范改写、语义改写、语音依据的结构化。评测上放弃纯词级指标，改用语音依据评估 + LLM 语义判断的多维框架，并经人类偏好研究验证可靠性；场景覆盖精修会议转录、跨方言翻译、上下文感知理解与静音/噪声鲁棒性。作者：Qing Wang、Qihan Hu、Hang Lv 等（12 人）。

数值结果：摘要未给出具体分数——实验覆盖传统 ASR 系统到端到端 Speech-LLM，揭示转录保真度与生成改写能力之间的根本权衡，并定位三类失败模式：声学幻觉、无依据生成与指令漂移；基准规模与评测者一致性数字需查正文。

批判性分析：这篇的价值在“先修评测，再谈模型”：只要基准还按词级精确匹配打分，Speech-LLM 的改写能力就永远显得像错误，反过来也会纵容无依据的流畅幻觉。四级层次是否真正互斥、可操作，是这套框架能否被社区采纳的关键；LLM-as-judge 本身的可靠性与成本（尤其跨方言场景）也需要正文的证据。对做语音助手的人，失败模式清单比基准本身更值得先读——声学幻觉与指令漂移正是语音 Agent 落地时最难查的账。

摘要译文：语音语言模型已把自动语音识别（ASR）从转录扩展为通用语音到文本生成。然而现有基准仍假设每条语音只有一个标准转录，这一假设在模型产出可读、格式化或结构化输出时难以成立。在本工作中，我们提出有依据的生成式语音识别（GSR），把语音识别重构为生成有语义依据的文本，而非单一转录。我们定义了一个有依据的改写空间，刻画输入语音所支撑的全部合法文本实现，并建立了一个四级改写能力层次，包括字面转录、规范改写、语义改写与语音依据的结构化。基于这一表述，我们推出 GSR-Bench，这是首个面向超越精确转录匹配的生成式语音识别系统评估的综合基准。GSR-Bench 覆盖多样场景，包括精修会议转录、跨方言翻译、上下文感知语音理解，以及静音或噪声声学条件下的鲁棒性。针对词级评测指标的局限，我们开发了一个结合语音依据评估与基于 LLM 的语义判断的多维评测框架，其可靠性经人类偏好研究验证。对从传统 ASR 系统到端到端 Speech-LLM 的代表性架构的大量实验，揭示了转录保真度与生成改写能力之间的根本权衡。我们的分析进一步识别出关键失败模式，包括声学幻觉、无依据生成与指令漂移，为未来有依据的生成式语音系统的设计与评估提供启示。

3. 开源语音助手的新模板：Apriel Voice 27B 把语音、推理与工具调用压进同一个 Gemma 骨干

2610.40738

一句话：能用的语音助手不止要听懂词，还要理解请求、基于上下文推理、持续对话并通过工具行动；Apriel Voice 27B Preview 在后训练的 Gemma 4 26B-A4B 骨干上直接处理语音、同时生成回复与工具调用，不再另挂对话模型，思考模式下 Big Bench Audio 98.90、Speech-BFCL 81.13、τ-Voice 任务成功率 65.51%、平均延迟 1.91 秒。

贡献/机制：两阶段训练：第一阶段建立语音接口，第二阶段联合适配投影器与骨干，用监督微调、文本回放、以及随数据源变化的交叉熵与前向 KL 散度监督；对话数据来自自动构建的语音条件对话；在线蒸馏侧用本地教师服务、师生计算重叠与融合全词表损失来提效，并保留文本与图像输入模态。作者：Aman Tiwari 等（31 人）。摘要未提供代码链接。

数值结果：思考模式下 Big Bench Audio 98.90、Speech-BFCL 81.13、τ-Voice 任务成功率 65.51%、平均延迟 1.91 秒；英语 EVA 准确率 51.27%、experience pass@1 74.13%。

批判性分析：这是本期最值得语音 Agent 团队对照的一篇：它把“语音助手”从 ASR + LLM 的拼接，收敛成“一个骨干 + 语音接口 + 工具调用”的形态，与 GSR 的“识别即生成”在同一条线上。但三点要打问号：一是 1.91 秒延迟的测试条件（硬件、并发、是否含工具执行）摘要没说；二是 EVA 英语准确率 51.27% 并不算高，说明语音条件下的评估能力仍是短板；三是“Preview”与“开放”的实际开放程度（权重、数据、评测细节）要以发布页为准，别按完整开源来规划。

摘要译文：一个能干的语音助手必须不止识别词语；它必须理解请求、基于上下文推理、维持对话并通过工具行动。我们推出 Apriel Voice 27B Preview，一个开放的语音语言模型，在共享的推理骨干内统一这些能力，同时保留文本与图像输入模态。基于后训练的 Gemma 4 26B-A4B 检查点，Apriel Voice 直接处理语音并生成回复与工具调用，无需单独的对话模型。我们引入两阶段训练流程来适配语音：第一阶段建立语音接口，第二阶段通过监督微调、文本回放、以及随数据源变化的交叉熵与前向 KL 散度监督，联合适配投影器与骨干。自动构建的语音条件对话提供会话训练数据，而本地教师服务、师生计算重叠与融合全词表损失则实现高效的在线蒸馏。在思考模式下，Apriel Voice 在 Big Bench Audio 上得 98.90，在 Speech-BFCL 上得 81.13，在 τ-Voice 上任务成功率 65.51%，平均延迟 1.91 秒。它还达到 51.27% 的英语 EVA 准确率与 74.13% 的 experience pass@1。最后，我们把 Apriel Voice 27B Preview 部署在定制服务平台上，以支持交互式语音交互。

4. 音频生成也该摆脱二次复杂度：MFlowAudio 用 Mamba 双扫描做流匹配，长音频流式延迟恒定 1.8 秒

2610.41852

一句话：Transformer 扩散音频模型受自注意力二次复杂度拖累，长音频合成先贵起来；MFlowAudio 把流匹配与定制的 TCMamba 骨干结合，生成加速 14.5% 以上，同时以恒定 1.8 秒延迟实现感知无缝的流式合成， fidelity 与现有最强基线相当。

贡献/机制：TCMamba 的双扫描分工明确：TimeMamba 以线性复杂度捕捉长程因果依赖，ChannelMamba 建模谐波结构这类跨通道相关；其上的状态化流匹配（SFM）天然支持分块训练与流式生成，缓存复杂度 O(1) 且无额外计算开销；另有一套引导机制，抵消提示语义切换时向量场碰撞带来的失真。作者：Hao Dai、Panyu Chen、Jagmohan Chauhan。演示已发布（见原文）。

数值结果：生成加速 14.5% 以上；流式合成恒定延迟 1.8 秒；生成 fidelity 与现有最强基线相当（摘要未给出逐项主观/客观分数）。

批判性分析：对长音频生成，Mamba 路线的吸引力不在单点分数，而在“长度上去、成本不爆炸”的结构性质——这正是 Transformer 扩散最难受的地方。但摘要的 14.5% 没交代基线与音频长度分布，长度越长 Mamba 的优势本应越大，平均数反而可能低估了长尾收益；1.8 秒是首包延迟还是每块延迟，也要看演示与正文。提示切换时的向量场碰撞是个真实痛点，引导机制是否通用到多说话人/多事件场景，值得在 Demo 里实测。

摘要译文：音频生成的近期进展主要由基于 Transformer 的扩散模型驱动。然而这些模型受自注意力二次复杂度的拖累，严重制约了长音频合成。为克服这一局限，我们提出 MFlowAudio，一个新颖的隐空间音频生成框架，它把流匹配的连续时间动态与定制设计的 TCMamba 骨干结合起来。TCMamba 采用创新的双扫描机制：TimeMamba 模块以线性复杂度捕捉长程因果依赖，ChannelMamba 模块建模谐波结构等跨通道相关。基于这一结构基础，我们提出状态化流匹配（SFM）范式。该框架天然支持分块训练与流式生成，保持 O(1) 的缓存复杂度且不产生额外计算开销。为实现细粒度可控合成，我们设计了一种新颖的引导机制，抵消由提示即时语义切换引发的向量场碰撞。全面的实证评估证实，MFlowAudio 在生成 fidelity 上与现有最强基线相当，同时确立了显著的计算效率：生成加速 14.5% 以上，并以恒定 1.8 秒的延迟实现感知无缝的流式合成。

一句话：企业语音系统高频上线，人工 MOS 贵且慢、进不了持续集成；该研究以 Qwen2-Audio-7B-Instruct 零样本打分起步，挖出感知盲点与固有偏见，再基于 SOMOS 构建诊断基准、做 LoRA 微调，给出一套可离线批量跑的企业级语音质检蓝图。

数值结果：摘要只给定性结论——微调后优于基座模型与 UTMOS；零样本盲点与偏见的具体表现、相关系数与提升幅度未在摘要中给出，需查正文。

6. 多模态推理的模态错位：token 推理带不动连续图像生成，LARC 把推理搬进连续隐空间

2610.42149

一句话：统一多模态模型在理解与生成上都很强，却难以把语言链式推理的 test-time scaling 与细粒度可控性继承到图像生成；作者把原因归于模态错位——推理在离散 token 空间、生成在连续空间——并提出连续隐空间推理框架 LARC，在 GenEval 上比 BAGEL 高 7 个百分点，且呈现清晰的 test-time scaling。

贡献/机制：两阶段：课程 SFT 把 token 级推理逐步转化为隐空间推理；信息增益 RL 在无标准答案监督下自我演化隐推理。关键是绕开 token 级瓶颈：推理直接在连续隐状态上进行，而非先离散化再生成。作者：Byungwoo Jeon、Yoonwoo Jeong、Hyunseok Lee、Minsu Cho、Jinwoo Shin。

数值结果：GenEval 上比 BAGEL 高 7 个百分点（SOTA）；在并行与串行两种 test-time scaling 策略下均优于基于 token 的生成；多项文本到图像基准上生成质量、提示遵循与组合 fidelity 一致提升（摘要未给逐项数字）。

批判性分析：这篇把“推理”从语言模型的专属能力，正式推广成统一模型的生成控制手段——如果隐推理的 scaling 行为成立，多模态生成的“算力换质量”就有了与 LLM 对齐的路线。但要追问两点：一是 7 个百分点的基线 BAGEL 版本与评测协议是否可比；二是隐空间推理的可解释性与可控性是否真优于 token 推理——摘要宣称细粒度可控，但证据在正文；RL 阶段无标准答案监督下的退化风险（隐推理漂移）也需要消融支撑。值得与同日另一篇隐空间注意力（精评 7）对照读：连续隐空间正在成为多模态与长上下文的共同解法。

摘要译文：统一多模态模型（UMM）在多样的多模态理解与生成任务上取得显著成功，但仍难以有效利用基于语言的链式思考推理来做图像生成。结果，现有推理增强的 UMM 常常无法继承大语言模型中观察到的 test-time scaling 与细粒度可控性。我们把这一失败归因于根本的模态错位：推理在离散 token 空间中进行，而图像生成在连续空间中运行。为弥合这一鸿沟，我们引入连续空间中的隐推理框架（LARC），它通过在连续隐状态上推理来缓解 token 级瓶颈。具体而言，训练框架包含两个阶段：（i）课程监督微调（SFT），以及（ii）信息增益强化学习（RL）。首先，课程 SFT 阶段逐步把 token 级推理转化为隐推理。随后，信息增益 RL 阶段在无标准答案监督的情况下自我演化隐推理。在多样的文本到图像生成基准上的实验表明，LARC 一致提升生成质量、提示遵循与组合 fidelity。值得注意的是，LARC 在 GenEval 上取得 SOTA，比 BAGEL 高 7 个百分点，并展现出清晰的 test-time scaling 行为，在并行与串行 test-time scaling 策略下均优于基于 token 的生成。

7. 10M token 的注意力账：LSA 在学习隐空间里层次聚类 key，单层 prefill 加速 72.4 倍

2610.42147

一句话：Agent 走向长 horizon 任务，上下文要冲到 1M token 以上，但全注意力在超长上下文下贵到不可行、现有稀疏索引要么仍是二次成本、要么在超长尺度掉精度；LSA 把 key 在学习隐空间里层次聚类，查询只打分簇层次，在 10M token 下单层 prefill 比全注意力快 72.4 倍且精度基本保持。

贡献/机制：查询不再逐个打分 key，而是打分层次化的簇，使 prefill、decode 与训练在长上下文下都更快；两个版本：D-LSA 经蒸馏用于已预训练模型，N-LSA 直接用下一 token 损失原生训练。作者：Ales Kubicek 等（11 人）。

数值结果：在 GLM-5.3-FLASH（QWEN-3.8-27B）、10M token 下，D-LSA 单个注意力层 prefill 比原稀疏注意力快 22.7 倍、比全注意力快 72.4 倍，decode 快 4.6 倍（42.5 倍）；多项任务精度与原模型相近；N-LSA 在 128k token 下以每层 1.6 倍训练加速达到与全注意力相当的精度。

批判性分析：超长上下文的稀疏注意力之争，关键从来不是“能不能稀疏”，而是“索引本身贵不贵、准不准”——LSA 的回答是把索引也做进学习隐空间。10M token 的数字很抓眼，但要问：10M 下的“相近精度”是在哪些任务上测的、真实长任务（而非合成针尖任务）表现如何；层次聚类的构建与维护成本、显存占用，摘要也没交代。同日还有一篇层次树索引的次二次注意力（2610.42112），两篇思路撞车，选型时值得对照精度—成本曲线。

摘要译文：Agent 工作流正日益转向长 horizon 任务，如开放式科学工作，模型受益于长上下文窗口。然而在超长上下文（1M token 以上）下，全注意力成本过高。一个有前景的方法是稀疏注意力，其中专用索引器选取一部分 key 做注意力。但现有的索引方法要么在上下文规模上仍有二次成本，要么在超长上下文尺度下失去精度。我们用隐空间稀疏注意力（LSA）解决这一问题，这是一种在超长上下文下保持精度的高效注意力方法。在 LSA 中，key 在学习到的隐空间里被层次聚类，查询对簇的层次打分而非对每个 key 打分，使 prefill、decode 与训练在长上下文下都更快。我们提出两个版本：蒸馏 LSA（D-LSA），可通过蒸馏应用于预训练模型；以及原生 LSA（N-LSA），仅用下一 token 损失原生训练。在 GLM-5.3-FLASH（QWEN-3.8-27B）10M token 下，D-LSA 使单个注意力层 prefill 比原稀疏注意力（全注意力）快 22.7 倍（72.4 倍），decode 快 4.6 倍（42.5 倍），同时在多项任务上保持相近精度。N-LSA 以 128k token 下每层 1.6 倍的训练加速达到与全注意力相当的精度。LSA 为模型从超长上下文中受益提供了实用的高效注意力。

8. RLVR 只奖结果对错是不够的：CRoS 只打乱 CoT 顺序不改内容，测到的才是真因果

2610.42054

一句话：RLVR 已是推理训练的标准做法，但只奖结果正确并不能保证 CoT 真对答案有因果贡献；已有因果度量靠删步或注错来扰动 CoT，会同时改变每步的信息量，测到的可能是信息敏感度而非因果性；CRoS 只打乱步骤顺序、不改内容，从而在保留步内信息的前提下度量因果。

贡献/机制：扰动方式的改变就是方法本身：顺序打乱不增删信息，因此“答案随扰动变化”更干净地归因于步骤间的因果依赖，而非信息丢失；用作训练奖励时，避免了已有因果奖励诱发的副作用——生成信息量更少的 CoT、减少探索与自我纠正。作者：Xiao Yu、Justin Chih-Yao Chen、Zaid Khan、Hyunji Lee、Mohit Bansal。

数值结果：在 Reasoning Gym + Gemma-3-4B 上，CRoS 在五项未见逻辑与游戏数据集上得 46.8%，高于最强基线 43.8%；CoT 质量上 CoT-Pass@K 从 K=1 到 128 一致优于基线，平均 43.4% 对 41.4%；CoT 忠实度上 hint 致谢分 34.0% 对 20.2%。

批判性分析：这篇的洞察很干净：因果度量的扰动本身必须“信息中性”，否则奖励会在训练中反噬推理质量——与本期 SCOPE/ATI-OPD 一脉的“监督要放对地方”哲学相通。但要留一个反问：对算术推导这类“顺序即信息”的推理，打乱顺序本身就是信息破坏，CRoS 的信息中性假设在那里是否还成立，摘要未讨论；验证也只在 4B 规模与逻辑/游戏域，数学与代码域的泛化待验。适合作为 RLVR 奖励设计的对照实验，而非直接替换 outcome reward。

摘要译文：可验证奖励的强化学习（RLVR）已成为训练语言模型推理的标准方法。然而 RLVR 通常只依赖结果正确性，这并不能保证 CoT 对最终答案有因果贡献。没有这种联系，结果奖励可能无法强化高质量推理。现有的因果度量通过扰动 CoT 来评估 CoT 因果性，如删除推理步骤或注入错误，并测量最终答案的变化。然而这些扰动不可避免地改变每步中的信息。因此，高因果分数可能反映的是对扰动引入的信息变化的敏感性，而非真正的因果性。当这些度量被用作训练奖励时，这种混杂效应还会进一步诱发不良推理行为，包括生成信息量更少的 CoT、减少探索与自我纠正。为解决这一问题，我们提出 CRoS（基于打乱 CoT 的因果奖励），一种新颖的 CoT 因果度量，它扰动推理步骤的顺序而不改变内容，从而保留每步内的信息。在 Reasoning Gym 上用 Gemma-3-4B，CRoS 在未见域精度、CoT 质量与 CoT 忠实度上均优于现有因果奖励与结果奖励。具体而言，CRoS 在五个未见逻辑与游戏数据集上达到 46.8% 的精度，优于最强基线（43.8%）。它还取得更好的 CoT 质量，在 CoT-Pass@K 从 K=1 到 128 上一致优于基线，平均 43.4% 对 41.4%。在 CoT 忠实度上，CRoS 的 hint 致谢分为 34.0% 对 20.2%。

9. 自蒸馏的动量不用另存：MUON-RT 直接复用教师-学生位移，SDFT 下比 AdamW 高 2.6 分、持久内存少 42%

2610.41104

一句话：带 EMA 教师的自蒸馏本来就存着学生更新的历史，Muon 还要为此另存一份动量缓冲；MUON-RT 直接复用教师-学生位移当动量，省掉隐藏层权重矩阵的动量缓冲，在 Qwen2.5-7B 自蒸馏微调上比 AdamW 平均高 2.6 分、持久内存少 42%。

贡献/机制：位移本身就是指数加权的历史更新和，兼有平滑时间不相关噪声的作用；方法上去掉位移的径向分量、做谱归一化，再经 Newton-Schulz 正交化后与当前梯度混合；理论上在显式的正则性与对齐假设下，期望目标间隔界向残差水平线性收缩。作者：Aryan Das、Vinay Kumar Verma、Aakansha Mishra。

数值结果：Qwen2.5-7B-Instruct 自蒸馏微调（SDFT）上，MUON-RT 比 AdamW 平均精度高 2.6 分、持久内存少 42%，比带动量的 Muon 高 5.4 分、持久内存少 27%；Olmo-3-7B-Instruct 自蒸馏策略优化（SDPO）上比 AdamW 高 2.0 分。

批判性分析：这是“把已有结构用出第二份价值”的典型优化：教师位移不是额外信息，而是被忽视的免费动量估计。对显存紧张的自蒸馏训练，42% 的持久内存削减很实在。但理论依赖的正则性与对齐假设在真实训练中对齐到什么程度，摘要未量化；收益目前只在自蒸馏设定（SDFT/SDPO）验证，普通 SFT 或预训练是否同样受益未见；“持久内存”的口径是否包含教师本身，也要看正文再算账。适合正在跑自蒸馏的团队先小规模对照。

摘要译文：带指数滑动平均（EMA）教师的自蒸馏方法已保留学生更新的历史。然而 Muon 仍存储单独的动量缓冲，增加了持久训练内存。我们提出带复用教师的 Muon（Muon-RT），它复用教师-学生位移来消除隐藏层权重矩阵的动量缓冲。我们证明该位移编码了已应用更新的指数加权历史，并在局部模型下平滑时间不相关的噪声。Muon-RT 去掉其径向分量，做谱归一化，并在 Newton-Schulz（NS）正交化后与当前梯度混合。在显式的正则性与对齐假设下，我们建立了期望目标间隔界向残差误差水平线性收缩的结论。在 Qwen2.5-7B-Instruct 上的自蒸馏微调（SDFT）中，Muon-RT 比 AdamW 平均精度高 2.6 分、持久内存少 42%，比带动量的 Muon 高 5.4 分、持久内存少 27%。在 Olmo-3-7B-Instruct 上的自蒸馏策略优化（SDPO）中，它比 AdamW 平均精度高 2.0 分。

10. 长度预测器本身别成为瓶颈：LEAP 复用 prefill 隐状态做线性读出，CPU 异步在线适配

2610.41359

一句话：长度感知调度能按短请求优先降延迟，但长度预测器本身又大、跨域泛化又差，适配还要昂贵重训，预测开销还会抵消调度收益；LEAP 复用 serving 模型 prefill 阶段的隐状态做线性读出，CPU 异步执行、递归最小二乘在线适配，跨域下 Spearman 相关提升 64.7%，平均每 token 延迟降 15.9–40.8%。

贡献/机制：prefill 隐状态里本来就含有输出长度信号，线性读出足以提取；域偏移大时用已完成请求做监督、经递归最小二乘在测试时更新读出，无梯度计算、无历史数据回放；预测与更新全在 CPU 异步跑，并与 GPU 剩余 prefill 重叠，调度不阻塞推理。作者：Kwan Yan、Jialun Zhong、Yanzeng Li。

数值结果：跨域迁移中在线适配使 Spearman 相关性在大域偏移下提升 64.7%；服务实验中平均每 token 延迟比所评测的长度预测器低 15.9–40.8%，吞吐高 1.9%，预测器参数比最强基线少 30,569 倍。

批判性分析：这篇的工程直觉值得 serving 团队参考：长度信号不必另训大模型去猜，prefill 隐状态里现成就有；在线适配用递归最小二乘而非梯度更新，也把“跨域”从重训问题降格为统计更新问题。但延迟降幅区间很大（15.9–40.8%），实际收益取决于负载形态与域偏移程度；流量突变与冷启动期的在线适配稳定性摘要未交代；线性读出在超长输出与多轮对话下的表现也要看正文。适合已有长度感知调度的系统做对照实验。

摘要译文：长度感知调度通过优先处理较短请求来降低 LLM 服务的请求延迟。然而，尽管模型规模很大，长度预测器在域与任务偏移下仍可能出现排序性能退化，适配它们可能需要昂贵的重训。它们的预测开销还会进一步抵消调度收益。为提升长度感知调度的泛化能力与效率，我们提出 LEAP，一个带快速在线适配与异步 CPU 执行的长度预测系统。LEAP 复用服务模型的 prefill 隐状态，其中包含关于输出长度的信息，并通过线性读出提取这一信号。为适应显著的域与任务偏移，它在测试时通过递归最小二乘更新读出，以已完成请求作为监督，无需梯度计算或历史数据回放。预测与更新在 CPU 上异步运行，而预测与初始批次排序与剩余 GPU prefill 重叠。在所评估的跨域迁移中，LEAP 保持了强排序性能，在线适配使大域偏移下的 Spearman 相关性提升 64.7%。服务实验表明，与所评估的长度预测器相比，LEAP 使平均每 token 延迟降低 15.9–40.8%，同时吞吐高 1.9%，预测器参数比最强基线少 30,569 倍。

简报

1. 对象中心音频表征：slot 注意力一套表征撑起分类、检测与分离三项任务

2610.41870

用 slot 注意力从 AST patch embedding 中重建出一组隐 slot，学到的对象中心表征在合成多声源混合上训练，却能一套表征撑起三项任务：分类 F1 0.8（clip 级 AST embedding 为 0.7）、声音事件检测 macro F1 0.7（clip 级 0.4、与细粒度 patch 级持平）、声源分离 SI-SDRi 18.4 dB、零样本分离 14.5 dB。亮点是“组合性”：slot 结构让表征在任务与数据集间迁移；短板是训练在合成混合上，真实多声源场景的泛化仍需验证。作者：Parthasaarathy Sudarsanam、Tuomas Virtanen。

2. GhostPrefix：一段可复用的通用前缀，不用对齐就能操纵 ASR 输出——数字域定向劫持成功率 93.4%

2610.42026

与逐句定制、要求与受害波形同步的旧攻击不同，GhostPrefix 学一段短音频前缀，加到任意实时语音前面即可操纵 ASR 输出，无需知道未来语音内容或时间对齐；token 级损失加表征级目标保证跨语境稳定，并向良性环境声分布正则以保持隐蔽、抵抗空中失真。数字域下提示 steering 成功率 97.6%、定向劫持 93.4%、无目标攻击把 WER 推到 1.18；空中播放下仍有 91.5% 与 89.5%；覆盖 13 个开源 ASR 模型、4 个模型家族，且操纵会传导到语音助手与 AI 笔记等下游。对语音 Agent 团队的提醒：威胁模型要从“单句对抗样本”升级为“可复用前缀”，防御侧这篇没给答案。作者：Shengding Liu、Ashwin Innuganti、Qiben Yan。演示与产物已发布（见原文）。

3. VoxLock：不用注册步骤的目标说话人提取——从通话本身切一段当声纹，单 CPU 线程跑实时

2610.40727

语音 Agent 的识别器会把麦克风附近所有人都转录进来；VoxLock 把公开因果目标说话人提取模型 REAL-TSE（27M 参数）在单 GPU 上微调，改用从通话本身切出的语音样本当参考，省掉注册步骤。Krisp 265 条录音基准上 WER 4.95%（未处理 23.21%），85 分钟纯背景语音只漏进 9 个背景词；400 段 AMI 会议窗口上 WER 从 42.95% 降到 10.63%；8-bit 模型在单 CPU 线程 77% 占用下跑实时通话、算法延迟 24 ms。单作者作品，但评测集在打分前冻结、模型代码与逐文件分数全公开，方法论上值得肯定。作者：Arbaz Siddiqui。模型与代码已开源（见原文）。

4. 音乐跨模态检索：LoRA 常赢全量微调，但单模态的赢不一定换来跨模态的赢

2610.41512

乐谱驱动的多模态音乐检索需要音频、乐谱图像与符号乐谱三模态的表征既各自可分、又彼此兼容；该研究在 9 个预训练编码器上比较全量微调、LoRA 与 QLoRA：18 个模态-目标组合里 14 个选了 LoRA/QLoRA，常用更少参数达到或超过全量微调。但单模态的提升并不均匀地转化为多模态收益：适配与共享投影在 TriScore 作曲家分类上互补、在另一些任务上冗余、在 Musical Theme 数据集作曲家分类上甚至部分干扰；最终 TriScore 曲目级检索 Top-5 55.32、Top-10 64.68。结论对多模态微调是个提醒：先分开测单模态、再测联合，别默认“各自变好等于一起变好”。作者：Eliseo Fuentes-Martinez、Antonio Hidalgo-Centeno、Jorge Calvo-Zaragoza、Antonio Javier Gallego。

5. BYOD：只用 LoRA 就能把自回归模型转成扩散语言模型——4 块 GPU 小时、50.6% 对 LLaDA 的 51.9%

2610.41574

扩散语言模型支持并行更新与双向注意力，但以往要么贵在预训练、要么贵在全量微调；BYOD 给出通用 LoRA 配方：不改架构、不调专属超参，把 Gemma 2 9B、Llama 3.1 8B、Qwen2.5 7B、Ministral 8B 转成扩散生成（首个 Mistral 系转换），适配器只占 4.1–5.8% 参数、每次转换至多 102.4M token、在单块 Colab GPU 上 3.1–4.0 小时完成。九任务评测中 BYOD-Gemma 平均 50.6%，接近同口径 LLaDA 8B Instruct 的 51.9%；但开放生成在低 NFE 下仍有明显差距：128 token、64 步时困惑度 8.3–11.1，对 LLaDA 的 4.1、自回归父模型的 2.2–3.0。训练与评测实现及四组交互 Demo 已公开。作者：Ruurd J. A. Kuiper、Robert A. Bagheri。

6. 后训练加循环没有免费午餐：只有 0.8B 小模型在同等算力下跑赢不循环的自己

2610.42030

给已训练模型加循环（复用一段层）不增加参数、显存与训练成本，但每个 token 都要为循环买单；该研究把循环模型与两个基线对照：同等参数的无循环同训模型，以及同等推理 FLOPs 下最优的无循环用法。Qwen3 与 Qwen3.5 从 0.8B 到 9B 的结果是：只有 0.8B 循环模型同时跑赢两个基线，4B 与 9B 甚至跑不赢第一个基线——而同基准上无循环 9B 比 4B 高出可达 13 分，说明不是基准太简单、而是循环本身在该规模下不划算。结论：预训练中学到的循环另当别论，后训练再加循环只对参数预算固定的小模型有意义。作者：Rhea Sanjay Sukthanker、Pashmina Cameron。
