精评

1. 空间音频生成与编辑：AMBIT 用可执行 ScenePlan 把“改什么、留什么”写进一张图里

2610.34415

一句话：空间音频创作要同时定声源内容与三维声场，编辑时更要分清改动与保留；AMBIT 用一个共享 Transfusion 骨干把自回归规划与整流流渲染耦合起来，以可执行的 ScenePlan（声源内容、活跃度、三维轨迹）统一生成与编辑，并用 FOA 感知的连续 VAE 与联合在线自蒸馏保证空间结构与未编辑声源的保留，在语音、音乐与声音三类内容上都优于对比基线。

贡献/机制：贡献分三层：规划层，ScenePlan 是可执行的中间表示，编辑时计划描述的是完整目标场景（含保留声源），而不是只写改动差分，这让“保留什么”有了显式载体；表示层，FOA 感知连续 VAE 用共享解码器的全向恢复、不对称分组 KL 与空间协方差匹配，同时保内容与通道间结构；训练层，联合 Transfusion 在线策略自蒸馏（OPSD）在学生自己生成的前缀与采样状态上精修规划与渲染，目标条件教师同时监督两种模式，缓解了训练与推理分布不一致。作者：Kam Man Wu、Yu Zhang、Pengjun Fang、Mingfei Chen、Weijia Chen、Zeyue Tian、Qifeng Chen。代码与项目页：https://github.com/WJM-George/AMBIT 。

数值结果：摘要未给逐项分数，只给出方向性结论：在语音、音乐与声音上生成内容与空间质量提升，指令引导编辑的声学保真度与未编辑声源保留优于基线。FOA 声场的具体指标（如空间定位误差、通道一致性分数）需查正文，引用时不要把“优于基线”读成已量化的幅度。

批判性分析：对做空间音频、沉浸式内容的人，这篇的参照价值在“规划—渲染”分工本身：把编辑写成完整目标场景的计划，天然解决了局部编辑最容易翻车的“改一处、动全身”问题；OPSD 把自蒸馏同时用在规划与渲染两端，也比只蒸馏生成器更完整。保留意见：评估结论全部是定性口径，基线名单与各内容类型的分项结果都在正文；FOA 是一阶 Ambisonics，空间分辨率上限本身有限，结论不宜外推到高阶 Ambisonics 或个性化 HRTF 渲染；编辑保真度在“保留声源”与“改动声源”之间的权衡曲线，摘要未展开，实际选型要看消融。

摘要译文：空间音频创作需要协调声源决策与声场合成。对于编辑，计划要说明改什么、留什么，而参考音频则提供进一步的声学细节。我们提出 AMBIT，一个用于原生一阶 Ambisonics（FOA）生成与编辑的统一框架，包含三个相互关联的贡献。第一，一个共享的 Transfusion 骨干通过可执行的 ScenePlan 把自回归规划与整流流渲染耦合起来，ScenePlan 规定声源内容、活跃度与三维轨迹。对于编辑，该计划描述完整目标场景，包括保留的声源；对比特征锚定请求的改动，而完整的参考隐变量为保留提供残余声学细节。第二，一个 FOA 感知的连续 VAE 结合共享解码器的全向恢复、不对称分组 KL 与空间协方差匹配，以保留内容与通道间结构。第三，联合 Transfusion 在线策略自蒸馏（OPSD）在学生生成的前缀上精修规划、在学生计划下到达的采样状态上精修渲染，目标条件教师同时监督共享学生的两种模式。在语音、音乐与声音上的评估显示，相比对比基线，生成内容与空间质量、指令引导编辑中的声学保真度以及未编辑声源的保留均有提升。

2. Audio-R1：不用人工答案，用自监督音频任务的可验证奖励做音频推理 RL

2610.34609

一句话：大音频语言模型的推理能力远不如文本与视觉模型，且缺乏可验证奖励；Audio-R1 把音频自监督学习重新用作奖励来源——任务构造时自动确定的答案直接验证模型回答、计算奖励，在多个大音频语言模型与多类音频基准上都带来一致提升，且只做 SFT 只能提升自监督任务本身，Audio-R1 还能迁移到训练任务之外的下游任务。

贡献/机制：关键设计是把“自监督任务的构造过程”本身变成奖励函数：答案在构造时就已确定，不需要人工标注或外部教师，奖励天然可验证；消融证明每个自监督任务都有独立收益，联合训练还有额外增益。对比 SFT 的对照尤其值得注意：SFT 与 Audio-R1 都能提升自监督任务准确率，但只有 RL 带来了下游迁移与推理轨迹质量的提升，这说明奖励信号在教模型“怎么推理”，而不只是“记住任务格式”。作者：Jihoon Jeong、Mirco Ravanelli、Zhepei Wang、Cem Subakan。摘要未提供代码链接。

数值结果：摘要未给逐基准分数，只给出方向性结论：跨多个大音频语言模型与多类音频基准一致提升，消融支持各任务收益与联合训练增益，SFT 对照下 RL 的下游迁移成立。具体到哪个基准提升多少、推理轨迹质量如何度量，需查正文表格，引用时不要编造幅度。

批判性分析：对做音频 RL 的人，这篇把“可验证奖励从哪来”这个最贵的环节降到了构造自监督任务的成本：不需要人工问答对，也不需要更强的教师模型，奖励来源可规模化。保留意见也正在这里：自监督任务的答案分布与真实推理任务的答案分布未必一致，奖励可验证不等于奖励与目标对齐，迁移收益的边界（哪些下游任务受益、哪些不受益）摘要未展开；另外“多个模型、多类基准”未点名，复现前要先看正文的模型与基准清单。尽管如此，在音频推理 RL 几乎没有现成奖励管线的当下，这是一条值得先跑通的路线。

摘要译文：推理对大音频语言模型（LALM）越来越重要，但相比纯文本与视觉语言模型，仍相对未被充分探索。我们引入 Audio-R1，一个强化学习（RL）后训练框架，它把音频自监督学习重新作为可验证奖励的来源，以提升音频理解与推理任务表现。Audio-R1 利用自监督任务构造过程中自动确定的答案来验证模型回答并计算奖励。在多个 LALM 与多类音频基准上的实验显示出一致的性能提升，消融证明了每个自监督任务的收益以及联合训练的额外增益。虽然监督微调与 Audio-R1 都能提升自监督任务准确率，但 Audio-R1 还能进一步提升与训练任务不同的下游任务表现。这些结果突显了用自监督音频任务做 RL 后训练以提升下游表现与推理轨迹质量的潜力。

3. Trajectory2Gym：成功的工具轨迹未必是好监督，可学的轨迹要先把“当时看不见的信息”筛掉

2610.33568

一句话：工具 Agent 的成功轨迹常被直接当作监督，但成功不等于可学——有些动作依赖学习者当时看不见的信息，有些多步依赖在数据里根本没被覆盖；Trajectory2Gym 围绕“组合覆盖”与“决策 grounded”两个要求，主动构造可执行交互、只从 grounded 决策派生监督，在五个 Qwen3 规模上把 Tau1、Tau2 与 BFCL 三个基准的等权均值提升了 16.9–29.8 个百分点，且增益在状态依赖的多轮交互中最强。

贡献/机制：方法本体是把轨迹生成从“收集成功轨迹”改成“构造可学习交互经验”：先围绕欠支持的组合结构构造可执行交互，再只从已实现执行中的 grounded 决策派生监督；结构支持选择分配经验，父级归一化 SFT 把语义交互作为训练权重单位而非单条样本。这两个要求是耦合的——只讲覆盖会混入不可学动作，只讲 grounded 会漏掉关键依赖组合。作者：Yihao Hu、Zhihao Wen、Yitong Lin、Siyuan Lu、Pan Wang、Wei Wu、Jiang-Ming Yang、Tao Lin。代码：https://github.com/yihaohu0118/Trajectory2Gym 。

数值结果：五个 Qwen3 规模上，Tau1、Tau2、BFCL 三基准等权均值提升 16.9–29.8 个百分点；增益在状态化与多轮交互中最强，后续决策依赖早期观测与反馈的场景受益最大。摘要未给各规模、各基准的逐项分数，引用具体规模的数字需查正文。

批判性分析：对做 Agent 后训练的人，这篇把一个常被忽略的监督质量问题形式化了：SFT 的有效样本不是“结果对了”，而是“在学习者可见历史下，动作可被推出”。与单纯扩大成功轨迹量相比，这个视角更接近 RL 里“on-policy、可学习”的直觉，也解释了为什么有些轨迹数据越训越不稳。保留意见：构造式交互的成本与覆盖策略本身需要人工设计组合结构，可扩展性取决于结构枚举是否完备；评估集中在 Qwen3 家族与三个工具基准，结论外推到其他模型家族与真实工具生态时要谨慎。

摘要译文：成功的工具使用轨迹未必是有用的监督。即使成功的交互也可能低估多步依赖，或包含在决策时学习者可见信息无法支持的动作。我们指出有效轨迹监督的两个耦合要求：组合覆盖，即重要的观测—动作依赖要被表示；决策 grounded，即每个被监督的动作都要得到学习者可见交互历史的支持。我们引入 Trajectory2Gym，它围绕欠支持的组合结构构造可执行交互，并只从已实现执行中的 grounded 决策派生监督。结构支持选择分配由此产生的经验，而父级归一化监督微调把语义交互作为训练权重的单位。这把轨迹生成重新定义为有意构造可学习交互经验，而非收集成功轨迹。在五个 Qwen3 规模上，Trajectory2Gym 在每个受测规模上都提升了 Tau1、Tau2 与 BFCL，使三个基准的等权均值提高了 16.9–29.8 个百分点。增益在状态化与多轮交互中最强，即后续决策依赖早期观测与反馈的场景。我们的结果表明，扩展工具 Agent 不仅取决于收集更多成功轨迹，还取决于构造依赖关系被表示、决策可从 Agent 可见历史中学习的交互。

4. TraceTrial-Bench：Agent 任务成功了，Harness 未必合格——31.1% 的成功运行至少违反一项可靠性准则

2610.32285

一句话：Agent 评测长期只看模型能力与最终任务成败，几乎不评支撑 Agent 运行的 Harness 本身；TraceTrial-Bench 把 Harness 可靠性拆成上下文、执行、治理、生命周期、可观测性、工具与验证七个组件，用 95 个专家级机制导向任务、轨迹追踪与双层评估框架，在 4 个 Harness、9 个模型、3420 次运行中发现 Harness 宏观均分只有 59.8%–72.0%，且 31.1% 的运行虽然任务成功，却至少违反一项 Harness 准则。

贡献/机制：贡献分三层：拆分层，七组件把“ Harness 好不好”从笼统印象拆成可分别打分、可归因的维度；任务层，95 个专家级机制导向任务带可执行或基于状态的真值，支持语义等价比较同时保留各 Harness 的原生行为；评估层，轨迹追踪（TT）捕获执行轨迹，多源证据获取（MEA）从 Agent 上下文、Harness 与执行环境三处取证，失败归因（FA）用显式机制链做到运行级归因，双层框架把“任务表现”与“ Harness 可靠性”分开打分，避免成功掩盖违规。作者：Zhiyong Cao、Hengjie Zhu、Yongxin Wang、Xuchen Li、Jintao Li、Shuxia Liu、Dunqiang Liu、Bo Wang、Kairan Zhang、Cong Lin、JiangDi Yu、Siyuan Liu、Sijia Yao、Yi-Liang Wei、Lingxu Ma、Aijia Wang、Anxin Chen、Zixian Wei、Xiang Ruan、Ruizhi Xu、Ruqian Shi、Baihua Xiao、Sicheng Zhou。代码：https://github.com/TraceLite-AI/TraceTrial-Bench 。

数值结果：4 个 Harness、9 个模型、95 个任务、3420 次运行；Harness 宏观均分 59.8%–72.0%；31.1% 的运行任务成功但至少违反一项 Harness 准则。摘要未给各 Harness 的分项分数与各组件的短板分布，选型时要看正文的组件对照表。

批判性分析：对搭 Agent 系统的人，这篇的 31.1% 是最值得带走的数字：只看任务成功率选 Harness，会系统性地漏掉治理、观测与验证层面的违规——这些违规在演示里看不见，在生产里会变成不可复现、不可审计、不可追责。双层评估的思路也值得借鉴到内部评测：先把“做对了没有”和“过程合规没有”分开，再谈综合分。保留意见：95 个任务的专家级机制导向设计本身带有作者对“好 Harness”的定义，分数的可迁移性取决于这套定义是否被社区接受；LLM 参与评估的部分（MEA/FA）也需要人类一致性对照，摘要未给。

摘要译文：LLM Agent 越来越多地用于解决现实问题，其效果既取决于底层模型，也取决于支撑其运行的 Harness。然而，大多数现有基准只关注模型能力与 Agent 整体表现，对 Agent Harness 的评估关注有限。为填补这一空白，我们引入 TraceTrial-Bench，它把 Harness 可靠性组织为涵盖上下文、执行、治理、生命周期、可观测性、工具与验证的七个组件。我们构建了 95 个专家级、机制导向的任务，配有可执行或基于状态的真值，以支持语义等价比较，同时保留每个 Harness 的原生行为。我们设计了轨迹追踪（TT）模块来捕获 Agent 执行轨迹，并引入双层评估框架，分别评估 Agent 表现与 Harness 可靠性。此外，我们设计了多源证据获取（MEA）模块，从 Agent 上下文、Harness 与执行环境提供证据以供基于 LLM 的评估，并开发了失败归因（FA）模块，用显式机制链支持运行级归因。在 4 个 Harness、9 个模型、95 个任务上，我们的评估共 3420 次运行，Harness 宏观均分在 59.8% 至 72.0% 之间，而 31.1% 的运行虽然任务成功，却至少违反一项 Harness 准则。TraceTrial-Bench 为比较 Agent Harness、诊断其失败以及研究 Harness 设计如何与模型行为相互作用，提供了可审计、可复现的基础。

5. FORK：Rubric 奖励只算覆盖率会把模型训得更啰嗦、更敢编，加一个“精确度”目标后胜率从 10.6% 涨到 68.0%

2610.33512

一句话：Rubric 奖励让不可验证任务也能做 RL，但按 Rubric 覆盖率加权本质上是召回目标，模型会越答越全、越答越长、越敢编，反而在人类偏好上输给基座模型；FORK 奖励同时优化召回与一个新的精确度目标——回答的每个单元既要必要、又要事实正确，召回覆盖不变的情况下大幅提升精确度、缩短回答，RubricHub-Medical 上的胜率从 10.6% 提升到 68.0%，HealthBench 上从 22.1% 提升到 74.1%。

贡献/机制：方法本体是把奖励从单维召回拆成召回与精确度的双目标：必要性用 Rubric 驱动的必要性信用度量，事实正确性用事实正确性评分器度量，两者缺一不可——只必要不正确的单元与只正确不必要的单元都不能拿满分。这个拆分直接对应“啰嗦与编造”两种失败模式：前者是必要性问题，后者是事实性问题，单维覆盖率奖励同时奖励了这两种行为。作者：Hyun Ryu、Jong-Heon Kim、Yiqing Xie、Seungone Kim、Carolyn Rose、Eunho Yang。代码：https://github.com/JHKim631/FORK 。

数值结果：相比原始召回奖励，FORK 在保持相似 Rubric 覆盖的同时大幅提升精确度、缩短回答长度；相对基座策略的胜率在 RubricHub-Medical 上从 10.6% 提升到 68.0%，在 HealthBench 上从 22.1% 提升到 74.1%。摘要称其达到 Pareto 最优的覆盖—质量平衡，但未给精确度与长度的具体数值，引用幅度时以胜率为准。

批判性分析：对做不可验证任务 RL 的人，这篇是直接可用的检查清单：上线 Rubric 奖励前，先看回答长度与事实错误率有没有跟着覆盖率一起涨——如果涨了，奖励函数本身就是问题，不是模型问题。FORK 的双目标设计也比事后加长度惩罚更干净，因为它在奖励层面就区分了“多余”与“错误”。保留意见：必要性信用与事实评分器本身都是模型打分，奖励信号的质量取决于这两个评分器的可靠性，存在“评分器被 hack”的二阶风险；评估集中在医疗类 Rubric 任务，结论外推到开放式写作、代码等任务时要先验证评分器口径。

摘要译文：基于 Rubric 的奖励使对不可验证任务的强化学习成为可能。然而，由于这些奖励通常定义为 Rubric 覆盖率的加权度量，模型主要被训练去最大化一个召回目标。结果是，经 RL 训练的模型回答更完整，但也更啰嗦、包含更多不必要或事实不正确的内容，导致在偏好上不如基座模型。为解决这一问题，我们提出 FORK 奖励，它联合优化召回与一个新的精确度目标，该目标要求回答的每个单元既必要又事实正确，分别由 Rubric 驱动的必要性信用与事实正确性评分器度量。实验结果显示，FORK 优于现有的基于 Rubric 的 RL 方法，达到了平衡 Rubric 覆盖与整体回答质量的 Pareto 最优表现。相比原始召回奖励，FORK 在保持相似 Rubric 覆盖的同时大幅提升精确度并缩短回答长度，从而显著提高相对基座策略的胜率（例如在 RubricHub-Medical 上从 10.6% 提升到 68.0%，在 HealthBench 上从 22.1% 提升到 74.1%）。

6. AV-FABLE：长视频里的篡改只占一小段，音视频大模型零样本检测近乎随机，冻住的特征里其实有信号

2610.33413

一句话：现有音视频 Deepfake 基准多是短 talking-head 片段，长视频里局部篡改的取证仍以视觉为主；AV-FABLE 用 16650 对原始—篡改孪生样本（998 小时、27 种编辑配置）搭了双时间线基准，音频与视觉时间线分开打分，暴露了联合时间线评估藏起的错误；零样本提示音视频大模型检测近乎随机、定位很差，但冻住的感知特征经监督读出后能恢复强取证信号，据此提出的 NFSR 在域内与三个分布外设定上都取得最佳音视频定位表现。

贡献/机制：贡献分三层：基准层，双时间线设计是关键——音频与视觉篡改位置不必重合，分开评估才能暴露“一种模态对了、另一种错了却被平均掉”的问题；诊断层，零样本语言输出近乎随机、而冻结特征监督读出却有强信号，这个反差说明取证证据已编码在表征里，只是语言输出通道没把它暴露出来；方法层，NFSR 用分离的音频与视觉时间解码器读冻结 AV-LLM 特征，不重训感知骨干，定位收益来自读出方式而非新表征。作者：Yuesheng Huang、Hoi Fan Au、Jiaqi Hou、Ruicheng Zhang、Jiarui He、Haocheng Yang、Bin Hu、Kewei Zhang、Weijian Deng、Jun Zhou、Xiu Li。摘要称 AV-FABLE、代码与模型权重将公开发布。

数值结果：基准规模 16650 对孪生样本、998 小时、27 种编辑配置；零样本 AV-LLM 检测近乎随机、时间定位差；NFSR 在域内与全部三个分布外设定上取得最佳音视频定位表现，并迁移到外部长视频取证基准的留出视频。摘要未给检测 AUC、定位 mAP 等逐项分数，引用时以方向性结论为准。

批判性分析：对做音视频取证与内容安全的人，这篇的诊断比方法更值得注意：不要因为大模型“说不出来”就断定它“看不出来”——语言输出通道的瓶颈会系统性低估感知表征里的信号，取证系统应该直接读特征、而不是只问模型。双时间线评估也值得借鉴到任何多模态定位任务：联合分数好看，可能是单模态错误被平均掩盖了。保留意见：27 种编辑配置的覆盖仍由作者定义，真实篡改手段的分布漂移会压缩基准的预测力；NFSR 的分布外迁移只在三个设定上验证，跨平台、跨编解码器的鲁棒性仍需实测。

摘要译文：长视频中局部的 AI 篡改往往只影响真实内容中的短暂事件，因此视频级分类不足以支撑取证分析。现有的音视频 Deepfake 基准大多聚焦短 talking-head 片段，而长视频时间取证仍主要以视觉为主。我们引入 AV-FABLE，一个用于开放场景长视频中稀疏篡改的双时间线基准。AV-FABLE 包含 16650 对原始—篡改孪生样本（998 小时），由 27 种编辑配置生成，音频与视觉时间线相互分离，从而支持模态特定的时间定位，并暴露联合时间线评估隐藏的错误。在 AV-FABLE 上，音视频大模型（AV-LLM）的零样本提示检测近乎随机，时间定位也很差。相比之下，对其冻结感知特征的监督读出恢复了强取证信号，表明篡改证据已编码在这些表征中，但未能通过语言输出有效暴露。受此观察启发，我们提出 NFSR（基于分离读出的原生取证），用分离的音频与视觉时间解码器读取冻结的 AV-LLM 特征。NFSR 在域内与全部三个分布外设定上都取得了最佳音视频定位表现，包括迁移到外部长视频取证基准的留出视频。AV-FABLE、代码与模型权重将公开发布。

7. S3AC：长 CoT 的 Critic 难训不是因为 Critic 没用，而是轨迹覆盖与价值头冷启动没处理好

2610.35518

一句话：无 Critic 方法在可验证奖励 RL 里流行，是因为长 CoT 的 Critic 训练本身很难——不同长度轨迹覆盖不足、新初始化的价值头早期梯度占主导；S3AC 给出一套可落地的 Critic 训练配方，让 Critic 提供 token 级优势与 prompt 级基线，并用难度感知提示采样减少 rollout 浪费，在 1.5B 到 397B 的稠密与 MoE 模型上都优于现代 GRPO 变体（GRPO-X），35B 规模上单 rollout 训练仍能维持，而无 Critic 基线在初期收益后恶化。

贡献/机制：配方分三层：稳定化，处理长 CoT 轨迹长度多样性的覆盖问题与价值头冷启动的早期梯度问题；选择性，Critic 估计的 prompt 级难度结合结果历史，在生成前选提示（DAPS），不依赖离线难度初始化就减少 rollout 浪费；可扩展性，同一配方从 1.5B 稠密模型覆盖到 397B MoE，说明 Critic 路线不是只在小规模上成立。token 级优势是 Critic 相对分组基线的根本优势：分组方法只能给整条轨迹一个基线，Critic 能给每个 token 不同的信用。作者：Shuo Shen、Guangran Cheng、Chengqi Lyu、Xiangsen Wang、Yanan Sun、Wenwei Zhang。代码：https://github.com/InternLM/xtuner 。

数值结果：模型范围 1.5B 至 397B（稠密与 MoE）；在各规模上组 rollout 表现优于 GRPO-X；35B 规模上 S3AC 维持单 rollout 训练，而受测无 Critic 基线在初期收益后恶化。摘要未给各规模、各基准的逐项分数，引用具体提升幅度需查正文。

批判性分析：对做长 CoT RL 的人，这篇的价值在于把“Critic 难训”从信仰问题变成了配方问题：覆盖与冷启动是可工程化解决的两点，而不是 Critic 路线的固有缺陷。DAPS 的“生成前选提示”也值得注意——它把难度估计从离线初始化改成在线估计，省掉了昂贵的预标注。保留意见：Critic 训练的额外算力与调参成本摘要未给账，配方在 397B 上的“优于 GRPO-X”未给幅度，是否值得为 Critic 付出额外成本，要看正文的性价比对照；另外价值头冷启动的解法细节在正文，复现前要先读配方章节。

摘要译文：无 Critic 方法在可验证奖励强化学习（RLVR）中被广泛用于长思维链（CoT）推理，因为它避免了困难且昂贵的 Critic 训练。常见的替代方法缺乏 token 级信用分配，通常依赖分组 rollout 来估计 prompt 特定的基线。Critic 可以解决这两个局限，但长 CoT 的 Critic 训练受到不同长度轨迹覆盖不足以及新初始化价值头主导早期梯度的阻碍。我们引入 S3AC（稳定化、选择性、可扩展的 Actor-Critic），用于 LLM 推理，围绕一套实用的 Critic 训练配方构建。训练好的 Critic 提供 token 特定的优势与 prompt 特定的基线。利用 prompt 级基线估计难度，我们提出难度感知提示采样（DAPS）。DAPS 把这一估计与结果历史结合，在生成前选择提示，无需离线难度初始化即可减少 rollout 浪费。S3AC 在 1.5B 到 397B 参数的稠密与混合专家模型上提升了组 rollout 表现，优于现代 GRPO 变体（GRPO-X）。在 35B 规模上，它维持单 rollout 训练，而受测的无 Critic 基线在初期收益后恶化。

简报

1. Omni-Woodpecker：Omni 模型的跨模态幻觉不在输出层，而在融合表征里先验与证据的纠缠

2610.27103

用互补的单模态视角先找出跨模态冲突，再用正交分解把融合隐状态里的 grounding 证据与竞争先验分开，最后按冲突自适应地压制误导先验、恢复被忽略的证据——全程免训练。以 Qwen2.5-Omni-7B 为骨干，在 CMM 上提升 12.9 分、AVHBench 上提升 8.6 分，四个通用 Omni 推理基准上提升 0.67–2.25 分；迁移到 VideoLLaMA2-AV 上，在同一对基准上提升 4.6 与 3.9 分。代码：https://github.com/ZiiJianLiu/Omni-Woodpecker 。

2. StreamVibe：主动视频 Agent 的难点不是“答什么”，而是“何时答、意图变了怎么办”

2610.34662

StreamVibe-Bench 覆盖显式、隐式与动态三类意图，4100 个评估样本、85000 个训练样本；StreamVibe-VL 从连续观测中推断隐式意图并随意图演变调整交互，相比基线在响应时机与回答质量上提升 10.7%，同时保持通用视频理解；StreamVibe-Harness 用分层记忆把用户意图作为带生命周期的持久状态维护，在持续交互中再带来 12.3% 的主动交互增益。现有主动模型在隐式与动态意图下的意图理解与响应时机决策上仍有限。

3. DynaFlow：多智能体编排不必预设结构，主 Agent 自己决定何时协作、生成什么工作流

2610.34467

主 Agent 把自由形式的可执行工作流合成放进动作空间，自行决定协作时机、生成串并行协调子 Agent 的任务程序，并用执行结果与轨迹调整后续协作；只训练主 Agent（蒸馏轨迹 SFT + 针对无支持前提、有偏验证与信息流缺陷过滤后的精修），子 Agent 全部固定。在六个数学、科学问答与多跳检索基准上，强制模式总体准确率 88.08%，用同一 Qwen3.5-27B 骨干比最强基线高 10.90 个百分点；训练后对上游输出的显式使用、验证与精修明显增加。代码：https://github.com/amiya-special/Dynaflow 。

4. InteractiveWorld：可穿戴助手到底能不能帮人干活，第一次有了不用真人也能闭环验证的考场

2610.33966

助手指导、人类行动、环境执行并更新所见——InteractiveWorld 让助手与人类 Agent 闭环交互，InteractiveBench 含 120 个多轮任务、六类场景，全部用可验证的基于状态的奖励打分。12 个前沿多模态大模型受测，最强的 Claude Fable 5.1 在长程引导任务上至多 20%、规划任务上至多 25%，离“可靠助手”还很远。代码：https://github.com/facebookresearch/InteractiveWorld 。

5. ProAS：GRPO 把整条轨迹的优势平均分给每个动作，会把不合理动作也一起奖励

2610.18683

ProAS 用动态演化的 Agentic 参考图（ARG）做细粒度信用分配：屏蔽不合理激励（MUI）与不对称惩罚再分配（APR），不引入 Critic 开销。在 Qwen2.5-1.5B 与 7B 上，ALFWorld 峰值成功率分别为 91.9% 与 94.3%，WebShop 上分别为 66.7% 与 70.8%，训练收敛加速最高 2.44 倍，且对不完美或蒸馏得到的 ARG 仍稳健。代码：https://github.com/LINs-lab/ProAS 。

6. Continual Learning Exam：经验能不能累积，要看 600 关的阶梯能不能一级一级爬上去

2610.33956

CLE 由 50 多位领域专家构建，120 个人工任务、每任务五级阶梯、共 600 关，覆盖 89 个职业角色、12 个职业领域，后一级建立在前一级积累的经验之上。17 个 Harness—模型配置受测，失败后给诊断反馈并允许一次修改，中位完成率提升 5.3 个百分点；但最强系统也只通过 47.7% 的关卡、仅在 23.3% 的任务上通关全部五级。代码：https://github.com/haoyu-zhao/Continual-Learning-Exam 。
