1. RRSI：正则化递归自改进智能体 Harness

2609.24972

一句话看点： RRSI 用退火编辑预算、探索约束、批评器和剪枝器抑制 harness 演化对训练任务的过拟合，在分布外基准仍提升最多 4.7 个百分点，并减少 30% policy token。

作者与元数据： Peng Xia、Rujun Han、Zifeng Wang、Yanfei Chen、Yufan Zhang、Yoonho Lee、Chengsong Huang、Han Yu、Zhongying CuiZhu、Yifei Ming；2026-09-21；AI Agents。

核心贡献与机制： 论文把智能体的提示词、控制流、工具、记忆和上下文管理视为可递归优化的 harness，但普通演化容易记住训练任务。RRSI 限制单次候选能捆绑的编辑数量，按演化历史鼓励探索未走过的轨迹；选择器用 critic 筛掉 benchmark-specific 改动，再由 pruner 移除过小、过贵或失效的修改。

结果与批判： 八个编码、智能体工作区和工程设计基准上，RRSI 相对未正则化演化在目标划分最多提升 14.1 个百分点，在五个分布外基准最多提升 4.7 个百分点，同时 policy token 减少 30%。批判地看，摘要没有给出各任务绝对分数、演化调用成本和不同正则项的独立贡献；分布外收益也可能受基准选择影响，harness 复杂度、搜索预算与部署稳定性的关系仍需公开。

摘要翻译： 论文认为，LLM 智能体的能力很大程度由围绕冻结骨干模型的 harness 放大，包括提示词、控制流、工具、记忆和上下文管理。近期方法通过反复提出并选择 harness 组件编辑，实际上形成了系统层面的递归自改进，但这种演化可能过拟合训练任务。我们提出 RRSI，通过约束候选提议和选择过程引入正则化：提议器采用随时间退火的预算限制单个候选可捆绑的编辑数量，并依据演化历史鼓励探索未走过的轨迹；选择器配备批评器和剪枝器，分别筛查特定于基准的提议，并删除过小、过贵或不再有用的变化。这些约束更偏向可复用的 agent 机制，而非基准特定技巧或噪声。在覆盖编码、智能体工作区和工程设计的八个基准上，RRSI 在演化目标划分最多提升 14.1 个百分点，在五个分布外基准最多提升 4.7 个百分点，并使 harness 比未正则化演化少运行 30% 的策略 token。代码已在 GitHub 公开。

2. VideoGen-Agent：用强化学习训练视频生成智能体

2609.24997

一句话看点： VideoGen-Agent 让多模态智能体在增强、生成和验证工具之间多轮协作，VABench 从 56.5 提升到 75.6，升级生成工具后无需再训练可达 86.1。

作者与元数据： Binxu Li、Haoyi Duan、Yuhui Zhang、Yaohui Zhang、Zihao Lin、Kaituo Feng、Suozhi Huang、Xiangyi Li、Yu Li、Chunyuan Li；2026-09-21；LLM Training。

核心贡献与机制： 方法在六类任务上用类别均衡数据训练共享策略，先用教师轨迹监督微调建立工具使用，再用多任务 agentic RL 优化；混合奖励同时检查工具调用合法性、任务匹配度和视频质量。VABench 含 600 个提示，覆盖程序知识、身份保持、物理一致性、构图和多镜头时序。

结果与批判： VABench 上相对基础文生视频生成器提升 19.1 分，从 56.5 到 75.6；仅替换更强生成工具就升到 86.1，人类评审在 84.3% 的比较中偏好升级配置。局限是摘要没有拆分六类任务的贡献，也没有说明工具调用成本、评测者数量和视频质量评分细则；更强工具本身贡献很大，智能体策略的独立增益需要更严格的交叉实验。

摘要翻译： 近年来视频生成模型已能生成高保真且时间连贯的视频，但面对需要专业知识、特定身份、物理一致性或有序事件的提示时仍常失败。我们提出 VideoGen-Agent，一个通过多任务智能体强化学习训练、能够使用外部工具的视频生成多模态智能体。它通过多轮交互协调增强、生成和验证工具，并利用提示与中间观察指导决策。我们在涵盖六项任务的类别均衡数据集上训练共享策略，先用教师生成轨迹进行监督微调，再用强化学习改进。类别感知的混合奖励同时评价工具调用合法性、任务适配的工具使用和生成视频质量。我们还提出 VABench，一个包含 600 个提示的留出基准，覆盖程序知识、单实体和多实体身份保持、物理一致性、场景构图和多镜头时间结构。在 VABench 上，VideoGen-Agent 将基础文生视频生成器的分数从 56.5 提升 19.1 分至 75.6；升级生成工具后无需额外训练即可达到 86.1。人类评审在 84.3% 的比较中偏好升级后的配置。结果表明，视频生成任务之间的工具使用可以学习，并且训练好的智能体能继续受益于后续生成工具升级。

3. RoboDawn：把 VLM 智能迁移到机器人控制

2609.22966

一句话看点： RoboDawn 用少量离散平移、旋转和夹爪指令把 VLM 接入闭环机器人控制，RoboTwin 2.0 C2R 一次示范成功率达 73.6%，超过 π0.5 的 46.0%。

作者与元数据： Meng-Hao Guo、Zhe-Han Mo、Jia-Jun Wang、Yi Zhang、Kejin Wang、Yi-Xuan Deng、Jia-Peng Zhang、Yongming Rao、Shi-Min Hu；2026-09-19；AI Agents。

核心贡献与机制： 接口让 agentic VLM 观察视觉状态、推理动作、执行并根据结果闭环修正；ICL 示例同时教会模型接口用法和任务策略，不需要任务专用机器人训练。方法在 RoboTwin 2.0 C2R、RoboDojo 和 Franka 实机上验证。

结果与批判： RoboTwin 成功率从 zero-shot 的 53.2% 升到 one-shot 的 73.6%，RoboDojo 从 35.67% 升到 47.17%，并完成篮中放块和堆块实机任务。风险在于离散动作接口可能把控制难度转移到高频闭环和视觉定位，摘要没有报告任务数量、失败类型、延迟或真实机器人统计显著性；zero-shot 超过专用策略的比较也需确认训练数据和算力是否公平。

摘要翻译： 人类可以自然地适应物理世界和数字世界，这启发了一个问题：视觉语言模型的智能是否也能从数字世界迁移到物理世界的机器人控制？我们通过 RoboDawn 研究这一问题。RoboDawn 是一种符合人类直觉的接口，用紧凑的离散平移、旋转和夹爪命令向 agentic VLM 暴露机器人控制。VLM 在闭环中观察当前视觉状态、推理下一动作、执行它，并根据结果调整后续决策。我们还提出一种上下文学习方案，用少量示范让 VLM 掌握接口使用和任务解决策略。在 RoboTwin 2.0 C2R 和 RoboDojo 上，RoboDawn 无需任务专用机器人训练即可取得较强性能。zero-shot 时它超过多个使用基准机器人数据训练的策略，而单个上下文示范进一步带来显著提升并达到 SOTA。在 RoboTwin 2.0 C2R 上，成功率由 zero-shot 的 53.2% 提升到 one-shot 的 73.6%，超过 π0.5 的 46.0%；RoboDojo 也从 35.67% 提升到 47.17%。同一框架还迁移到 Franka 实机，完成篮中放块和堆块任务。

4. D-RAC：面向检索的企业文档切分

2609.24220

一句话看点： D-RAC 先把异构文档统一渲染成 PDF，再用一次多模态 LLM 转成保留层级和表格语义的 Markdown，使 795 页文档零错误切分并将输出 token 降低 95.7%。

作者与元数据： Uday Allu、Abhivanth Sivaprakash、Pratik Singh、Aman Manocha；2026-09-21；AI Agents。

核心贡献与机制： 方法把 PDF 作为确定性中间表示，用一次多模态转换把复杂版式、表格和标题层级变成检索友好的 Markdown；随后只在可寻址 ID 上规划 chunk，不重新生成源文本，因此切分阶段保持可观测、确定且低成本。

结果与批判： 在 236 份、795 页、五个企业领域的 RAG-Multi-Corpus 子集上，72 分钟完成 1,748 个 chunk 且零错误；相比 frontier LLM agentic chunking，输出 token 降 95.7%，成本降 77.8%–85.6%，时间降 75%。但单次多模态转换仍是质量瓶颈，表格改写可能损失原始结构；摘要也未报告跨 OCR 质量、版式极端样本和检索端到端收益。

摘要翻译： 企业知识库的 RAG 系统必须摄取 PDF、Word、演示文稿和扫描件等异构文档，其中内容常被复杂版式、多栏页面和密集表格锁住。规则抽取和 OCR 会破坏阅读顺序、展平表格并丢失标题层级，而完全 agentic 的文本切分又带来高 token 成本和幻觉风险。我们提出 D-RAC，这是 W-RAC 面向任意文档格式的扩展。D-RAC 先把输入文档统一为 PDF，再用一次多模态 LLM 将渲染页面转换成面向检索的 Markdown：表格被重写为自包含的陈述，标题层级得到保留。随后切分过程与 W-RAC 相同，对可寻址单元做确定性解析，再让轻量 LLM 只基于标识符规划 chunk，而不是读取全文。切分过程中不重新生成源文本，因此保留了 W-RAC 的成本、确定性和可观测性，同时让所有可渲染格式成为一等输入。在覆盖五个企业领域的 RAG-Multi-Corpus 236 份文档、795 页 PDF 子集上，D-RAC 在 72 分钟内零错误完成转换和切分，产生 1,748 个检索就绪 chunk。相较 frontier LLM 的 agentic chunking，它将切分阶段输出 token 减少 95.7%，按 GPT-4.1 价格成本降低 77.8%，按 Gemini 2.5 Pro 价格降低 85.6%，切分时间缩短 75%，并可线性扩展到 500 页以上文档。

5. CodeMidas：从源代码构造编码 RL 环境

2609.22068

一句话看点： CodeMidas 从已实现功能自动生成可执行规格、测试和验证 rollout，构造 5,545 个跨 23 种语言的任务，使 DeepSWE、ProgramBench 和 Terminal-Bench 分别提升 11.7%、17% 和 8.5%。

作者与元数据： Bowen Ye、Lei Li、Shicheng Li、Zihao Yue、Linghao Zhang、Hanglong Lv、Yuanxin Liu、Wenhan Ma、Hao Tian、Rang Li；2026-09-18；LLM Training。

核心贡献与机制： 管线让智能体探索代码库形成行为规格，再依据原代码执行构造测试，并用执行检查和重复解题 rollout 过滤任务；数据覆盖 3,185 个开源代码库和 15 个技术领域，训练 MiMo-V2.5 后轨迹显示更多代码探索与自验证。

结果与批判： 源代码是便宜且可扩展的任务来源，但实现行为不一定等于用户需求，自动 verifier 可能奖励对具体实现的模仿；代码污染、测试覆盖偏斜和 RL 训练成本也会影响泛化。摘要没有给出任务去重、仓库许可和 benchmark 代码泄漏的独立审计。

摘要翻译： 通过强化学习训练有能力的编码智能体需要多样任务和可靠验证器。开源代码库提供丰富任务来源，但现有方法通常依赖 issue 和 commit 等开发产物，限制任务范围。我们提出 CodeMidas，一个只把源代码作为任务特定输入的 agentic 管线，将现有代码库中已实现功能转换为可执行 RL 环境。智能体探索功能形成行为规格，构造以原代码执行为依据的测试，并通过执行检查和重复解题 rollout 验证和筛选候选任务。数据集含 3,185 个开源代码库的 5,545 个训练任务，覆盖 23 种语言和 15 个技术领域。用这些任务以 GRPO 训练 MiMo-V2.5 后，五个多样化基准均提升，包括 DeepSWE +11.7%、ProgramBench +17% 和 Terminal-Bench v2.1 +8.5%。消融显示增加高质量任务会提高性能；轨迹分析显示 RL 智能体更常探索代码库并进行更多样的自验证。

6. GameHorizon：多时间尺度游戏智能评测套件

2609.25001

一句话看点： GameHorizon 用 5,000 小时、21 款游戏和 100 名专家玩家构建多时间尺度数据与离线/在线评测，揭示游戏智能体在不同任务跨度上的能力层级。

作者与元数据： Yiran Wang、Xingyilang Yin、Junfu Pu、Guangzhi Wang、Kaifeng Li、Mingyu Ouyang、Huiqiang Sun、Lingen Li、Cheng Cheng、Wangbo Yu；2026-09-21；AI Agents。

核心贡献与机制： 套件包括自动多时间尺度指令标注器、带视频/动作/指令对齐的 AAA 游戏数据，以及可复现离线题目和逐步在线测试；在线轨道检查离线分数是否真的反映长程游戏能力，并定位具体失败步骤。

结果与批判： 评测 47 个模型、超过一百万次调用，得到明显难度层级和能力差异；数据、标注器和基准计划公开。但摘要没有给出模型分数表和游戏许可细节，离线题目与在线环境之间仍可能存在分布差异，5,000 小时数据的行为覆盖也未必代表非玩家指令。

摘要翻译： 现代电子游戏为 AI 提供了可测量的试验场，结合视觉理解、指令分解、目标规划和精确动作控制，并覆盖多个时间尺度。我们提出 GameHorizon 统一数据与评测套件。它包括可扩展的多时间尺度指令自动标注管线；由 100 名专家玩家在 21 款游戏中录制的 5,000 小时、含时间对齐视频、玩家动作和多时间尺度指令的大规模 AAA 游戏数据；以及支持可复现离线和逐步在线测试的 GameHorizon-Bench。离线轨道用数千个标准化问题评估三类主要任务及诊断变体，在线轨道则检验离线分数是否反映真实游戏能力并定位长程游戏中的具体失败步骤。基于套件，我们对 47 个模型进行了超过一百万次调用评测，发现了有意义的任务难度层级和显著能力差异。作者将发布数据集、标注器和基准。

7. Jev-Mem：由 System One 控制的高效智能体记忆

2609.23986

一句话看点： Jev-Mem 用轻量 System-One 控制面负责记忆类型、检索路由和预算分配，只在复杂任务调用 System Two，在 LoCoMo 上得分 0.777、查询延迟降 36.7%。

作者与元数据： Dongming Jiang、Yi Li、Bingzhe Li；2026-09-21；AI Agents。

核心贡献与机制： 架构把记忆分成 System-One 控制平面、多关系记忆平面和 System-Two 推理平面；控制器动态完成查询路由、检索预算、图遍历、候选评分和自适应停止，把昂贵生成从常规记忆操作的关键路径移开。

结果与批判： LoCoMo 上相对最强基线相对提升 11.0%，记忆构建 158 秒、比最快竞争系统快 6.6 倍，平均查询延迟 0.93 秒、降 36.7%。但 LLM-as-a-Judge 的 0.777 仍缺少人工核验和成本曲线，System-One 控制器本身的训练、错误路由和多关系图维护成本也需要评估。

摘要翻译： 智能体记忆对长程智能体越来越重要，但很多系统用自回归 LLM 控制记忆组织、检索和使用，使昂贵生成位于记忆操作关键路径。我们提出受 System One/System Two 认知启发的智能体记忆架构 Jev-Mem：System One 负责快速轻量决策，System Two 负责慢速审慎推理。Jev-Mem 由 System-One 控制平面、结构化多关系记忆平面和 System-Two 推理平面组成。System-One 控制器在构建时管理记忆类型和关系组织，在检索时动态进行查询路由、预算分配、图遍历、候选评分和自适应停止，仅在复杂推理与答案综合时调用 System Two。在 LoCoMo 上，Jev-Mem 的 LLM-as-a-Judge 总分为 0.777，比最强基线相对提高 11.0%；记忆构建时间为 158 秒，比最快竞争系统快 6.6 倍，平均查询延迟为 0.93 秒，降低 36.7%。

8. Harness-Zero：把智能体 Harness 蒸馏进模型

2609.24974

一句话看点： Harness-Zero 用 agent-as-harness 把专用 harness 的纠错行为转成训练轨迹，移除专用 harness 后仍将基础模型宏平均成功率从 23.3% 提到 44.3%，恢复 82.3% 的行为模式。

作者与元数据： Haoran Ye、Yuxing Lu、Haonan Dong、Zhaochen Su、Guojie Song；2026-09-21；LLM Training。

核心贡献与机制： 优化 harness 引导一个 harnessing agent 在目标 harness 的动作空间内纠正学生响应，再用这些轨迹微调模型，使 harness 诱导出的行为进入权重，部署时可去掉专用 harness。

结果与批判： 去掉专用 harness 后成功率 23.3%→44.3%，甚至高于保留该 harness 时的 41.7%，三领域 28 个行为模式平均恢复 82.3%。不过结果横跨知识工作、工具使用和科学任务，摘要没有报告训练样本量、纠错 agent 成本、不同模型规模及长期回归；“恢复行为”与真实任务可靠性也不是同一指标。

摘要翻译： 智能体 harness 能显著提升性能，但收益通常绑定部署时的 harness。由于最佳 harness 会随领域、实例和模型变化，通用智能体要么使用次优共享 harness，要么维护不断增长的专用 harness。我们研究 harness 蒸馏：把领域或实例优化 harness 作为训练期引导，将其诱导的行为迁移到模型权重，使收益在单一固定目标 harness 下保留。挑战在于两个 harness 的动作空间和可用信息不同，优化 harness 的指导不能直接作为目标 harness 的监督。Harness-Zero 通过 agent-as-harness 实现蒸馏：在优化 harness 引导下，harnessing agent 在目标 harness 动作空间内纠正学生响应，把 harness 指导转成训练示范。微调这些轨迹后，模型内化 harness 行为，部署时即可移除专用 harness。在知识工作、工具使用和科学领域实验中，使用同一演化 harness 时 agent-as-harness 超过 code-as-harness；移除专用 harness 后，基础模型宏平均任务成功率从 23.3% 提升至 44.3%，甚至超过保留该 harness 时的 41.7%；三领域 28 种模式平均恢复率为 82.3%。

9. iSDFT：信息近端自蒸馏的持续学习

2609.24646

一句话看点： iSDFT 把教师视为可控信息预算而非固定终点，并用冻结基座锚定累积漂移，在 8 个模型任务设置中 7 个超过 vanilla SDFT，73% 评测保持在基座 ±0.5 分内。

作者与元数据： Ahmed Khaled Khamis、Xiaotong Ji、Hassan Jaber、Rasul Tutunov、Matthieu Zimmer、Jun Wang、Haitham Bou-Ammar；2026-09-21；LLM Training。

核心贡献与机制： 每个 token 选择距离当前学生最近、同时满足教师信息约束的分布，得到局部指数倾斜目标，再以冻结基座策略控制长期漂移；因此能调节示范信息在何时、以多少强度进入学生。

结果与批判： 四种异构 LLM backbone、两类专门化任务中 8 个设置有 7 个提升；原 SDFT 套件上 73% 评测落在基座模型 ±0.5 分内，而最强基线为 52%。但摘要没有给出各任务绝对收益和信息预算敏感性，持续学习场景较窄，教师约束的标定成本也可能抵消训练收益。

摘要翻译： 在线策略自蒸馏微调可以从示范学习新技能并减少遗忘，但它总是向完整的示范条件教师蒸馏，无法控制每个预测状态传递多少示范信息。我们提出 iSDFT，把教师视为有预算的信息来源：每个 token 选择距离当前学生最近、同时满足预设教师信息约束的分布，得到带局部确定倾斜的闭式指数目标。为控制累积漂移，我们进一步把学生锚定到冻结的基础策略。在四种异构 LLM backbone 和两项专门化任务上，iSDFT 在 8 个模型—任务设置中有 7 个超过 vanilla SDFT，剩余一个持平。在原 SDFT 基准套件上，73% 的评测保持在基座模型 0.5 分以内，而最强基线为 52%；同时在十个额外数学、编码和竞赛数学基准上取得最大平均提升。

10. Calibrated Clipping：稳定全流程 FP8 强化学习

2609.22870

一句话看点： 论文定位 FP8 量化噪声会扭曲重要性比率并错误清零负优势 token 梯度，提出 Calibrated Clipping 后在 8B–32B、GRPO/DAPO 上恢复接近 BF16 的表现。

作者与元数据： Fanchao Chen、Ziheng Jiang、Ziyun Wei、Zheng Zhong、Du Li、Chi Zhang、Haibin Lin、Shivaram Venkataraman；2026-09-19；LLM Training。

核心贡献与机制： 方法让 FP8 clipping 边界匹配高精度 BF16 分布的下侧裁剪分位点，再重新平衡上界，动态校准量化分布；目标是避免负优势 token 被错误推离信赖域后无法受到惩罚，累积成熵暴增和乱码输出。

结果与批判： 覆盖 GRPO、DAPO、8B–32B 模型和多种 FP8 scaling 粒度后，方法消除熵暴增并恢复接近 BF16 基线的表现。摘要没有给出各模型的绝对指标、吞吐/显存收益及校准额外开销，也未说明在不同硬件 FP8 内核和更长训练中是否稳定；“接近 BF16”仍需明确误差范围。

摘要翻译： 强化学习已成为提升大语言模型推理和 agentic 能力的重要方法，FP8 量化可加速 RL 训练，但在完整 FP8 RL 管线中保持稳定仍困难。我们发现，全流程 FP8 RL 会出现严重不稳定，包括训练中期熵异常上升和输出乱码。根因是复合 FP8 量化噪声扭曲重要性比率，使负优势 token 不成比例地被推到信赖域外并错误清零梯度，因此病态输出没有得到恰当惩罚并在训练中累积。我们提出 Calibrated Clipping：让 FP8 裁剪边界与高精度 BF16 分布对齐，匹配下侧裁剪分位点并重新平衡上界。在 GRPO、DAPO、8B 至 32B 模型和多种 FP8 scaling 粒度的实验中，该方法消除熵暴增，使性能恢复到接近 BF16 基线。
