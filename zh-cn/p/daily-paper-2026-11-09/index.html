精评

1. 蒸馏比 RL 便宜多少：外部教师输给 GRPO，自家 GRPO 检查点蒸馏却便宜 50 倍

2611.08453

一句话：在线策略蒸馏（OPD）的性价比取决于教师是谁——用外部后训练教师时它在单位算力精度上输给 GRPO，但蒸馏学生自己的 GRPO 检查点时只需 1/50 的蒸馏算力就能收回同等精度，多教师合并专家时总算力比联合 GRPO 省 42%。

贡献/机制：在任务难度、学生与教师规模、领域与优化选择多个维度上，系统比较反向 KL 的 vanilla OPD 与 GRPO，以 held-out 准确率对训练 FLOPs 作图。关键发现是教师来源决定结论：外部教师下 OPD 即使教师再经 GRPO 训练仍输，且常伴随回答变长；教师换成学生自己的 GRPO 检查点后，OPD 以 50 倍更少的蒸馏 FLOPs 恢复该检查点的数学精度，结论在更大尺寸学生、代码任务与另一模型家族上均成立；跨领域时单个 GRPO 检查点无法兼顾各域能力，多教师 OPD 把各域专家合并进一个学生，蒸馏阶段仅占专家训练 FLOPs 的 5.2%（2 域）与 8.0%（4 域）。作者：Zeyu Leo Liu、Yang Li、Bo Pang、Emre Can Acikgoz、Xuan-Phi Nguyen、Anurag Koul、Srijan Bansal、Erik Nijkamp、Shafiq Joty、Semih Yavuz（10 人）。

数值结果：单域内自家检查点蒸馏用 50 倍更少的 FLOPs 达到 GRPO 同等精度；多教师合并后学生精度与各域专家持平，蒸馏成本仅为专家训练的 5.2%/8.0%；计入专家训练与蒸馏总账，2 域混合上该流程比联合 GRPO 少用 42.0% 的总 FLOPs 达到同等性能。

批判性分析：这篇最有价值的是把“蒸馏 vs RL”从方法之争变成算账问题，而且结论是条件性的，不是站队式的——教师来源一换，胜负就翻转，这对正在排 RL 训练计划的人是直接可用的决策依据。但要注意三点：一是“50 倍”只在蒸馏自家检查点时成立，单域里那个检查点本身就是想要的模型，蒸馏属于多余开销，真正的收益只在跨域合并时兑现；二是外部教师 OPD 的回答膨胀问题没有给出成因分析；三是比较集中在数学与代码，结论能否外推到开放式任务仍待验证。

摘要译文：在线策略蒸馏（OPD）让学生在自己采样轨迹上接受一个冻结教师的逐 token 监督。这种稠密信号能否比强化学习更少训练 FLOPs 就达到目标精度？我们系统比较了 vanilla 反向 KL 的 OPD 与 GRPO，覆盖任务难度、学生与教师规模、领域与优化选择，以 held-out 准确率对训练 FLOPs 作图。使用外部后训练教师时，OPD 在匹配设置下单位训练 FLOPs 的精度总体上输给 GRPO，即便教师再经 GRPO 训练也是如此，而且常常出现回答长度膨胀。但换一个教师，图景就变了：当教师是学生自己的 GRPO 检查点时，OPD 在数学上以比 GRPO 达到同等精度少 50 倍的蒸馏 FLOPs 恢复了该检查点的精度。在同一教师设置下，更大的学生、代码任务与第二个模型家族上我们都一致观察到这种高效率。然而在单个领域，GRPO 检查点本身就是想要的模型，蒸馏它只会增加总算力。跨领域时，不同的 GRPO 检查点持有不同能力，没有单个检查点能服务所有领域。多教师 OPD（DeepSeek-AI，2026）把各域 GRPO 专家合并进一个学生，使其精度与各专家持平，蒸馏阶段在 2 个域上仅占专家训练 FLOPs 的 5.2%、在 4 个域上占 8.0%。把专家训练与蒸馏加总，该流程在 2 域混合上以比联合 GRPO 少 42.0% 的总 FLOPs 达到其性能。

2. 多智能体 RL 不再各自为政：Octopus 用共享 KV 的 DAG 让分支零拷贝分叉，BrowseComp-Plus 涨 17.5 分

2611.06956

一句话：Octopus 把多智能体探索装进一个模型里：所有线程共享同一主干，通过 GPU 常驻的 KV 状态有向无环图协调，分支分叉零拷贝、跨线程只挂载注意力 KV，训练吞吐涨 3.3 倍、峰值 KV 内存降 2.8 倍。

贡献/机制：现有框架让各分支复制前缀 KV 缓存、靠重填文本摘要交换发现、RL 时压平或丢弃跨分支依赖。Octopus 用五个原语（fork、read_thread、wait_threads、rewind、commit）协调同一主干上的多线程，三项协同设计：零拷贝基数分叉（分支只是共享物理 KV 页上的 O(1) 游标视图）、仅注意力 KV 挂载（把兄弟线程的终态 KV 块直接挂进全注意力层、绕过线性循环状态，把跨任务劫持从 57.9% 压到 2.7%，同时在零额外 KV 分配下保留 92.2% 的全文互信息）、打包 DAG-GRPO 训练器（把一条 episode 的所有分支打包进一次块稀疏注意力前向，用留一分支边际奖励做反事实分支信用分配）。作者：Tianming Sha（1 人）。

数值结果：在 Qwen3.5-4B 上用 GRPO 端到端训练、稀疏 BM25 语料，BrowseComp-Plus 准确率 49.6%，比单智能体 GRPO（143K 上下文）高 17.5 分、比文本摘要式多智能体 RL 高 12.5 分；OpenResearcher 上 51.2%，超过大至 250 倍的稠密检索智能体；训练吞吐提升 3.3 倍，峰值 KV 内存降低 2.8 倍。

批判性分析：这是多智能体 RL 里少见的同时动系统与算法的工作——KV 共享解决的是真实存在的成本墙，而不只是换个训练目标；跨任务劫持 57.9%→2.7% 这个数字尤其值得注意，它说明“把兄弟线程文本拼进来”这种常规做法本身就在污染注意力。但要打折扣：评测集中在检索式研究任务（BrowseComp-Plus、OpenResearcher），结论能否推广到工具调用、代码等多智能体场景未验证；250 倍这个对比对象是稠密检索智能体，胜之有取巧之嫌；单作者、单模型规模（4B）的结果也需要独立复现。

摘要译文：多智能体 LLM 系统通过派生带独立上下文窗口的子智能体来并行探索，而单智能体系统把每一步搜索与验证都追加进一条不断增长的轨迹。然而现有框架在各分支间复制前缀 KV 缓存、靠重填文本摘要交换发现、在强化学习（RL）中压平或丢弃跨分支依赖。我们提出 Octopus，一个单模型多智能体 RL 框架：所有线程共享一个主干，通过 GPU 常驻的 KV 状态有向无环图（DAG），以五个原语（fork、read_thread、wait_threads、rewind、commit）协调。Octopus 结合三项协同设计的机制：（1）零拷贝基数分叉，把分支生成为共享物理 KV 页上的 O(1) 游标视图；（2）仅注意力 KV 挂载，把兄弟线程的终态 KV 块直接挂进全注意力层，同时绕过线性循环状态（Gated DeltaNet / Mamba-2），把跨任务劫持降低 21 倍（57.9% → 2.7%），同时在零额外 KV 分配下保留 92.2% 的全文互信息；（3）打包 DAG-GRPO 训练器，把一条 episode 的所有分支打包进一次块稀疏注意力前向，并通过留一分支边际奖励分配反事实分支信用。用 GRPO 在 Qwen3.5-4B 上、稀疏 BM25 语料上端到端训练，Octopus 在 BrowseComp-Plus 上达到 49.6% 准确率（比 143K 上下文下的单智能体 GRPO 高 17.5 分，比文本摘要式多智能体 RL 高 12.5 分），在 OpenResearcher 上达到 51.2%，超过大至 250 倍的稠密检索智能体，同时训练吞吐提升 3.3 倍、峰值 KV 内存降低 2.8 倍。

3. 验证器 RL 在 SFT 之后还剩多少：预注册实验的答案是分布内约等于零，分布外 +0.33 分

2611.07639

一句话：在一项预注册的对照实验里，60 步 GRPO 在 SFT 之后分布内只带来 +0.22 分（置信区间包含零），分布外 +0.33 分——SFT 拿走了绝大部分可得的提升，验证器 RL 的边际价值比通常宣称的小得多。

贡献/机制：RLVR 通常被当作 SFT 的替代或后续阶段来评估，默认 RL 阶段自有其贡献。这篇直接度量这份贡献：自建 gpu-train-debug，一个 1,877 道合成 GPU 与 LLM 训练故障诊断任务、30 类原型、程序化验证器带部分分的确定性基准，校准到中等模型得分落在 0.60–0.75 区间。试点出现意外：1,200 条金标准演示几乎解掉了基准（困难切分上 SFT 0.785），而 base 模型上 15 步 GRPO 毫无 movement（0.314 vs base 0.311）。作者因此在完整实验前书面修正研究问题，改为问“验证器 RL 在演示之外还加了什么”。预注册规模为 60 步 GRPO、学习率 1e-6，另设全程冷启动 GRPO 对照臂。作者：Amit Sagtani、Saloni Garg（2 人）。

数值结果：预注册规模下，分布内 +0.22 分（95% CI [-0.06, +0.51]，无可检测提升）；held-out 分布外切分 +0.33 分（CI [+0.02, +0.68]）；SFT 占了绝大部分可得提升；全程 60 步冷启动 GRPO 与试点结论一致；整项研究只花 8.69 美元算力，可从归档生成、冻结配置与打标签代码完整复现。

批判性分析：这篇的价值首先在方法：预注册、试点后书面修正问题、置信区间、8.69 美元可复现——在 RL 论文里这种克制很少见，结论也因此可信。它直接对准当前 RL 后训练的默认叙事：如果 SFT 已经把演示里的信号吃干，GRPO 的组内学习信号会被 SFT 残留的系统性同质错误进一步压缩。但适用范围要划清：这是合成诊断任务、单一领域、60 步小规模实验，结论不能直接外推到数学、代码等 RL 收益已被反复验证的领域；“SFT 几乎解掉基准”本身也说明该基准对 RL 不友好，换一个 SFT 摸不到天花板的任务，边际价值可能完全不同。

摘要译文：可验证奖励的强化学习（RLVR）通常被评估为监督微调（SFT）的替代，或作为其后的一环，隐含假设 RL 阶段自有其贡献。我们在一个可控设定中直接度量这份贡献：两个阶段都能跑完并精确比较。我们构建了 gpu-train-debug，一个 1,877 道合成 GPU 与 LLM 训练故障诊断任务、覆盖 30 类原型、由程序化验证器以部分分评分的确定性基准，校准到中等模型得分落在 0.60 到 0.75 区间。试点带来一个意外：1,200 条金标准演示几乎解掉了基准（困难切分上 SFT 0.785），而 base 模型上的 15 步 GRPO 毫无 movement（0.314 vs base 0.311）。因此我们在完整实验前书面修正了研究问题，改为更尖锐的问题：验证器 RL 在演示之外还加了什么？在预注册规模（60 步 GRPO，学习率 1e-6）下，答案是：分布内没有可检测的提升（+0.22 分，95% CI [-0.06, +0.51]），分布偏移下有适度但可度量的提升（held-out 分布外切分 +0.33 分，CI [+0.02, +0.68]）。SFT 占了绝大部分可得提升，而验证器 RL 只在分布偏移下带来适度额外收益。SFT 残留的错误大多是系统性的、在样本间相同，这可能压缩了 GRPO 可用的组内学习信号。一项完整 60 步冷启动 GRPO 对照在全程上证实了试点结论。整项研究花费 8.69 美元算力，可从归档生成、冻结配置与打标签代码完整复现。

6. 真实世界任务卡在最后一公里：HEELO 把“会用资源”做成可复用原语，Terminal-Bench 4.0 从 37.3% 提到 55.5%

7. 长程 Agent 的每一步都值得一个奖励：AttnSR 从策略注意力里直接算步级奖励，ALFWorld 91.2%→97.1%

2611.07932

一句话：长程 Agent 的 RL 只有终局奖励、对中间步骤几乎没有监督；AttnSR 不训奖励模型、也不多采样，直接从训练重放时策略自身的注意力反推每步与最终回答的相关性来分配步级奖励，ALFWorld 成功率从 91.2% 提到 97.1%，环境交互还少了 29.9%。

贡献/机制：长程 LLM 智能体做多步决策，但只有结果的奖励对单个步骤几乎没有直接监督。AttnSR 是一种步级奖励增强方法：它在训练重放中从策略注意力中导出奖励分配，无需单独训练的奖励模型或额外采样。具体做法是沿策略模型的注意力图向后追踪，估计早期步骤与最终回答的相关性；终局步骤相对于一个运行基线的度量，决定这些奖励是强化还是惩罚所选步骤。Qwen2.5-7B-Instruct 的对照研究中，AttnSR 在所有被评估的检查点上都稳定超过 PPO 基线；消融表明，收益取决于中间奖励如何分配，而非随时间简单累加步级奖励。代码：https://github.com/fairyshine/AttnSR。作者：Mengsong Wu、Tianchen Zhou、Zhaochen Su、Zhenhua Liu、Zhe Cui、Aimin Zhou（6 人）。

数值结果：ALFWorld 上最终 held-out 成功率从 91.2% 提升到 97.1%；ScienceWorld 上每个检查点均有提升，同时环境交互减少 29.9%。

批判性分析：用策略自己的注意力当步级奖励的先验，是个便宜而聪明的想法——不训奖励模型、不多采样，几乎零额外成本；ALFWorld 91.2%→97.1% 的提升幅度在高基线上尤其难得。但要注意：注意力相关性不等于因果贡献，注意力高也可能只是模型在“看”而不是“依赖”；实验只用了 7B 单模型与两个模拟环境（ALFWorld、ScienceWorld），在真实工具调用与长上下文任务上是否成立未知；“交互减少 29.9%”与成功率提升同时出现，收益里有多少来自奖励分配、有多少来自训练动态变化，需要更细的消融才能分清。

摘要译文：长程 LLM 智能体做出多步决策，但只有结果的奖励对单个步骤几乎没有直接监督。我们提出 AttnSR，一种步级奖励增强方法，它从训练重放中提取的策略注意力中导出奖励分配，无需单独训练的奖励模型或额外采样。AttnSR 沿策略模型的注意力图向后追踪，估计早期步骤与最终回答的相关性。终局步骤相对于一个运行基线的度量，决定这些奖励是强化还是惩罚所选步骤。在一项受控的 Qwen2.5-7B-Instruct 研究中，AttnSR 在所有被评估的检查点上都稳定超过 PPO 基线，把 ALFWorld 上最终 held-out 成功率从 91.2% 提升到 97.1%。消融实验表明，收益取决于中间奖励如何分配，而非随时间简单累加步级奖励。AttnSR 还在每个检查点上提升了 ScienceWorld，同时把环境交互减少了 29.9%。这些结果支持把策略注意力作为长程智能体 RL 中步级奖励分配的一种实用先验。代码见 https://github.com/fairyshine/AttnSR。

2611.07756

一句话：稀疏自编码器的训练瓶颈常在激活存储上；这篇的规模律表明，独特激活数过了某个平台点后，重复回放缓冲区的效果几乎等同于一直用新激活——按“最小够用缓冲 + 重放”训，存储省 8–64 倍、质量几乎无损。

贡献/机制：激活存储常是 SAE 训练的瓶颈。这篇研究在总训练预算固定时，SAE 需要多少独特激活：质量随缓冲增大快速提升，随后进入平台期，超过该点后重放缓冲区几乎与全程使用新鲜激活一样有效；超过平台点，更多独特激活对重建或可解释性几乎没有收益，因此缓冲无需随训练预算增长。作者用“有限数据的规模律”描述多样性与重复之间的权衡，并在字典规模与 token 预算、Llama-3.1 的早中晚层、Qwen3 模型尺寸、BatchTopK/TopK/JumpReLU 三种 SAE 上验证；用数学文本与 Python 代码做激活源切换实验；评估覆盖解释方差（EV）、重建 MSE、特征吸收、自动可解释性与稀疏探针。实用规则是：选达到质量平台点的最小缓冲，剩余预算全部重放。作者：Nikita Koriagin、Nikita Balagansky、Daniil Gavrilov（3 人）。

数值结果：按该规则，激活存储减少 8–64 倍，质量损失可忽略；结论在多字典规模、多 token 预算、多层、多模型尺寸与三种 SAE 变体上成立。

批判性分析：对正在训 SAE 的人这是直接省钱的结论——8–64 倍的存储削减不是小优化，而且“平台点后重放≈新鲜激活”这个发现本身就有方法论价值。但适用边界要看清：验证集中在数学文本与 Python 代码激活源，换到对话、音频等分布差异大的激活源时平台点位置可能不同；评估用的是重建与可解释性代理指标，SAE 下游真正关心的特征质量（如 steering 效果）没有直接度量；“可忽略的质量损失”没有给出统一的量化阈值。

摘要译文：激活存储常是稀疏自编码器（SAE）训练的瓶颈。我们研究在总训练预算固定时，SAE 需要多少独特激活。质量随缓冲增大而快速提升，随后进入平台期，超过该点后重放缓冲区几乎与全程使用新鲜激活一样有效。超过这一点，更多独特激活对重建或可解释性几乎没有收益，因此缓冲无需随训练预算增长。我们用有限数据的规模律描述多样性与重复之间的权衡。我们在字典规模与 token 预算、Llama-3.1 的早中晚层、Qwen3 模型尺寸以及 BatchTopK、TopK 与 JumpReLU 三种 SAE 上验证了它。用数学文本与 Python 代码的实验检验了改变激活源的效果。评估覆盖解释方差（EV）、重建 MSE、特征吸收、自动可解释性与稀疏探针。这些结果给出一条实用训练规则：选择达到质量平台点的最小缓冲，并为剩余预算重放它。在我们的实验中，这把激活存储减少了 8–64 倍，而质量损失可忽略。

9. 蒸馏的风格税：教师与学生的差异里风格位置占 3.5 倍，SD-OPD 用学生自己的增量做参考，数学平均涨 7.76–10.37 分

2611.07722

一句话：OPD 的教师反馈里有个幅度失衡——风格相关位置的教师-学生对数概率差是数学位置的 3.5 倍，更新强度全被风格吸走；SD-OPD 改用学生相对自身 base 的增量作参考，只保留与教师反馈同向的系数，数学六任务平均比 OPD 高 7.76–10.37 分。

贡献/机制：OPD 通过教师在学生生成回答上的稠密反馈改进语言模型的推理。作者首先观察到反馈中的幅度失衡：在数学推理回答上，风格相关位置的平均教师-学生对数概率绝对差是数学位置的 3.5 倍；按这些差异缩放 OPD 更新，会把大部分更新强度导向匹配教师的表达方式。作者改用学生自己的预训练 base 作参考：学生与 base 的差异记录了后训练中获得的 token 偏好，提供不依赖于学生与教师距离的监督信号。在此基础上提出 Student-Delta OPD（SD-OPD）：以中心化的学生-base 差异作更新系数，仅当系数符号与中心化的教师-学生反馈一致时保留，并在每轮训练中重新计算学生信号。五个教师-学生配置（Qwen3 学生 1.7B 至 8B）上，SD-OPD 在六任务数学平均 pass@1（avg@16）上比 OPD 高 7.76 至 10.37 个百分点。代码：https://github.com/aim-uofa/sd-opd。作者：Bozhen Fang、Linhao Zhong、Xuehao Wang、Huanyi Zheng、Hao Chen、Chunhua Shen（6 人）。

数值结果：风格位置的教师-学生差异幅度是数学位置的 3.5 倍；五个配置上 SD-OPD 比 OPD 的六任务数学平均 pass@1（avg@16）高 7.76–10.37 个百分点。

批判性分析：这个诊断很漂亮——它解释了为什么 OPD 常常“学了个说话腔调”：更新强度被风格位置的幅度差吸走了，而 SD-OPD 用学生-base 增量作参考是个干净的修正，收益幅度也足够大。但要注意：3.5 倍这个数字来自数学推理回答，换到代码、对话等任务上失衡程度可能不同；“只保留同向系数”本质上是把教师信号当作过滤器，教师本身有系统性错误时仍会漏过去；实验全部集中在 Qwen3 家族与数学任务，跨家族、跨领域的稳健性尚未验证。

摘要译文：在线策略蒸馏（OPD）通过教师对学生生成回答的稠密反馈改进语言模型的推理。我们首先观察到这种反馈中的幅度失衡：在数学推理回答上，风格相关位置的平均教师-学生对数概率绝对差是数学位置的 3.5 倍。按这些差异缩放 OPD 更新，会把大部分更新强度导向匹配教师的表达方式。我们改用学生自己的预训练 base 作参考：学生与 base 的差异记录了后训练中获得的 token 偏好，提供不依赖于学生与教师距离的监督信号。基于这一参考，我们提出 Student-Delta 在线策略蒸馏（SD-OPD）：以中心化的学生-base 差异作更新系数，仅当其符号与中心化的教师-学生反馈一致时保留系数，并在每轮训练中重新计算学生信号。在 5 个教师-学生配置（Qwen3 学生，1.7B 至 8B 参数）上，SD-OPD 在六任务数学平均 pass@1（avg@16）上比 OPD 提高 7.76 至 10.37 个百分点。代码见 https://github.com/aim-uofa/sd-opd。

简报

10. 耦合采样补上 OPD 的盲区：CoRD 让学生在教师才会到达的状态上也受监督

2611.07959

在线策略蒸馏只在学生自己的采样轨迹上训练，教师会到达、学生到不了的状态很少被监督。CoRD 保持在线损失不变，只把训练状态分布向教师移动：通过推测解码的最大耦合，从学生与教师的几何插值中采样 rollout——两者一致时保留学生的 token，否则从学生低估的那部分目标中替换一个 token，干预频率已是任何精确采样器能做到的最小，且随学生进步而消退。六个 Qwen3/Qwen3.5 base 学生（0.6B–4B）上，CoRD 在五个公开数学基准上比 OPD 的平均 pass@1 高 0.9–2.0 分、pass@8 高 1.2–3.4 分；冻结的教师可达状态上，4B 学生 16 步就弥合了 OPD 80 步都弥合不了的差距。作者：Guhan Chen、Bohan Li、Jun Rao、Hejin Wang、Songtao Tian、Yexin Xie、Xiaojun Meng、Peng Yuan、Jiansheng Wei、Xuebo Liu、Zixiong Yu（11 人）。

11. 外推的方向与距离要分开算：D²-OPD 用硬 KL 约束管距离、自适应组合定方向，数学推理三档场景全胜

2611.07241

外推式 OPD 把教师相对参考策略的对数概率偏移放大来构造更强的学习目标，但现有方法把外推方向与距离耦合在一起，教师偏移的幅度决定了目标走多远。D²-OPD 把两者解耦：逐前缀硬 KL 约束限定目标离教师的距离，教师后训练偏移与初始学生-教师差距的自适应组合决定外推方向，再用前向 KL 优化学生——即使低概率 token 也有学习信号。在 OPD 本来表现好、base 初始化下表现差、无教师参考三种设定中，D²-OPD 在数学推理基准上三档全取最高分，比最强基线最多高 9.45 分。作者：Bowen Fang、Dingmin Wang、Hengzhi Pei（3 人）。

12. 别整条重采样，只重采错的那一步：StepBack 定位首个错误位置再续写，精度持平、自洽采样 token 省 41.26%

2611.08403

自洽采样（SC）要采多条完整推理轨迹，预算固定且浪费在已经对的部分上。StepBack 先采少量草稿轨迹，用轻量信号定位可能的第一个错误位置，只重采该步及其后缀，再多数投票定答案。七个数学推理与多跳问答基准上平均精度与 SC 持平，token 用量最多省 41.26%，且可与 Adaptive Consistency 等自适应推理方法叠加。作者：Yang Ouyang、Jung-Eun Kim（2 人）。

13. Agent 的 token 有多少是白烧的：41–46% 的推理可以剪掉而不掉性能，浪费的分布取决于任务与 harness 而非模型

2611.07238

Agent 的 token 开销里有多少是真正必要的？这篇给出统一的 token 浪费度量框架：记录并归一化完整 Agent 轨迹，用 LLM-as-a-Judge 标出可删片段，再映射回原始轨迹做 token 级度量，并通过直接干预验证——删掉标记片段、恢复执行、看任务结果与后续动作的变化。在线剪枝实验中，删掉 41–46% 的模型推理，两个不同 Agent 基准上的任务性能基本保持。分析发现浪费有系统级结构：它在任务与 Agent 设置间的差异大于模型间差异；推理与可见执行的浪费模式不同；同一模型同一任务下，不同 harness 会引入不同的低效来源。作者：Huimin Zeng、Yuxuan Lu、Jesse Cai、Eric Hanchen Jiang、Di Wu、Po-Nien Kung、Wenbo Hu、Ziyi Wang、Dakuo Wang、Jiaxin Pei、Kai-Wei Chang（11 人）。

14. KV 缓存的键与值不是一回事：LowRAM 用值可由键预测的性质做到 4 倍近无损压缩，叠加量化与淘汰达 26.9 倍

2611.07025

KV 缓存随上下文线性增长，现有后训练压缩方法多在 token、层、特征维或数值精度上做文章。这篇发现另一条轴：同一注意力头内，值大体上可由对应的键预测。LowRAM 据此做值缓存摊销——每头拟合一个轻量预测器，只把重建最差的 token 的残差存下来，得到 4 倍近无损的值压缩；再配跨层低秩键压缩，三个模型家族上都接近无损；每步只重建选定的 KV 子集，4 倍压缩下峰值解码吞吐最高提升 5 倍；与量化、淘汰叠加后达 26.9 倍压缩、保留 94.5% 的基线性能。作者：Teresa Delgado、Hugo Hazard、Martin Benfeghoul、Jun Wang、Zafeirios Fountas（5 人）。

15. MoE 专家的分工比门控显示的更细：SAE 拆解 Qwen3-30B-A3B，发现 Java 与前端、几何与算术各有专属专家

2611.08089

MoE 每个 token 只路由给少数专家，但单个专家到底负责什么一直没有定论；以往按领域语料统计专家被选中的频率，分类事先定死、粒度粗、记录的是“被选”而非“贡献”。这篇在 MoE 层输出上训 SAE：输出是专家输出的路由加权和、SAE 编码器是仿射的，于是每个隐变量的预激活可以精确分解到各专家头上；汇总后每个专家得到一组主要驱动的隐变量。在 Qwen3-30B-A3B 的第 4、30、46 层上，贡献比门控集中得多，多数隐变量只有一两个主导专家，主导集的重叠集中在少数专家对上；自动解读显示分工在粗领域之下：Java 与前端 Web 代码、几何与算术多项式各有不同专家，而粗领域本身占用的专家数极不均匀。SAE 与代码见 https://github.com/Bytedance-Seed/SAE-Interprets-MoE。作者：Anyuan Zhuo、Shaohua Zhang、Yuan Lin、Pinyan Lu（4 人）。

16. 编码 Agent 的长程能力到底多差：Multi-step SWE 69 个任务、每步都建在自己写的代码上，最强模型只解出 18.5%

2611.07166

现有基准一次只考一个任务，但真实开发是连续的：在自己写的代码上接着扩展、升级、优化。Multi-step SWE 是 69 个长程软件工程任务的基准，每个任务是一条 5–15 步的依赖链，每步都是数小时量级的完整工程请求、从上一步 Agent 自己产出的代码开始，早期设计决策与错误会一路传递。任务覆盖四类工程工作、九种语言，含从零搭建与现有开源代码库，每步都有现成事实来源定义指令与验证器。九个前沿模型中，最强的单步解决率只有 18.5%，69 个任务里 38 个没有任何模型解出。基准见 https://multistepswe.com。作者：Xiangkai Zeng、Zheng Liu、Zihao Lin（3 人）。

17. 跨模型迁移的诚实拷问：PLatour 的增益不用发送方信息也能复现，桥接层可能只是在做参数高效适配

2611.06976

大模型提示表示 + 小模型高效生成的 PACT（Prefill-to-Autoregressive 跨模型迁移）被寄望于兼顾能力与推理成本，但现有系统缺乏对大小模型协作的独立评估，任务分数提升本身也不能证明接收方真的用上了发送方的信息。这篇开源 PLatour 框架：冻结模型间用轻量零初始化线性桥接、以任务奖励直接训练、支持混合注意力架构；它在生成任务上显著超过开源基线，在共享数学与代码基准上超过 Mostik 的报告结果、用的发送方还小得多。但对照实验显示，部分任务的增益用无信息发送方信号、自通信或只训接收方也能复现——可训练桥接可能只是在做参数高效适配，而非利用发送方信息。作者据此提出 PACT-Check，量化训练好的 PACT 系统里有多少增益真正来自通信。代码见 https://github.com/zhenyi4/platour。作者：Zhenyi Shen、Junru Lu、Wei Liu、Jiangnan Ye、Jiazheng Li、Di Yin、Xing Sun、Tameem Adel、Yali Du、Lin Gui、Yulan He（11 人）。
