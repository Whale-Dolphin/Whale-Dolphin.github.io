精评

1. 写代码比生成视频更会看：Solve Vision with Code 让编码智能体在视觉推理上甩开视频模型 0.22 分

2611.34813

一句话：同样一帧图加一段提示，写代码渲染答案的智能体在 500 题视觉推理基准上拿到 0.923，比最强的视频生成模型高出 0.22 以上。

贡献/机制：指出视频生成模型正越来越多地被当作视觉推理器来评估：给首帧和自然语言提示，看它能否生成完成指定任务的视频；这种"原生视觉推理"被认为有优势，因为推理直接在画面中展开而非经由语言或代码；但这条原生路线是否真比符号化路线更可靠，此前从未在相同条件下做过对照；作者把同一批任务、相同输入、相同输出规范和同一评分器同时交给两种媒介：视频模型去噪像素，编码智能体则写一段程序渲染出答案视频，由未经修改的基于规则的评估器打分；在 VBVR-Pro-Bench（500 个实例、5 类认知任务、有符号化标准答案）上，智能体拿到的首帧和提示与视频模型完全相同，且接触不到标准答案、元数据或生成模型，每题只有一次机会；还区分了两类智能体程序：描绘型程序（在图像中导航、恢复可迁移的图式）与命题型程序（操作硬编码的数值），揭示智能体程序中的视觉推理是如何展开的。作者：Dezhi Luo、Fengyuan Yu、Haotian Zhang、Zehong Zhao、Ran Ji、Siyuan An 等。

数值结果：三个闭源模型智能体 Codex（配 gpt-6-astra）、Claude Code（配 Fable 5.1）、Gemini CLI（配 Gemini 3.1 Pro）分别拿到 0.923、0.894、0.893，均比最强视频模型高出 0.22 以上；23 个可运行的开源权重模型中最好的是 GLM-5，0.572，高于除经 RL 训练的那一个之外的全部视频模型。

批判性分析：这篇的对照设计很干净：同一任务、同一输入、同一评分器，结论才站得住——“代码比像素可靠"不是修辞，是 0.22 分的硬差距；而且它直接挑战了"视频生成即视觉推理"这个正在成形的评估范式，对做视频世界模型的人是个提醒。但要留神：结论限定在"解能从首帧加提示算出来"的任务上，开放式、需要想象新内容的视觉推理不在此列；一次机会的设定对视频模型也可能更不利（视频模型通常靠多次采样挑优）；描绘型与命题型的区分有意思，但摘要没给两类程序的占比与分数对比。值得读全文看失败案例里视频模型到底输在哪。

摘要译文：视频生成模型正越来越多地被作为视觉推理器来评估：给定首帧和自然语言提示，模型能否生成一段完成指定任务的视频？这一范式被认为具有优势，因为推理在视觉媒介中原生展开，直接在画面中进行，而非通过语言或代码。至于这条原生路线是否确实是通往视觉推理的更可靠路径，此前尚未在相同条件下与符号化替代方案做过检验。因此，我们把同一批任务、以相同的输入、输出规范和评估器，同时交给两种媒介：编码智能体不去噪像素，而是编写一段渲染出答案视频的程序，由未经修改的基于规则的评估器打分。在 VBVR-Pro-Bench（Xu 等，2026）——一个包含 500 个实例、覆盖五类认知任务、带有符号化标准答案的基准——上，智能体拿到与视频模型相同的首帧和提示，接触不到标准答案、元数据或生成模型，且每个实例只有一次机会。三个闭源模型智能体（Codex 配 gpt-6-astra、Claude Code 配 Fable 5.1、Gemini CLI 配 Gemini 3.1 Pro）分别得到 0.923、0.894 和 0.893，均比最强的视频模型高出 0.22 以上。在 23 个可运行的开源权重模型中，最好的 GLM-5 达到 0.572，高于除经强化学习训练的那一个之外的全部视频模型。总之，对于解能从首帧和提示计算出来的任务，程序合成目前是比视频生成可靠得多的视觉推理路线。我们进一步区分了描绘型程序（在图像中导航以恢复可迁移的图式）与命题型程序（操作硬编码的数值），揭示了视觉推理如何在智能体编写的程序中展开，以及这对一般意义上的推理本质意味着什么。

2. 线性注意力先修自己的不稳定：Stable Gated DeltaNet-2 把 128K 长上下文 RULER 拉高 6.80 分

2611.34051

一句话：Gated DeltaNet-2 长上下文训练会崩，是因为擦除操作的方向不对称让状态指数膨胀；对称擦除加衰减调节的残差写入把它修稳，128K 的 RULER 平均分涨 6.80。

贡献/机制：指出线性注意力以线性复杂度和固定大小的循环状态为长序列建模提供高效方案；Gated DeltaNet-2（GDN-2）引入对擦除与写入的独立通道级控制，增强了状态更新的表达能力与上下文检索能力，却在长上下文训练中出现训练失败；作者把失败追溯到擦除时读取方向与修改方向的不对称：它产生非正规（non-normal）的擦除算子，其方向增益随 token 累积，即使没有新写入也会触发状态的指数增长；为解决这一问题，提出对称擦除以保证非扩张的状态传播，并用衰减调节的残差写入保留写入灵活性；理论上建立了循环状态增长的 O(√T) 上界，同时保留分块并行计算。作者：Xichong Zhang、Xixuan Hao、Zhichen Liu、Le Zhou、Zeyu Zhang、Boyu Chen 等。

数值结果：约 1.6B 参数模型上实现稳定训练并改善长上下文检索；相比 GDN-2，循环设定下 128K 平均 RULER 分数提升 6.80 分，混合设定下九个下游任务的平均准确率提升 0.62 分。

批判性分析：这篇的诊断比方法更值钱：把"训练崩了"归因到擦除算子的非正规性，给出了可验证的机制而非调参经验；O(√T) 的状态增长上界加分块并行保留，理论与工程都照顾到了。但要留神：实验只在约 1.6B 规模上做，放大到 7B 以上是否还稳、摘要没说；RULER 涨 6.80 分很亮眼，但九个下游任务平均只涨 0.62 分，说明收益集中在长上下文检索而非通用能力；方法名在摘要里以未渲染的宏占位，细节要看全文。对做线性注意力与长上下文的人，这篇值得精读。

摘要译文：线性注意力以线性复杂度和固定大小的循环状态，为长序列建模提供了高效方案。Gated DeltaNet-2（GDN-2）引入了对擦除与写入的独立通道级控制，增强了状态更新的表达能力与上下文检索能力，但它在长上下文训练中会出现训练失败。我们把这些失败追溯到擦除过程中读取方向与修改方向的不对称：它产生了非正规的擦除算子，其方向增益随 token 累积，即使没有新写入也会触发状态的指数增长。为解决这一问题，我们提出对称擦除以保证非扩张的状态传播，并用衰减调节的残差写入保留写入灵活性。理论上，我们在保留分块并行计算的同时，建立了循环状态增长的 O(√T) 上界。在约 1.6B 参数模型上的实验表明，该方法实现了稳定训练，同时改善了长上下文检索。相比 GDN-2，它在循环设定下把 128K 平均 RULER 分数提升了 6.80 分，在混合设定下把九个下游任务的平均准确率提升了 0.62 分。

3. 电脑智能体要跨六个平台干长活：OS-Omni 上 Claude Opus 5.5 成功率 68.5%，离人类还差 8.8 个点

2611.34232

一句话：OS-Omni 把电脑智能体的考场从单个系统扩到 Windows、Ubuntu、macOS、iOS、Android 与 Web 六平台、最长 67.54 步的真实工作流，最强的 Claude Opus 5.5 也只有 68.5%。

贡献/机制：指出电脑智能体正越来越多地被要求完成真实的用户目标而非孤立的 GUI 动作；但现有基准通常把 Web、手机或桌面环境隔离开，单个通用智能体能否执行跨多个操作系统与持久应用状态的长程工作流，仍不清楚；作者推出 OS-Omni，一个跨平台实时基准与执行环境，覆盖 Windows、Ubuntu、macOS、iOS、Android 与 Web；以每波 300 个任务分版本发布，本篇聚焦首个版本 v1，含每平台 48 个任务与 12 个跨平台工作流（桌面配 Android 手机）；提供可复现的初始化、平台适配器、轨迹记录与可执行的终态评估器，并为涉及账户、购物车、预算、日历、消息等持久状态的工作流提供受控的服务后端应用。作者：Hui Shen、Yunta Hsieh、Jianing Ma、Zhuoran Yin、Zhuhan Bao、Ziyuan Liu 等。

数值结果：人类研究表明 OS-Omni 任务平均需要 67.54 步交互，远超 OSWorld 的 15.0 步；v1 上最强的被测智能体 Claude Opus 5.5 平均成功率 68.5%，落后人类参考值 77.3% 共 8.8 个点；差距在各平台上并不均匀：前沿模型在 Linux 上超过人类，但在 iOS 与 macOS 上落后 25 个点以上。

批判性分析：这篇把"电脑智能体"的评估从玩具任务拉回了真实工作流：跨平台、持久状态、终态评估，67.54 步这个数字本身就说明了难度量级；平台间的不均匀差距（Linux 超人类、iOS/macOS 落后 25 点）是很有信息量的诊断，指向各平台自动化接口与生态成熟度的差异。但要留神：12 个跨平台工作流的样本还小，结论主要来自单平台任务；68.5% 这个平均数掩盖了平台方差；受控服务后端虽然保证可复现，也离真实应用的脏状态有距离。做 computer-use 方向的人应该把它当作新的主基准来跟踪。

摘要译文：电脑智能体正越来越多地被期望完成真实的用户目标，而非孤立的 GUI 动作。然而，现有基准通常把 Web、移动端或桌面环境隔离开来，单个通用智能体能否执行跨多个操作系统与持久应用状态的长程工作流，仍不清楚。我们推出 OS-Omni，一个跨平台实时基准与执行环境，用于在 Windows、Ubuntu、macOS、iOS、Android 与 Web 环境中评估电脑智能体。OS-Omni 以每波 300 个任务分版本发布；本文聚焦首个版本 v1，包含每平台 48 个任务与 12 个将桌面与 Android 手机配对的跨平台工作流。OS-Omni 提供可复现的初始化、平台适配器、轨迹记录与可执行的终态评估器，并为涉及账户、购物车、预算、日历、消息等持久状态的工作流提供受控的服务后端应用。人类研究表明，OS-Omni 任务平均需要 67.54 步交互，大幅超过 OSWorld 的 15.0 步。在 v1 上，最强的被测智能体 Claude Opus 5.5 达到 68.5% 的平均成功率，落后 77.3% 的人类参考值 8.8 个点；差距在各平台上并不均匀，前沿模型在 Linux 上超过人类，但在 iOS 与 macOS 上落后 25 个点以上。这些结果表明，当前的智能体离平台稳健的长程电脑使用仍有距离，尤其是在成功需要持续的状态跟踪与持久的终态改变时。

4. 给机器人看一段人类视频就会干活：Entangle 无需微调在六个未见任务上拿到 83.5 分

如今的智能体框架替模型管理上下文：窗口满了就触发一次压缩，把历史总结掉。这篇研究反过来的做法——模型驱动的上下文管理：模型自己通过一个上下文 API 决定何时压缩、压缩什么。作者在 NVIDIA 的开源智能体框架 \nooa 中给了模型这个控制权，并在 8K 到 512K 的上下文预算下，比较两种策略在文档研究与机器学习工程任务上的表现：会用上下文 API 的模型准确率更高，且输入 token 常常更少，尤其在预算紧张时：GPT 6.1 在 32K 预算下于 OfficeQA Pro v2 上得分从 21% 几乎涨到三倍（56%），Kimi 则以最多少 41% 的输入 token 取得增益。但各模型在 API 使用频率、压缩激进程度与开始压缩的时机上差异很大，且提示词变化会改变压缩时机。最后作者证明推理引擎能让模型驱动的编辑更便宜：复用编辑后未变后缀的 KV 缓存，每次请求把预填充计算最多减少 15%，且准确率无可测变化。作者：Alessio Devoto、Avinash Vem、Tara Safavi、Sanjay Kariyappa、Yu-Hsuan Tseng、Paul Furgale 等。upvotes 11。

16. 世界模型也要抢答：ShowNow 用推测流把输入到显示的延迟从 620ms 压到 208ms

2611.34693

交互式世界模型必须持续生成视频，同时及时响应用户动作；仅有实时吞吐量还不够：粗粒度的生成块会延迟动作更新，而输入后再生成又会给响应路径增加工作量。ShowNow 是一个细粒度推测流框架，利用播放期间可用的计算，在输入到达前就准备好动作条件下的未来；单 latent 提交支持高频决策，可配置的准备覆盖一到八个动作；作者构建了匹配的多未来数据集，从同一状态训练多种延续方案，共享历史树执行与融合提交让准备过程高效。在单块 H100 上，5B 模型以 8 个预备未来维持 480p、16fps 生成；在 ViZDoom 上，完整的 ShowNow 部署把中位输入到显示延迟从 620ms 降到 208ms（相对原生块 SolarWM-FT 部署）；匹配策略实验把重启空 tick 从 1.56% 降到 0.09%（降 94%），并改善了对动作变化的准时响应。作者：Yiren Song、Guian Fang、Mike Zheng Shou。upvotes 19。项目页：https://github.com/showlab/ShowNow

17. 深度研究智能体的知识覆盖率：DRBench Pro 上最好的智能体也只有 57.04%

2611.34852

深度研究智能体从多个来源收集信息，合成为针对复杂开放问题的报告；现有基准沿多个维度评估报告质量，但缺少专门的知识中心评估：报告覆盖了哪些研究方向、挖得有多深。DRBench Pro 把结构化知识覆盖作为首要评估目标：自动化流程从维基百科构建本地知识树，用采样子图生成研究问题与证据支撑的量规，每个量规对应树中的一个关系，保留被评估知识的结构；智能体只拿到研究问题；据此可度量主要研究方向上的广度与相关知识链上的深度，二者的几何平均即总体覆盖率。基准含 144 个案例、24 个领域、44,102 条量规；评估 16 个深度研究智能体发现广度与深度上各有所长，表现最好的智能体总体覆盖率也只有 57.04%；量规判断与人类标注高度一致，智能体排名在测试的指标配置下保持稳定。作者：Han Huang、Yuchen Yan、Xingyu Wu、Yijun Li、Chao Deng、Jie Liu 等。upvotes 17。
