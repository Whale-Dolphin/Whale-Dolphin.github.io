1. PawCT：合唱转录第一次把 SATB 四个声部分开转，还分对是谁在唱

2610.09861

一句话：首个端到端的声部感知合唱转录框架：不光转出音符，还判断女高、女低、男高、男低四个声部各自是否在唱、并把每个音符分到对应声部，靠的是基于 SATB 音域的范围先验与有序连续性约束，在 YouChorale 上声部感知音符 F1 相对适配基线提升 36.4%。

贡献/机制：PawCT 把声部专属的起音、止音与帧级预测、声部存在估计、并集级监督拼在一起，训练目标里加入两类结构先验：范围先验（RP）利用四个声部各自的音高范围，有序连续性（OC）再加上声部内的旋律连续性与声部之间的音高排序。作者：Hanyu Meng、Zhanhong He、Zixun Guo、Yaolong Ju。代码与演示：https://hanyu-meng.github.io/Paw_Choral_AMT_Demo/ 。

数值结果：在 YouChorale 上，PawCT-RP-OC 在 50 毫秒起音容差下宏平均声部感知音符 F1 为 0.225，高于适配后的合唱基线 0.165（相对提升 36.4%）与两阶段事后分配流水线 0.175；其声部无关变体 PagCT 的 50 毫秒起音 F1 为 0.382，上一代合唱转录 SOTA 为 0.237。另在 CSD 与 Cantoria 上做了跨数据集评测以检验分布偏移。

批判性分析：这是今天唯一一篇纯音频论文，问题选得准：合唱转录的难点从来不是"有没有音"，而是同音高区间里多个声部叠在一起时音符归谁—— merged 单轨输出对排练和乐谱重建几乎没法用，分声部才是可用形态。但也要看清绝对数：声部感知 F1 只有 0.225，离"转出来就能用"还很远，相对提升大更多说明这个子任务此前有多空白。RP/OC 用的是音域与排序这类乐理硬先验，在标准四部合唱上成立，遇到声部交叉频繁、现代合唱写作或非 SATB 编制时先验本身会变成约束。跨数据集只说"做了评测"，摘要未给 CSD/Cantoria 的具体分数，泛化幅度要查正文。

摘要译文：单乐器自动音乐转录（AMT）已取得很大进展，但合唱应用要求把女高音、女低音、男高音和男低音（SATB）转录为各自独立的声部。近期的音符级合唱 AMT 只产出一条合并的音符轨，限制了它在排练、教育和乐谱重建中的用途。为解决这一局限，我们提出声部感知合唱转录（PawCT），据我们所知这是首个端到端神经框架，能从合唱音频中识别出活跃的 SATB 声部，并把每个声部转录为独立的音符级音轨。PawCT 结合了声部专属的起音、止音和帧级预测与声部存在估计、并集级监督，以及使用基于 SATB 音高范围的范围先验（RP）及其有序连续性（OC）扩展的结构化训练目标，后者加入了声部内的旋律连续性和声部之间的音高排序。在 YouChorale 上，PawCT-RP-OC 在 50 毫秒起音容差下取得 0.225 的宏平均声部感知音符 F1，相对适配后的合唱基线 0.165 提升 36.4%，也优于两阶段事后分配流水线 0.175。其声部无关变体 PagCT 取得 0.382 的 50 毫秒起音 F1，而此前的合唱 AMT 最优模型为 0.237。在 CSD 和 Cantoria 上的跨数据集评测进一步评估了数据集偏移下的表现。这些结果表明，联合建模音符转录与人声声部分配是有益的。代码和演示见 https://hanyu-meng.github.io/Paw_Choral_AMT_Demo/ 。

2. StreamEval：流式视频生成画质再好也没用，请求执行最高分只有 36.90

2610.28402

一句话：面向交互式流式视频生成的统一基准：300 个 15–300 秒的脚本化用例、五类任务、四维评测（含音视频协调），测了 37 个模型后发现画质与身份保持和"按时按要求执行请求、维持状态一致"基本是两回事，请求执行是全场最难的一项。

贡献/机制：每个用例都明确给出初始资产、增量到达的多模态请求，以及状态变化与内容保持的显式要求；评测沿任务执行、状态一致性、视觉保真、音视频协调四个维度展开，落成十个 0–100 分的任务专属指标。五类任务为数字人对话、数字人表演、世界生成、指令编辑与参考编辑。作者：StreamEval Team。排行榜：https://streameval.ai 。

数值结果：请求执行普遍很差：数字人表演的 Following 指标在 7 个模型中最高仅 36.90，文本条件世界生成的 Following 最高 25.93，参考编辑的 Edit Success 在所报 3 个模型中最高仅 15.00。摘要未给出各模型在状态一致性与音视频协调维度上的具体分数分布。

批判性分析：这篇的价值在把流式交互的失败模式从"生成质量"里剥出来：一次性生成里画质即一切，流式场景里请求是中途到达的，模型要在对的时间改对的东西、其余全部不许动——这本质是 Agent 式的指令跟随与状态管理问题，不是扩散模型画得好不好。对音频方向的读者，音视频协调被单列为一个评测维度值得注意，数字人对话与表演恰是语音驱动最直接的落地形态。局限：用例是脚本化的，真实用户的请求时机与措辞分布更脏；十个指标里多项依赖自动评测器，Following 这类分数与人类判断的对应关系需看正文校验；37 个模型的完整榜单不在摘要里，引用结论时只引这三个最高分锚点是安全的。

摘要译文：随着流式视频生成不断进步，让生成视频能实时交互变得日益重要。我们提出 StreamEval，一个面向交互式流式视频生成的统一基准，涵盖五项任务：数字人对话、数字人表演、世界生成、指令编辑和参考编辑。StreamEval 包含 300 个时长 15–300 秒的脚本化测试用例，每个用例都指定了初始资产、增量到达的多模态请求，以及状态变化与内容保持的明确要求。表现沿四个评测维度评估：任务执行、状态一致性、视觉保真和音视频协调，并具体化为十个 0–100 分的任务专属指标。在 300 个用例上评测 37 个不同模型后，我们发现高视觉质量和身份保持并不必然与可靠的请求执行或持续的状态一致性同时出现。尤其是请求执行仍然困难：数字人表演的 7 个模型中 Following 最高分仅 36.90，文本条件世界生成的 Following 为 25.93，参考编辑所报 3 个模型的 Edit Success 为 15.00。这些发现表明，在时间与保持约束下可靠地执行请求，是推进全模态实时交互系统的核心挑战。排行榜见 https://streameval.ai 。

3. Cache Engineering for Agents：别改写历史了，让 Agent 直接动手删自己的 KV 缓存

2610.28577

一句话：长轨迹 Agent 的成本大头是 KV 缓存，但靠裁剪或摘要历史来省缓存会让前缀失效、招来昂贵的重预填充——这篇让 Agent 直接对活跃缓存做 drop（排除选定缓存参与后续注意力）与 repos（调整保留键的位置编码），不改轨迹、不重预填充，平均分数还涨 1.7 分、成本降 27.7%。

贡献/机制：形式化了缓存操作后，一个新的服务难题浮出来：相同 token 序列在不同缓存操作序列下会得到不同的缓存状态，前缀匹配不再足以保证缓存复用正确。于是作者共设计了 AKV 服务引擎：对外是与现有服务 API 兼容的无状态接口，对内管理有状态的缓存复用、淘汰与恢复。作者：Tianyu Fu、Ruoxi Wang、Zihan Min、Zhongqi Ren、Zhihao Li、Tengxuan Liu、Shengxu Mu、Hanling Zhang、Yu Wang。代码：https://github.com/thu-nics/AKV 。

数值结果：一种对工具响应做滚动 drop 的缓存策略，相比常规的阈值触发摘要，平均基准分数提高 1.7 分、平均成本降低 27.7%；配合 AKV，输出吞吐最高达 1.2 倍、P95 请求延迟加速 1.5 倍。缓存策略的递归自我改进在专家设计之上再降成本 7.1%。

批判性分析：切入点很实：上下文工程社区默认"省上下文 = 改文本"，但在真实服务栈里改文本等于缓存作废，这篇把问题搬回系统层，用缓存原语代替文本手术，是少数同时谈分数、成本、吞吐和尾延迟的 Agent 论文。drop/repos 的粒度与时机由策略决定，摘要没有交代策略在不同任务族上是否需要重调，滚动 drop 对工具响应有效、对推理链本身是否同样安全未在摘要区分。历史依赖也意味着缓存状态成了新的可复现性变量——同一请求两次跑结果可能因缓存操作历史不同而不同，评测与线上排障都要为此留痕。对做 Agent 服务的人，AKV 的无状态接口设计比策略本身更值得先读。

摘要译文：大语言模型（LLM）Agent 能处理日益复杂的任务，在由观察和动作组成的长轨迹中导航。随着这些轨迹变长，键值（KV）缓存的读写与存储成为主导成本。轨迹还可能超过 LLM 的最大上下文长度，需要控制活跃缓存的增长。已有工作用上下文工程通过裁剪或摘要历史来减小缓存，但修改轨迹前缀会使后续缓存状态失效，并触发对保留上下文的昂贵重预填充；保留太少上下文时任务准确率也会受损。我们提出缓存工程这一新方案：它让 Agent 直接控制自己的活跃 KV 缓存，而不修改轨迹、也不重预填充保留的上下文。具体而言，Agent 可以主动使用 drop 从未来的注意力中排除选定的缓存，并用 repos 调整保留键的位置编码。我们形式化了这些缓存操作，并指出历史依赖是一个服务挑战：相同的 token 序列在不同的缓存操作序列下可以产生不同的缓存状态，使前缀匹配不足以保证正确的缓存复用。因此我们共设计了 AKV 服务引擎：它提供与现有服务 API 兼容的无状态接口，同时在内部管理有状态的缓存复用、淘汰与恢复。实验表明，一种对工具响应做滚动 drop 的缓存策略，相比常规阈值触发的摘要，平均基准分数提高 1.7 分、平均成本降低 27.7%。配合 AKV，它实现最高 1.2 倍的输出吞吐和 1.5 倍的 P95 请求延迟加速。缓存策略的递归自我改进在专家设计之上进一步降低成本 7.1%。代码见 https://github.com/thu-nics/AKV 。

4. Cola2：把语言模型拆成"连续语义压缩 + 离散生成"两层，用 Llama-3 的 1/43 预算追上它两项

2610.31305

一句话：分层语言生成框架 Cola2：动态把文本切成语义跨度并压进连续潜变量，再由块因果掩码扩散解码器把潜变量落成文字，两层通过潜变量共同适应；用 346.03B 源 token 训出的未收敛检查点在八项任务上平均 60.10，并在 HellaSwag 与 StoryCloze 上超过预训练预算大 43 倍以上的 Llama-3-8B。

贡献/机制：三个设计是骨架：动态语义跨度切分加上无辅助损失的负反馈来控制压缩率；重建与生成双监督共同塑造紧凑且有预测性的潜表示，解码器在干净、带噪、丢弃三种潜条件上训练，推理时用无分类器引导调节"忠于语义"与"自主生成"的平衡；协同适应上，token 预测梯度经潜变量回传更新编码器，而流匹配的先验学习用停梯度与表示学习解耦，推理时按固定跨度布局把已生成文本重新编码以保持潜历史与真实上下文一致。作者：Hongcan Guo、Yian Zhao、Feng Wang、Shen Nie、Guoqiang Wei、Yan Zeng、Hengshuang Zhao。

数值结果：在约 210B 训练 token、五项下游任务上验证了核心设计，并显示出有竞争力且未饱和的扩展趋势；346.03B 源 token 的未收敛检查点在八项任务上取得 60.10 的平均分，并在 HellaSwag 与 StoryCloze 上超过 Llama-3-8B，而后者报告的预训练预算是其 43 倍以上。

批判性分析：连续潜空间做语言建模这条线一直卡在"潜变量压掉了什么、解码器到底用不用它"两个问题上，Cola2 的贡献是把这两问做成了可训练的机制（压缩率反馈、三条件解码训练、重编码对齐），而不是只报一个困惑度。对预训练方向的读者，最该盯的是"未收敛 + 43 倍预算差"这个组合：它既说明分层架构的数据效率可能真实更高，也意味着结论对训练继续跑下去后的相对位置非常敏感——自回归基线在更大预算上的扩展曲线更平滑，分层模型后段是否掉队摘要无法回答。八项任务平均 60.10 的构成、生成质量（而非理解任务）上的对照在摘要里缺席，而分层生成最后要过的恰是开放生成这一关。

摘要译文：分层语言生成把连续语义建模与离散文本实现分开，但其效果取决于潜空间压缩了什么、以及离散生成器如何使用它。我们提出 Cola2，一个联合研究连续语义压缩、重建与生成之间的平衡、以及连续-离散协同适应的框架。Cola2 动态地把文本切分为语义跨度，通过无辅助损失的负反馈控制压缩率，并结合重建与生成监督来学习紧凑、有预测性的潜表示。一个块因果掩码扩散解码器在干净、带噪和丢弃的潜条件上训练，同时无分类器引导调节语义重建与自主生成之间的平衡。Token 预测的梯度通过潜变量更新编码器，而流匹配的先验学习通过停梯度与表示学习解耦。推理期间，生成的文本在固定跨度布局下被重新编码，以保持潜历史与实际文本上下文一致。在约 2100 亿训练 token、五项下游任务上的实验验证了核心设计，并显示出有竞争力、未饱和的扩展性。使用 346.03B 源 token 时，一个未收敛的检查点在八项任务上达到 60.10 的平均分，并在 HellaSwag 和 StoryCloze 上超过 Llama-3-8B，尽管后者报告的预训练预算是其 43 倍以上。这些结果展示了连续潜变量分层语言生成的潜力。

5. Deep Fusion Memory：外部知识不检索了，训一个预测器把分块记忆直接融进隐藏状态

2610.25100

一句话：分块级参数记忆架构 DFM：用检索到的分块嵌入作监督，训一个因果记忆预测器从前文直接生成记忆，再经门控交叉注意力融进每个 token 的隐藏状态，骨干冻结、推理时零检索，在六项 QA 上相对最强基线在 Mistral-7B 上高 12.71%、在 Qwen3-8B-Base 上高 11.19%。

贡献/机制：与已有参数记忆相比，DFM 把记忆目标从 token 级改为分块级：预测出的记忆在一个分块内被所有 token 共享，构造训练数据所需的检索查询减少 32 倍、检索条目减少 2048 倍。记忆预测与融合在骨干冻结下端到端训练，推理不需要显式检索，绕开了持续预训练的灾难性遗忘与在线检索的开销。作者：Rubin Wei、Siyuan Sun、Hao Sun、Yuliang Liu、Xiang Shi、Jiarui Wang、Junming Zhang、Zhouhan Lin。

数值结果：六项 QA 任务上，DFM 在 Mistral-7B-v0.3 上比最强基线高 12.71%，在 Qwen3-8B-Base 上高 11.19%；领域适应上，相对 Qwen3-4B-Base 与 Qwen3-8B-Base 分别取得 6.51 与 4.38 分的平均提升。

批判性分析：思路是"把检索蒸馏进参数、把融合做进中间层"，比输出层插值的浅融合更深，比持续预训练更可控，构造数据便宜两个数量级这一点如果成立，参数记忆路线的成本账会被改写。需要打折的都在摘要的留白里：12.71% 是相对提升还是百分点、六项 QA 的具体构成与基线名单未给；记忆预测器是从前文"猜"记忆，语料里没被前文暗示的知识它猜不出来，这套机制对"上下文无关的事实注入"是否有效，领域适应那组 +6.51/+4.38 分更接近证据；骨干冻结意味着记忆容量上限由预测器与交叉注意力承担，规模再大时是否成为瓶颈未提。对做知识注入与领域适应的人，这是比 RAG 更值得先做小规模对照的一条新路线。

摘要译文：大语言模型需要有效的方法来获取和使用预训练中保留下来的知识之外的外部知识。持续预训练有灾难性遗忘的风险，推理时检索则会带来可观的开销。外部参数记忆避免了在线检索，但构造其训练数据需要大量离线搜索，且输出层插值只提供浅层融合。我们提出 Deep Fusion Memory（DFM），一种参数记忆架构，它减少了这种构造工作量，并把学到的记忆纳入中间隐藏状态。一个因果记忆预测器学习从前文生成记忆，使用从语料中检索到的分块嵌入作为监督。预测出的记忆在一个分块内被各 token 共享，并通过门控交叉注意力融入它们的隐藏状态。记忆预测与融合在骨干冻结的情况下端到端训练，推理不需要显式检索。与已有的参数记忆方法（它们通常构造 token 级记忆目标）相比，DFM 构造训练数据所需的检索查询少 32 倍、检索条目少 2048 倍。在六项 QA 任务上，DFM 在 Mistral-7B-v0.3 上比最强基线好 12.71%，在 Qwen3-8B-Base 上好 11.19%。在 QA 之外，领域适应相对 Qwen3-4B-Base 和 Qwen3-8B-Base 分别取得 6.51 和 4.38 分的平均提升。

6. Harness Scaling：Agentic RL 别只训一个 Harness，执行环境的多样性本身是一个扩展维度

2610.29458

一句话：现有 Agentic RL 都在单一固定 Harness 里训练，模型容易对那套工具与上下文管理方式过拟合——这篇把 Harness 空间因子化，用均衡因子覆盖挑一个紧凑训练子集做跨 Harness 训练，在白盒新配置上泛化更好，还能迁移到没见过的外部黑盒 Harness，效果超过在单个复杂黑盒 Harness 里训的模型。

贡献/机制：Harness Scaling 的操作分三步：把 Harness 的构成因子化成一个可组合空间；在其中选一个具备均衡因子覆盖的紧凑子集；组织跨 Harness 训练，使同一任务同时获得全局覆盖与受控变化。验证覆盖多个基准、多个模型规模与多种 RL 算法。作者：Fei Bai、Huatong Song、Chuan Hao、Ran Tao、Jian Yang、Bryan Dai、Wayne Xin Zhao、Ji-Rong Wen。

数值结果：摘要只给定性结论，未给具体数值：在多个基准、模型规模与 RL 算法上，Harness Scaling 持续改善对未见白盒配置的泛化；经结构化白盒变化训练的模型能有效迁移到未见的外部黑盒 Harness，并优于经单个复杂黑盒 Harness 训练的模型。各基准的提升幅度需查正文。

批判性分析：对正在做 Agentic RL 的人，这篇的命题比方法更重要：Harness 不是中性的脚手架，它决定了工具调用格式、上下文压缩与错误恢复的分布，只在一个 Harness 里做 RL，学到的策略里有多少是任务能力、多少是这套 Harness 的脾气，此前很少有人单独量。它把"环境多样性"提成与数据、模型并列的扩展维度，且声称白盒多样训练能迁移到黑盒，这个迁移结论如果数值扎实，意味着团队不必绑死某个闭源 Agent 框架来训模型。保留意见：摘要零数字，“因子空间"的因子清单与子集规模决定了这套方法的可复现性，而 Harness 因子之间的交互（工具格式 × 上下文策略 × 重试机制）是否真能因子化处理，正文的消融才是关键。

摘要译文：Agent Harness 已成为现代 Agentic 系统的核心组件，塑造模型如何使用工具、管理上下文以及协调长程交互。要实现这些 Harness 的收益，取决于底层模型能多有效地利用它们，这促使人们直接通过 Harness 做强化学习。然而，已有方法通常通过单一固定 Harness 训练，这可能导致专门化，并限制在不同 Harness 配置之间的迁移。为解决这一点，我们提出 Harness Scaling，一个 Agentic RL 的新扩展维度，把训练从单一 Harness 扩展到多样的执行配置。具体而言，我们构造一个因子化的 Harness 空间，选取一个具有均衡因子覆盖的紧凑训练子集，并组织跨 Harness 训练，把全局覆盖与同一任务的受控变化结合起来。在多个基准、模型规模和 RL 算法上，Harness Scaling 持续改善对未见白盒配置的泛化。此外，经结构化白盒变化训练的模型能有效迁移到未见的外部黑盒 Harness，优于经单个复杂黑盒 Harness 训练的模型。这些结果确立了 Harness 多样性作为 Agentic RL 一个有意义的扩展维度，并强调了组织这种多样性的方式对跨 Harness 泛化的重要性。

简报

1. Raw-RAG：复杂 Agent 记忆打不过"原文检索 + 重排"的朴素基线

2610.30755

在 LoCoMo、LongMemEval、MEME、MemoryAgentBench 上，用稠密检索加重复排序直接从原始历史里取证据的 Raw-RAG，在 7 个基准-模型设置中的 6 个排名第一，领先最强的 Agentic 记忆系统 0.13–5.53 分。作者的解释是原始证据的覆盖率优势抵消了利用率劣势，且转换后的记忆库哪怕完整可达也与原始证据存在准确率差距。结论不是"别做记忆系统”，而是任何新记忆方法先过 Raw-RAG 这关再谈复杂度。

2. LASAGNA：RAG 组件单独测的好成绩，拼起来只剩三分之一

2610.29722

在 8 个基准、5K–200K 文档语料上系统测了 450 种 RAG 配置：三个检索技术单独预测的组合收益是 +47%，实际组合只交付 +17%；检索质量与答案忠实度偏好的组件选择还不一样，优化一个会伤另一个；小语料上的最优组合到大语料上也不再最优。以后看单组件 RAG 论文的提升数字，先默认打个组合折扣。

3. DeLoop：Agent 反复做已经做过的事，用它自己的轨迹做偏好对就能治

2610.19376

长程 Agent 会重复发出已发过、且返回完全相同观察的工具调用，历史被压缩后更严重。DeLoop 把循环动作作负例、同轨迹里其后第一个非循环动作作正例，用 DPO 自监督训练，不需要任务奖励、金标答案或 LLM 评委。在 CodeGym 压缩设定下，Qwen3-8B 含循环任务占比从 57.3% 降到 6.1%、步数约为原来的三分之一且成功率相近；Qwen3-32B 上成功率从 37.7% 升到 44.8%。

4. CAP：后训练在悄悄把方言回复"标准化"，DPO 偏好的还是英澳拼写

2610.28474

追踪 10 个开放模型谱系从 SFT 到 DPO 再到 RL 的各阶段后发现：后训练普遍把回复拉向标准英语，但校正基线概率后，DPO 更新仍在 10 个谱系上系统性偏好匹配英式与澳式拼写、而非 AAE 与新加坡英语。作者提出的校准顺应配对（CAP）用奖励"匹配用户方言密度、同时为标准英语用户保留标准英语"的偏好数据训练，在未训过的方言特征上也提高了顺应度，且未检出对标准英语用户的方言增加或指令跟随损失。

5. Looped UDLM：给均匀扩散语言模型加循环层，训练 FLOPs 省到 1/3

2610.30066

均匀扩散语言模型（UDLM）训练时要在不可靠的上下文上做去噪，比掩码扩散更费算力但推理表现更强。这篇在每个去噪步内递归复用少数早期 Transformer 层后发现：循环版 UDLM 达到非循环版用约 0.5 万亿 token 训出的验证 NLL，所需训练 FLOPs 在 OpenWebText 上少至 2.8 倍、在 FineWeb-Edu 上少至 3.3 倍；同等 NFE 预算下生成困惑度最高低 9.8%，且训练时更频繁地采样较小循环次数还能再省 12% 的推理循环而不掉准确率。
